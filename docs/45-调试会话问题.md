## 概述

本文档专注于 OpenCode 会话级别的问题诊断和解决。涵盖会话卡住、消息丢失、权限错误、工具调用失败和会话恢复等常见问题。

**会话系统架构：**

```
┌─────────────────────────────────────────────────┐
│              Session Manager                 │
├─────────────────────────────────────────────────┤
│ • Session.create()                         │
│ • Session.fork()                          │
│ • Session.update()                         │
│ • Session.remove()                         │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│           Session Processing                 │
├─────────────────────────────────────────────────┤
│ • SessionPrompt.prompt()                   │
│ • SessionProcessor.process()                │
│ • Tool execution                         │
│ • LLM streaming                         │
└─────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────┐
│              Storage Layer                  │
├─────────────────────────────────────────────────┤
│ • Session metadata                      │
│ • Messages                              │
│ • Parts                                 │
│ • Diffs                                 │
└─────────────────────────────────────────────────┘
```

## 会话卡住

### 症状

```
1. 会话状态一直显示 "Processing..."
2. 消息没有响应
3. 工具调用挂起
4. TUI/Web UI 无响应
```

### 诊断步骤

#### 1. 检查会话状态

```bash
# 查看当前会话状态
opencode session show <session-id>

# 查看所有会话状态
opencode session list --status
```

**输出示例：**

```
Session ID: abc123
Status: busy
Last Activity: 2026-01-22 10:30:00
Current Operation: Processing message
```

#### 2. 检查日志

```bash
# 实时查看会话日志
tail -f ~/.local/share/opencode/logs/dev.log | grep "session=abc123"

# 查看错误
grep ERROR ~/.local/share/opencode/logs/dev.log | grep "session=abc123"
```

**关注的关键日志：**

- `Session.BusyError` - 会话忙
- `Session.Event.Error` - 会话错误
- `tool.*timeout` - 工具超时
- `retry.*attempt` - 重试信息

#### 3. 检查 LLM 响应

```bash
# 查看是否有 LLM 响应
grep "assistant" ~/.local/share/opencode/logs/dev.log | grep "session=abc123"

# 检查流式响应
grep "stream.*chunk" ~/.local/share/opencode/logs/dev.log | grep "session=abc123"
```

### 常见原因和解决方案

#### 原因 1: 网络超时

**症状：**

```
Error: ECONNRESET
Connection reset by peer
```

**解决方案：**

```bash
# 1. 增加超时时间
opencode config set agent.timeout 120000  # 2 分钟

# 2. 配置重试策略
opencode config set agent.retry.max_attempts 3
opencode config set agent.retry.delay 2000  # 2 秒

# 3. 测试网络连接
ping api.anthropic.com -c 5
```

#### 原因 2: 工具执行挂起

**症状：**

```
[DEBUG] bash-command status=started duration=0s
# 无后续输出
```

**解决方案：**

```bash
# 1. 增加工具超时
opencode config set tool.timeout 300000  # 5 分钟

# 2. 查看工具执行状态
tail -f ~/.local/share/opencode/logs/dev.log | grep "tool.*execution"

# 3. 手动测试命令
# 在终端中运行相同的命令
npm install
```

#### 原因 3: 上下文窗口溢出

**症状：**

```
Error: Context window exceeded
```

**解决方案：**

```bash
# 1. 启用自动压缩
opencode config set session.compaction.enabled true
opencode config set session.compaction.threshold 100000  # tokens

# 2. 减少最大输入 tokens
opencode config set agent.max_input_tokens 50000

# 3. 减少最大输出 tokens
opencode config set agent.max_tokens 4096

# 4. 手动压缩会话
opencode session compact abc123
```

#### 原因 4: Doom Loop（无限循环）

**症状：**

```
AI 重复调用相同的工具：
Tool: read /path/to/file
Tool: read /path/to/file
Tool: read /path/to/file
```

**解决方案：**

```bash
# 1. 启用 doom loop 检测（默认已启用）
opencode config set agent.doom_loop_detection true

# 2. 配置在检测时询问
opencode config set agent.doom_loop_on_deny ask

# 3. Fork 会话避免循环
opencode session fork abc123
```

### 终极解决方案

如果会话完全卡住无法恢复：

```bash
# 1. Fork 会话到新状态
opencode session fork abc123 --point last-success

# 2. 如果无法 fork，创建新会话
opencode session create --title "Recovery session"

# 3. 删除卡住的会话（谨慎操作）
opencode session remove abc123
```

## 消息丢失

### 症状

```
1. 消息没有显示在历史中
2. 部分消息内容丢失
3. 消息顺序错乱
4. 消息没有持久化
```

### 诊断步骤

#### 1. 检查消息存储

```bash
# 列出会话的所有消息
opencode session messages abc123

# 检查消息完整性
opencode session messages abc123 --verify
```

#### 2. 检查存储完整性

```bash
# 检查会话数据文件
ls -la ~/.local/share/opencode/session/<project-id>/abc123/

# 检查消息部分
ls -la ~/.local/share/opencode/message/abc123/
```

#### 3. 查看错误日志

```bash
# 查看消息相关错误
grep "message" ~/.local/share/opencode/logs/dev.log | grep ERROR

# 查看存储错误
grep "storage" ~/.local/share/opencode/logs/dev.log | grep ERROR
```

### 常见原因和解决方案

#### 原因 1: 存储写入失败

**症状：**

```
Error: Failed to write message to storage
EIO: Input/output error
```

**解决方案：**

```bash
# 1. 检查磁盘空间
df -h

# 2. 检查磁盘 I/O 错误
dmesg | grep -i error

# 3. 检查文件权限
ls -la ~/.local/share/opencode/

# 4. 重启 OpenCode
opencode
```

#### 原因 2: 消息序列化失败

**症状：**

```
Error: Failed to serialize message
Invalid message format
```

**解决方案：**

```bash
# 1. 检查消息大小
opencode session messages abc123 --size

# 2. 如果消息太大，拆分消息
# 在提示词中要求分步回答

# 3. 查看消息格式
opencode session show abc123 --format json
```

#### 原因 3: 事件流中断

**症状：**

```
SSE connection lost
WebSocket disconnected
```

**解决方案：**

```bash
# 1. 检查网络连接
ping -c 10 localhost

# 2. 检查服务器状态
opencode status

# 3. 重新连接会话
opencode session attach abc123

# 4. 如果使用 Web，刷新页面
```

### 恢复丢失的消息

如果消息已丢失，尝试恢复：

```bash
# 1. 检查会话历史
opencode session history abc123

# 2. 从特定点 fork
opencode session fork abc123 --point <message-id>

# 3. 检查备份
ls -la ~/.local/share/opencode/backup/

# 4. 如果有导出，从导出恢复
opencode session import --file sessions-backup.json
```

## 权限错误

### 症状

```
1. 权限请求频繁出现
2. 权限被意外拒绝
3. 权限规则不匹配
4. 操作被阻止
```

### 诊断步骤

#### 1. 检查当前权限

```bash
# 查看当前代理权限
opencode agent config build

# 查看会话权限
opencode session show abc123 --permission
```

#### 2. 检查权限规则

```bash
# 查看权限配置
opencode config get permission

# 验证权限规则
opencode config check --permission
```

#### 3. 查看权限历史

```bash
# 查看权限请求历史
tail -f ~/.local/share/opencode/logs/dev.log | grep "permission"

# 查看被拒绝的权限
grep "Permission.DeniedError" ~/.local/share/opencode/logs/dev.log
```

### 常见原因和解决方案

#### 原因 1: 权限规则过于严格

**症状：**

```
Error: Permission.DeniedError
Permission denied: bash command 'npm install'
```

**解决方案：**

```bash
# 1. 查看当前规则
opencode config get permission

# 2. 添加允许规则
opencode config add.permission --action allow --permission bash --pattern "npm install"

# 3. 移除过于严格的规则
opencode config remove.permission --index 0

# 4. 切换到完全访问的代理
opencode agent switch build
```

**示例配置：**

```json
{
  "permission": [
    {
      "action": "allow",
      "permission": "bash",
      "patterns": ["npm install", "git status", "npm test"]
    },
    {
      "action": "deny",
      "permission": "bash",
      "patterns": ["rm -rf /", "sudo", "dd"]
    },
    {
      "action": "ask",
      "permission": "bash",
      "patterns": ["*"]
    }
  ]
}
```

#### 原因 2: 权限请求卡住

**症状：**

```
Waiting for permission request...
# 无响应
```

**解决方案：**

```bash
# 1. 检查客户端连接
curl -I http://localhost:4096/session/abc123/events

# 2. 检查 SSE 事件流
tail -f ~/.local/share/opencode/logs/dev.log | grep "permission"

# 3. 重启 UI
# 如果使用 TUI，按 Ctrl+C 重新启动
# 如果使用 Web，刷新页面

# 4. 自动允许所有权限（不推荐）
opencode config set permission.auto_allow true
```

#### 原因 3: 模式匹配失败

**症状：**

```
Error: Pattern does not match
Permission denied: bash command 'npm run build'
```

**解决方案：**

```bash
# 1. 检查模式语法
opencode config test.permission --pattern "npm run build" --permission bash

# 2. 使用通配符
opencode config add.permission --action allow --permission bash --pattern "npm run *"

# 3. 使用正则表达式
opencode config add.permission --action allow --permission bash --pattern "^npm (install|test|build)$"
```

### 权限调试

```bash
# 启用权限调试日志
DEBUG=permission* opencode

# 实时查看权限评估
tail -f ~/.local/share/opencode/logs/dev.log | grep -E "permission|Permission"

# 查看权限匹配结果
grep "permission.*match" ~/.local/share/opencode/logs/dev.log
```

## 工具调用失败

### 症状

```
1. 工具调用超时
2. 工具返回错误
3. 工具执行被取消
4. 工具参数验证失败
```

### 诊断步骤

#### 1. 检查工具执行历史

```bash
# 查看会话的工具调用
opencode session tools abc123

# 查看失败的工具
opencode session tools abc123 --status failed
```

#### 2. 查看工具日志

```bash
# 查看工具执行日志
tail -f ~/.local/share/opencode/logs/dev.log | grep "tool"

# 查看特定工具的日志
grep "tool=read" ~/.local/share/opencode/logs/dev.log
```

#### 3. 测试工具

```bash
# 测试特定工具
opencode debug tool read --params '{"filePath": "/path/to/file"}'

# 测试 bash 工具
opencode debug tool bash --params '{"command": "ls -la"}'
```

### 常见原因和解决方案

#### 原因 1: 工具参数验证失败

**症状：**

```
Error: Tool.InvalidError
Invalid tool parameters: filePath is required
```

**解决方案：**

```bash
# 1. 查看工具 schema
opencode tool show read --schema

# 2. 验证参数类型
opencode tool validate read --params '{"filePath": "/path/to/file"}'

# 3. 检查必需字段
opencode tool show read --required

# 4. 在提示词中要求正确参数
```

**示例工具调用：**

```typescript
// ✅ 正确
{
  "name": "read",
  "arguments": {
    "filePath": "/path/to/file.ts"
  }
}

// ❌ 错误 - 缺少必需参数
{
  "name": "read",
  "arguments": {}
}

// ❌ 错误 - 参数类型错误
{
  "name": "read",
  "arguments": {
    "filePath": 12345  // 应该是字符串
  }
}
```

#### 原因 2: 工具执行超时

**症状：**

```
Error: Tool timeout after 30s
```

**解决方案：**

```bash
# 1. 增加工具超时
opencode config set tool.timeout 120000  # 2 分钟

# 2. 为特定工具配置超时
opencode config set tool.bash.timeout 300000  # 5 分钟

# 3. 检查工具是否真的挂起
# 手动在终端中运行相同命令

# 4. 查看工具执行日志
tail -f ~/.local/share/opencode/logs/dev.log | grep -E "tool.*started|tool.*completed"
```

#### 原因 3: 工具权限不足

**症状：**

```
Error: Permission denied
Tool 'bash' requires write permission
```

**解决方案：**

```bash
# 1. 检查工具权限要求
opencode tool show bash --permission

# 2. 更新权限规则
opencode config add.permission --action allow --permission bash --pattern "*"

# 3. 切换代理
opencode agent switch build
```

#### 原因 4: 外部命令失败

**症状：**

```
Error: External command failed
Command: npm install
Exit code: 1
```

**解决方案：**

```bash
# 1. 查看命令输出
tail -f ~/.local/share/opencode/logs/dev.log | grep "bash.*stderr"

# 2. 手动测试命令
npm install

# 3. 检查环境
echo $NODE_VERSION
which node

# 4. 在正确的目录中执行
cd /path/to/project
npm install
```

## 会话恢复

### 会话 Revert 功能

Revert 允许你撤销会话中的更改，恢复到之前的状态。

#### 1. 查看可恢复的点

```bash
# 列出所有可恢复的点和部分
opencode session revertable abc123

# 输出示例：
# Message ID: msg_123 (User message)
#   Part ID: part_456 (Tool: read)
#   Part ID: part_789 (Assistant response)
# Message ID: msg_124 (User message)
```

#### 2. Revert 到特定点

```bash
# Revert 到特定消息
opencode session revert abc123 --message msg_123

# Revert 到特定部分
opencode session revert abc123 --part part_456

# Revert 到上一个成功点
opencode session revert abc123 --last-success
```

#### 3. 查看恢复状态

```bash
# 检查当前恢复状态
opencode session show abc123 --revert

# 输出示例：
# Reverted to: msg_123
# Revert timestamp: 2026-01-22 10:30:00
# Snapshot: /path/to/snapshot.tar.gz
# Diff: /path/to/diff.patch
```

#### 4. 取消恢复

```bash
# 如果恢复后想要取消
opencode session unrevert abc123

# 恢复恢复前的状态
```

### 会话 Fork 功能

Fork 允许你从任何点创建新会话，保留历史。

```bash
# Fork 当前会话
opencode session fork abc123

# Fork 到特定消息点
opencode session fork abc123 --point msg_123

# Fork 到特定部分
opencode session fork abc123 --point part_456

# Fork 并设置新标题
opencode session fork abc123 --title "Forked session"
```

### 会话备份和导出

```bash
# 导出单个会话
opencode session export abc123 --output session-backup.json

# 导出所有会话
opencode session export --all --output all-sessions.json

# 包含消息和部分
opencode session export abc123 --include-messages --output full-session.json
```

### 会话导入

```bash
# 导入会话
opencode session import --file session-backup.json

# 导入并覆盖现有会话
opencode session import --file session-backup.json --overwrite

# 导入到特定项目
opencode session import --file session-backup.json --project /path/to/project
```

## 会话压缩

会话压缩自动减少上下文窗口大小，当会话历史超过模型限制时。

### 何时触发压缩

```bash
# 查看压缩阈值
opencode config get session.compaction.threshold

# 默认：100,000 tokens（输入 + 缓存 + 输出）
```

### 压缩过程

1. **检测溢出：**

   ```
   tokens.input + tokens.cache.read + tokens.output > threshold
   ```

2. **创建压缩代理：**
   - 使用 "compaction" 代理
   - 只读权限
   - 总结历史消息

3. **移除旧内容：**
   - 保留最近的消息（~40,000 tokens）
   - 移除旧工具输出
   - 过滤掉压缩消息

4. **创建摘要：**
   - 总结之前的内容
   - 保留重要信息
   - 作为第一条消息插入

### 手动压缩会话

```bash
# 压缩特定会话
opencode session compact abc123

# 压缩所有旧会话
opencode session compact --older-than 7d

# 查看压缩状态
opencode session compact abc123 --status
```

### 压缩配置

```bash
# 启用自动压缩
opencode config set session.compaction.enabled true

# 设置压缩阈值
opencode config set session.compaction.threshold 80000

# 设置保留消息数
opencode config set session.compaction.keep_messages 10

# 禁用压缩（不推荐）
opencode config set session.compaction.enabled false
```

### 监控压缩

```bash
# 查看压缩事件
tail -f ~/.local/share/opencode/logs/dev.log | grep "compaction"

# 查看压缩日志
grep "session.*compact" ~/.local/share/opencode/logs/dev.log
```

## 会话状态

### 状态类型

| 状态    | 描述                     | 转换到      |
| ------- | ------------------------ | ----------- |
| `idle`  | 会话空闲，可以处理新请求 | busy        |
| `busy`  | 会话正在处理请求         | idle, retry |
| `retry` | 会话正在重试失败的操作   | busy, idle  |

### 查看会话状态

```bash
# 查看所有会话状态
opencode session status

# 查看特定会话状态
opencode session status --session abc123

# 实时监控状态
watch -n 1 'opencode session status --session abc123'
```

### 状态日志

```bash
# 查看状态变化
tail -f ~/.local/share/opencode/logs/dev.log | grep "SessionStatus"

# 输出示例：
# [INFO] SessionStatus changed: idle → busy
# [INFO] SessionStatus changed: busy → retry
# [INFO] SessionStatus changed: retry → busy
# [INFO] SessionStatus changed: busy → idle
```

### 状态转换图

```
    ┌──────┐
    │ idle │
    └───┬──┘
        │
        │ prompt()
        ↓
    ┌──────┐
    │ busy │
    └───┬──┘
        │
        │ error (retryable)
        ↓
    ┌────────┐
    │  retry │
    └───┬────┘
        │
        │ retry attempt
        ↓
    ┌──────┐
    │ busy │
    └───┬──┘
        │
        │ error (non-retryable) / success
        ↓
    ┌──────┐
    │ idle │
    └──────┘
```

```bash
# 查看会话性能

# 查看消息处理时间
opencode message timing msg_123

# 查看工具执行时间
opencode tool timing --session abc123
```

## 故障排除工作流

### 问题识别 → 诊断 → 解决 → 验证

```
┌─────────────┐
│ 问题识别    │  用户报告问题或系统检测到异常
└───────┬─────┘
        ↓
┌─────────────┐
│   诊断     │  1. 查看会话状态
│             │  2. 检查日志
│             │  3. 运行健康检查
└───────┬─────┘
        ↓
┌─────────────┐
│   解决     │  1. 应用修复
│             │  2. 使用恢复机制
│             │  3. 创建新会话
└───────┬─────┘
        ↓
┌─────────────┐
│   验证     │  1. 测试会话
│             │  2. 监控日志
│             │  3. 确认问题解决
└─────────────┘
```
