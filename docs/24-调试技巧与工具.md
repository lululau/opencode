## 概述

## Bun Inspector

### 启用 Inspector

Bun 内置调试器，使用 Chrome DevTools Protocol：

```bash
# 启用 inspector 运行应用
bun --inspect opencode

# 或指定端口
bun --inspect=9230 opencode

# 暂停执行等待调试器连接
bun --inspect-brk opencode
```

### 连接 Chrome DevTools

1. 启动带 inspector 的应用：

   ```bash
   bun --inspect-brk bun run --conditions=browser ./src/index.ts serve
   ```

2. 打开 Chrome 浏览器，访问 `chrome://inspect`

3. 选择 "Open dedicated DevTools for Node"

4. 在 DevTools 中设置断点并调试

### 调试命令

| 命令                 | 描述                             |
| -------------------- | -------------------------------- |
| `bun --inspect`      | 启动 inspector，运行到第一个断点 |
| `bun --inspect-brk`  | 启动并在第一行暂停               |
| `bun --inspect=PORT` | 指定 inspector 端口（默认 9230） |

### Inspector 使用示例

```bash
# 调试 opencode 服务器
cd packages/opencode
bun --inspect-brk dev -- --print-logs serve

# 控制台输出：
# Debugger listening on ws://127.0.0.1:9230/...
# For help, see: https://nodejs.org/en/docs/inspector
# Waiting for debugger to disconnect...
```

然后在 Chrome DevTools 中：

1. 打开 `chrome://inspect`
2. 点击 "inspect"
3. 查看源码、设置断点
4. 继续执行

## VSCode 调试

### 创建 launch.json

OpenCode 当前没有预设的 VSCode 调试配置。需要手动创建 `.vscode/launch.json`：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "node",
      "request": "launch",
      "name": "Debug OpenCode Server",
      "program": "${workspaceFolder}/packages/opencode/src/index.ts",
      "runtimeExecutable": "${workspaceFolder}/node_modules/.bin/bun",
      "runtimeArgs": ["--inspect-brk"],
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}/packages/opencode",
      "env": {
        "NODE_ENV": "development"
      }
    },
    {
      "type": "node",
      "request": "launch",
      "name": "Debug Bun Test",
      "program": "${workspaceFolder}/packages/opencode/test/tool/bash.test.ts",
      "runtimeExecutable": "${workspaceFolder}/node_modules/.bin/bun",
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}/packages/opencode",
      "internalConsoleOptions": "neverOpen"
    },
    {
      "name": "Debug Playwright E2E",
      "type": "node",
      "request": "launch",
      "runtimeExecutable": "${workspaceFolder}/node_modules/.bin/bun",
      "program": "${workspaceFolder}/packages/app/node_modules/.bin/playwright",
      "args": ["test", "--debug", "--headed"],
      "cwd": "${workspaceFolder}/packages/app",
      "console": "integratedTerminal"
    }
  ]
}
```

### 调试配置说明

| 配置项              | 说明                                    |
| ------------------- | --------------------------------------- |
| `type`              | 调试类型（node）                        |
| `request`           | launch（启动）或 attach（附加）         |
| `program`           | 入口文件路径                            |
| `runtimeExecutable` | Bun 可执行文件路径                      |
| `runtimeArgs`       | 传递给 Bun 的参数（如 `--inspect-brk`） |
| `cwd`               | 工作目录                                |
| `env`               | 环境变量                                |

### 调试 TypeScript 源码

VSCode 会自动使用 source maps。确保 `tsconfig.json` 配置正确：

```json
{
  "compilerOptions": {
    "sourceMap": true,
    "outDir": "./dist",
    "rootDir": "./src"
  }
}
```

### 调试步骤

1. 在 VSCode 中打开项目
2. 按 `F5` 或点击 Run and Debug 面板
3. 选择配置（如 "Debug OpenCode Server"）
4. 设置断点
5. 按 `F5` 开始调试
6. 使用调试工具栏控制执行：
   - `F5`：继续
   - `F10`：单步跳过
   - `F11`：单步进入
   - `Shift+F11`：单步跳出
   - `Shift+F5`：停止

### 调试 Bun 测试

```json
{
  "name": "Debug Bun Test",
  "type": "buntest",
  "request": "launch",
  "program": "${workspaceFolder}/packages/opencode/test/tool/bash.test.ts",
  "cwd": "${workspaceFolder}/packages/opencode"
}
```

## 日志系统

### 日志系统架构

OpenCode 使用结构化日志系统，提供多级别日志和时间追踪。

### 日志级别

| 级别    | 用途         | 示例                                       |
| ------- | ------------ | ------------------------------------------ |
| `DEBUG` | 详细调试信息 | "Loading config from /path/to/config.json" |
| `INFO`  | 一般信息     | "Server started on port 4096"              |
| `WARN`  | 警告信息     | "Permission rejected by user"              |
| `ERROR` | 错误信息     | "Failed to connect to MCP server"          |

### 创建日志记录器

```typescript
import { Log } from "@opencode-ai/opencode/util/log"

// 创建日志记录器
const log = Log.create({ service: "your-service" })

// 记录不同级别
log.debug("debug message", { extra: "data" })
log.info("info message")
log.warn("warning message")
log.error("error message", { error: err })
```

### 日志初始化

```typescript
import { Log } from "@opencode-ai/opencode/util/log"

// 初始化日志系统
await Log.init({
  print: true, // 输出到控制台
  level: "DEBUG", // 最低日志级别
  dev: true, // 开发模式
})

// 获取日志文件路径
const logPath = Log.file()
console.log("Logs at:", logPath)
```

### 性能计时

```typescript
import { Log } from "@opencode-ai/opencode/util/log"

const log = Log.create({ service: "your-service" })

// 使用 using 语句自动计时
using timer = log.time("operation-name", { id: 123 })
// 执行操作...
await someOperation()
// 自动停止并记录

// 手动控制
const timer = log.time("operation")
// ... 做一些工作
timer.stop()
```

输出：

```
[DEBUG] operation status=started id=123
[DEBUG] operation status=completed id=123 duration=45ms
```

### 日志文件位置

| 环境     | 日志路径                                              |
| -------- | ----------------------------------------------------- |
| 开发模式 | `$XDG_DATA_HOME/opencode/logs/dev.log`                |
| 生产模式 | `$XDG_DATA_HOME/opencode/logs/YYYY-MM-DDTHHHMMSS.log` |

XDG 数据目录默认值：

- Linux/macOS: `~/.local/share/opencode/logs/`
- Windows: `%LOCALAPPDATA%\opencode\logs\`

### 日志清理

日志系统自动保留最近 10 个日志文件，删除旧文件：

```typescript
// packages/opencode/src/util/log.ts
const MAX_LOG_FILES = 10

// 自动清理逻辑
const logFiles = await fs.readdir(logDir)
if (logFiles.length > MAX_LOG_FILES) {
  const toDelete = logFiles.slice(0, logFiles.length - MAX_LOG_FILES)
  for (const file of toDelete) {
    await fs.unlink(path.join(logDir, file))
  }
}
```

### 查看日志

```bash
# 实时查看开发日志
tail -f ~/.local/share/opencode/logs/dev.log

# 查看最近的日志
ls -lt ~/.local/share/opencode/logs/ | head -5

# 搜索错误
grep ERROR ~/.local/share/opencode/logs/dev.log

# 查看特定服务的日志
grep "service=agent" ~/.local/share/opencode/logs/dev.log
```

### 云端日志 (Zen API)

Zen API 使用 Honeycomb 进行分布式追踪：

```typescript
// packages/console/function/src/log-processor.ts

// 记录指标
log.info("_metric:request_latency", {
  latency: 123,
  endpoint: "/api/v1/chat",
})

// Honeycomb 会收集并可视化这些指标
```

## 性能分析

### 导航性能追踪

Web 应用使用 `performance.now()` 进行精确计时：

```typescript
// packages/app/src/utils/perf.ts

import { navStart, navParams, navMark } from "~/utils/perf"

// 开始导航
navStart({
  dir: "/path/to/project",
  to: "session-id",
  trigger: "click",
})

// 记录参数
navParams({ dir: "/path/to/project", to: "session-id" })

// 记录生命周期事件
navMark({
  dir: "/path/to/project",
  to: "session-id",
  name: "session:first-turn-mounted",
})

navMark({
  name: "storage:prompt-ready",
})

// 自动提交或超时
```

**性能标记：**

| 标记                         | 描述               |
| ---------------------------- | ------------------ |
| `session:params`             | 会话参数加载完成   |
| `session:data-ready`         | 会话数据加载完成   |
| `session:first-turn-mounted` | 第一条消息渲染完成 |
| `storage:prompt-ready`       | 提示输入就绪       |
| `storage:terminal-ready`     | 终端就绪           |
| `storage:file-view-ready`    | 文件视图就绪       |

## 常见问题排查

### 应用启动失败

**问题**：`bun run` 失败，无错误消息

**排查步骤：**

1. **启用详细日志**：

   ```bash
   DEBUG=* bun run --conditions=browser ./src/index.ts serve
   ```

2. **检查依赖**：

   ```bash
   bun install
   rm -rf node_modules bun.lockb
   bun install
   ```

3. **检查环境变量**：

   ```bash
   echo $ANTHROPIC_API_KEY
   echo $OPENAI_API_KEY
   ```

4. **查看日志文件**：
   ```bash
   tail -f ~/.local/share/opencode/logs/dev.log
   ```

### 工具执行超时

**问题**：工具调用超时或挂起

**排查步骤：**

1. **添加超时日志**：

   ```typescript
   const log = Log.create({ service: "tool" })
   using timer = log.time("tool-execution")

   try {
     const result = await Tool.execute(args, ctx)
   } finally {
     timer.stop()
   }
   ```

2. **检查 AbortSignal**：

   ```typescript
   if (ctx.abort.aborted) {
     log.warn("Tool execution aborted")
     throw new Error("Aborted by user")
   }
   ```

3. **查看工具执行历史**：
   ```bash
   grep "tool-execution" ~/.local/share/opencode/logs/dev.log
   ```

### 权限请求卡住

**问题**：权限请求无响应

**排查步骤：**

1. **检查 Question.ask 调用**：

   ```typescript
   const log = Log.create({ service: "permission" })
   log.debug("Asking permission", { permission: "bash" })

   await ctx.ask({
     permission: "bash",
     patterns: ["*"],
     metadata: { command: args.command },
   })
   ```

2. **查看 SSE 事件流**：

   ```typescript
   // 客户端端
   eventSource.addEventListener("permission", (e) => {
     console.log("Permission request received:", JSON.parse(e.data))
   })
   ```

3. **检查客户端连接**：
   ```bash
   # 检查 SSE 连接
   curl -v http://localhost:4096/session/123/events
   ```

### 内存泄漏

**问题**：应用随时间使用更多内存

**排查步骤：**

1. **使用 Bun 内存分析**：

   ```bash
   bun --expose-gc opencode
   ```

2. **在代码中监控内存**：

   ```typescript
   const log = Log.create({ service: "memory" })

   setInterval(() => {
     const mem = process.memoryUsage()
     log.info("Memory usage", {
       heapUsed: `${Math.round(mem.heapUsed / 1024 / 1024)}MB`,
       heapTotal: `${Math.round(mem.heapTotal / 1024 / 1024)}MB`,
     })
   }, 5000)
   ```

3. **查看大对象**：
   ```typescript
   // 检查缓存大小
   const log = Log.create({ service: "cache" })
   log.info("Cache size", {
     entries: cache.size,
     memory: JSON.stringify(Array.from(cache.entries())).length,
   })
   ```

### 性能缓慢

**问题**：应用响应慢

**排查步骤：**

1. **启用性能标记**：

   ```typescript
   // packages/app/src/pages/session.tsx
   import { navMark } from "~/utils/perf"

   useEffect(() => {
     navMark({ name: "session:mounted" })
   }, [])
   ```

2. **检查日志计时**：

   ```bash
   grep "status=completed" ~/.local/share/opencode/logs/dev.log
   ```

3. **使用浏览器性能工具**：
   - 打开 Chrome DevTools Performance 面板
   - 录制页面加载
   - 查看长时间运行的脚本
   - 检查重绘和布局

4. **检查网络请求**：
   - DevTools Network 面板
   - 查看慢请求
   - 检查请求大小和响应时间

### LSP 连接失败

**问题**：LSP 服务器无法启动或连接

**排查步骤：**

1. **启用 LSP 调试日志**：

   ```bash
   DEBUG=lsp* bun run --conditions=browser ./src/index.ts serve
   ```

2. **检查 LSP 服务器进程**：

   ```bash
   ps aux | grep -i "typescript-language-server"
   ```

3. **手动测试 LSP**：

   ```bash
   # 使用内置调试命令
   cd packages/opencode
   bun debug lsp --file test.ts --line 10
   ```

4. **查看 LSP 日志**：
   ```bash
   grep "service=lsp" ~/.local/share/opencode/logs/dev.log
   ```

## 调试最佳实践

### 1. 使用结构化日志

❌ **Bad**:

```typescript
console.log("Error loading file:", error)
```

✅ **Good**:

```typescript
const log = Log.create({ service: "file-loader" })
log.error("Failed to load file", {
  filePath: path,
  error: error.toString(),
  code: error.code,
})
```

### 2. 性能关键路径添加计时

```typescript
const log = Log.create({ service: "api" })

// 快速操作不需要计时
const config = loadConfig()

// 慢操作需要计时
using timer = log.time("database-query")
const data = await db.query("SELECT * FROM table")
```

### 3. 使用断点调试

- ✅ 在 VSCode 中设置断点
- ✅ 使用条件断点（如 `count > 10`）
- ✅ 使用日志断点（`console.log` 执行特定操作）
- ❌ 不要在代码中硬编码调试语句

### 4. 错误处理和日志

```typescript
try {
  await operation()
} catch (error) {
  const log = Log.create({ service: "operation" })

  // 记录错误上下文
  log.error("Operation failed", {
    error: error.message,
    stack: error.stack,
    cause: error.cause,
    context: { param1, param2 },
  })

  // 重新抛出或处理
  throw error
}
```

### 5. 环境特定日志

```typescript
const log = Log.create({ service: "service" })

// 开发模式详细日志
if (process.env.NODE_ENV === "development") {
  log.debug("Detailed debug info", { details })
}

// 生产模式仅错误
if (process.env.NODE_ENV === "production") {
  log.error("Production error", { error })
}
```

### 6. 渐进式日志级别

```typescript
// 开始时使用 DEBUG
await Log.init({ level: "DEBUG" })

// 找到问题后降低级别
await Log.init({ level: "INFO" })

// 解决后恢复
await Log.init({ level: "DEBUG" })
```

### 7. 使用 Inspector 深入调试复杂函数

```bash

bun --inspect-brk opencode

# 2. 连接 Chrome DevTools
# 3. 设置条件断点

# 5. 修改变量值测试不同路径
```
