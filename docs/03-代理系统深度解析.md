## 代理系统概述

代理（Agent）是 OpenCode 的核心概念，代表具有不同能力、权限和行为模式的 AI 助手。每个代理都是一个专门的 AI 实体，拥有：

- **特定的系统提示词**：定义代理的角色、职责和行为边界
- **独立的权限配置**：控制代理可以执行的操作
- **模型配置**：可以选择使用不同的 AI 模型
- **自定义参数**：温度、top_p、steps 等 AI 模型参数

### 架构图

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户交互层                                 │
│              (TUI / Web / Desktop CLI)                           │
└────────────────────┬────────────────────────────────────────────┘
                     │
                     ├─→ Primary Agents (直接切换使用)
                     │   - build: 完整开发权限
                     │   - plan: 只读分析
                     │
                     ├─→ Subagents (内部调用)
                     │   - general: 通用任务
                     │   - explore: 代码搜索
                     │
                     └─→ Custom Agents (用户自定义)
                         └─→ 从配置文件加载
└────────────────────┴────────────────────────────────────────────┘
                     │
                     ↓
         ┌──────────────────────┐
         │   代理管理器         │
         │   (Agent.state)      │
         │                      │
         │ - Agent.get()        │
         │ - Agent.list()       │
         │ - Agent.generate()   │
         └──────────┬───────────┘
                    │
                    ↓
         ┌──────────────────────┐
         │   权限系统           │
         │   (PermissionNext)   │
         │                      │
         │ - 规则评估           │
         │ - 动作检查           │
         │ - 用户交互           │
         └──────────────────────┘
```

### 核心设计原则

1. **专业化**：每个代理专注于特定任务领域
2. **权限隔离**：代理的权限严格分离，确保安全性
3. **可组合性**：代理可以相互调用，形成复杂工作流
4. **可扩展性**：用户可以轻松创建自定义代理

## 代理类型

OpenCode 定义了三种代理类型，通过 `mode` 字段标识：

### 1. Primary Agents（主要代理）

**特点**：

- 用户可以直接通过 `Tab` 键或命令行切换使用
- 在 TUI 中显示为可切换的选项
- 作为默认交互代理

**示例**：

- `build`：默认开发代理
- `plan`：只读分析代理

**代码识别**：

```typescript
mode: "primary"
```

**使用场景**：

- 作为用户的主工作代理
- 长期交互和复杂任务
- 需要用户直接控制的场景

### 2. Subagents（子代理）

**特点**：

- 不能直接由用户切换使用
- 由其他代理内部调用（通过 `task` 工具）
- 不出现在 TUI 的代理切换列表中
- 专注于特定子任务

**示例**：

- `general`：通用子代理
- `explore`：代码探索子代理

**代码识别**：

```typescript
mode: "subagent"
```

**使用场景**：

- 代理内部委托任务
- 专业化子任务处理
- 需要权限隔离的场景

### 3. All（通用代理）

**特点**：

- 既可以作为主要代理，也可以作为子代理
- 提供最大的灵活性

**代码识别**：

```typescript
mode: "all"
```

**使用场景**：

- 需要多用途的代理
- 用户自定义代理的默认模式

### 类型对比表

| 特性            | Primary | Subagent | All |
| --------------- | ------- | -------- | --- |
| 用户可切换      | ✅      | ❌       | ✅  |
| 内部可调用      | ✅      | ✅       | ✅  |
| 显示在 TUI 列表 | ✅      | ❌       | ✅  |
| 可通过 @ 调用   | ❌      | ✅       | ✅  |
| 默认可代理      | ✅      | ❌       | ✅  |

### 隐藏代理

任何代理都可以通过 `hidden: true` 属性隐藏：

```typescript
{
  name: "compaction",
  hidden: true,
  mode: "primary"  // 隐藏的主要代理（不显示在 TUI 中）
}
```

**使用场景**：

- 内部实用代理（如 `compaction`、`title`、`summary`）
- 不希望用户直接调用的代理
- 后台处理代理

## 代理配置结构

### Agent.Info 接口定义

```typescript
import { z } from "zod"
import { PermissionNext } from "@/permission/next"

export const Info = z.object({
  // 基础信息
  name: z.string(), // 代理唯一标识
  description: z.string().optional(), // 描述

  // 类型和行为
  mode: z.enum(["subagent", "primary", "all"]), // 代理类型
  native: z.boolean().optional(), // 是否内置代理
  hidden: z.boolean().optional(), // 是否隐藏

  // AI 模型参数
  topP: z.number().optional(), // Top P 参数
  temperature: z.number().optional(), // 温度参数
  color: z.string().optional(), // UI 颜色（十六进制）

  // 权限配置
  permission: PermissionNext.Ruleset, // 权限规则集

  // 模型选择
  model: z
    .object({
      modelID: z.string(), // 模型 ID
      providerID: z.string(), // 提供商 ID
    })
    .optional(),

  // 提示词和选项
  prompt: z.string().optional(), // 系统提示词
  options: z.record(z.string(), z.any()), // 自定义选项
  steps: z.number().int().positive().optional(), // 最大迭代步骤
})
```

### 配置优先级

代理配置遵循以下优先级顺序（从高到低）：

1. **用户配置文件**（`~/.opencode/config.json` 中的 `agent` 字段）
2. **代码内置配置**（内置代理的默认配置）
3. **默认权限配置**（系统默认权限）

### 配置合并机制

```typescript
// 1. 从默认权限开始
const defaults = PermissionNext.fromConfig({
  "*": "allow",
  read: {
    "*": "allow",
    "*.env": "ask",
  },
})

// 2. 合并用户配置
const user = PermissionNext.fromConfig(cfg.permission ?? {})

// 3. 合并代理特定权限
const agentPermission = PermissionNext.merge(
  defaults,
  PermissionNext.fromConfig({
    question: "allow",
    edit: "deny",
  }),
  user,
)
```

### 字段详解

#### `name`（必需）

- 代理的唯一标识符
- 用于在配置、日志、UI 中引用
- 必须符合标识符命名规范（字母、数字、连字符）

#### `description`（可选）

- 描述代理的用途和使用场景
- 显示在 TUI 的代理选择界面
- 用于 `@` 自动完成提示

#### `mode`（可选，默认："all"）

- `"primary"`：主要代理，用户可直接切换
- `"subagent"`：子代理，只能内部调用
- `"all"`：通用代理，两者皆可

#### `permission`（必需）

- 权限规则集，定义代理可以执行的操作
- 详细说明见 [权限系统集成](#权限系统集成)

#### `prompt`（可选）

- 系统提示词，定义代理的角色和行为
- 支持多行文本
- 可以包含变量和模板

#### `model`（可选）

```typescript
{
  modelID: "anthropic/claude-sonnet-4-20250514",
  providerID: "anthropic"
}
```

#### `temperature`（可选）

- 控制输出随机性
- 范围：0.0 - 1.0
- 较低的值使输出更确定
- 较高的值使输出更多样

#### `topP`（可选）

- 核采样参数
- 控制词汇多样性
- 范围：0.0 - 1.0

#### `steps`（可选）

- 最大代理迭代步骤数
- 超过此步骤数后强制返回文本响应
- 防止无限循环

#### `options`（可选）

- 任意自定义键值对
- 可以存储代理特定的配置

#### `color`（可选）

- UI 中显示的颜色
- 格式：十六进制（如 `#FF5733`）
- 用于在 TUI 中区分不同代理

## 内置代理详解

### 1. Build 代理

**基本信息**：

```typescript
{
  name: "build",
  mode: "primary",
  native: true,
  description: "默认开发代理，完整访问权限"
}
```

**特点**：

- 默认主要代理
- 拥有最宽泛的权限
- 适用于大多数开发任务

**权限配置**：

```typescript
{
  "*": "allow",           // 允许所有操作
  doom_loop: "ask",       // 循环检测需要确认
  question: "allow",      // 允许提问
  plan_enter: "allow",    // 允许进入计划模式
  external_directory: {
    "*": "ask",           // 外部目录需要确认
  },
  read: {
    "*": "allow",
    "*.env": "ask",       // .env 文件需要确认
  }
}
```

**适用场景**：

- 日常开发工作
- 文件编辑和创建
- 命令执行
- 需要完整权限的任务

**特殊行为**：

- 作为 `Agent.defaultAgent()` 的默认返回值
- 在 `Agent.list()` 中排在首位（如果配置了 `default_agent`）

### 2. Plan 代理

**基本信息**：

```typescript
{
  name: "plan",
  mode: "primary",
  native: true,
  description: "只读代理，用于分析和规划"
}
```

**特点**：

- 专注于代码分析和规划
- 默认拒绝文件编辑
- 适合探索不熟悉的代码库

**权限配置**：

```typescript
{
  "*": "allow",
  question: "allow",
  plan_exit: "allow",     // 允许退出计划模式
  external_directory: {
    [planPath]: "allow",  // 允许访问计划目录
  },
  edit: {
    "*": "deny",          // 拒绝所有编辑操作
    [".opencode/plans/*.md"]: "allow",  // 只允许编辑计划文件
  }
}
```

**适用场景**：

- 代码探索和分析
- 架构理解
- 重构规划
- 代码审查准备

**特殊行为**：

- 当代理尝试编辑文件时，会被权限系统阻止
- 自动切换到只读模式
- 创建计划文件时不受限制

### 3. General 代理

**基本信息**：

```typescript
{
  name: "general",
  mode: "subagent",
  native: true,
  description: `General-purpose agent for researching complex questions and executing multi-step tasks. Use this agent to execute multiple units of work in parallel.`
}
```

**特点**：

- 通用子代理
- 支持复杂的多步骤任务
- 可以并行执行多个工作单元

**权限配置**：

```typescript
{
  "*": "allow",

  todowrite: "deny",      // 禁止写入待办事项
```

**适用场景**：

### 4. Explore 代理

**基本信息**：


**特点**：

- 支持不同探索深度

**适用场景**：

- 代码模式搜索

**特殊行为**：

- 不修改任何文件

## 代理生命周期

### 1. 代理注册

代理在应用启动时通过 `Instance.state` 注册：

```typescript
// packages/opencode/src/agent/agent.ts

const state = Instance.state(async () => {
  const cfg = await Config.get()

  // 1. 定义默认权限
  const defaults = PermissionNext.fromConfig({
    "*": "allow",
    doom_loop: "ask",
    external_directory: {
      "*": "ask",
      [Truncate.DIR]: "allow",
    },
  })

  // 2. 合并用户配置
  const user = PermissionNext.fromConfig(cfg.permission ?? {})

  // 3. 定义内置代理
  const result: Record<string, Info> = {
    build: {
      /* ... */
    },
    plan: {
      /* ... */
    },
    general: {
      /* ... */
    },
    explore: {
      /* ... */
    },
    // ...
  }

  // 4. 加载用户自定义代理
  for (const [key, value] of Object.entries(cfg.agent ?? {})) {
    if (value.disable) {
      delete result[key]
      continue
    }

    let item = result[key]
    if (!item) {
      // 创建新代理
      item = result[key] = {
        name: key,
        mode: "all",
        permission: PermissionNext.merge(defaults, user),
        options: {},
        native: false,
      }
    }

    // 合并用户配置
    if (value.model) item.model = Provider.parseModel(value.model)
    item.prompt = value.prompt ?? item.prompt
    item.description = value.description ?? item.description
    item.temperature = value.temperature ?? item.temperature
    item.topP = value.top_p ?? item.topP
    item.mode = value.mode ?? item.mode
    item.color = value.color ?? item.color
    item.hidden = value.hidden ?? item.hidden
    item.steps = value.steps ?? item.steps
    item.options = mergeDeep(item.options, value.options ?? {})
    item.permission = PermissionNext.merge(item.permission, PermissionNext.fromConfig(value.permission ?? {}))
  }

  return result
})
```

### 2. 代理获取

```typescript
// 获取单个代理
const agent = await Agent.get("build")
console.log(agent.name, agent.mode, agent.permission)

// 获取代理列表
const agents = await Agent.list()
// 返回按 default_agent 排序的代理数组
```

### 3. 代理选择

用户交互时选择代理：

```typescript
// 获取默认代理
const defaultAgent = await Agent.defaultAgent()

// 在会话中使用代理
await Session.prompt({
  sessionID,
  agent: defaultAgent, // 或用户指定的代理
  model: { modelID, providerID },
  parts: messageParts,
})
```

### 4. 代理执行流程

```
用户输入
  ↓
选择代理 (Agent.get/Agent.defaultAgent)
  ↓
构建会话上下文
  ↓
调用 SessionPrompt.prompt()
  ↓
初始化 LLM 流 (LLM.stream)
  ↓
处理 AI 响应 (SessionProcessor.process)
  ↓
  ├─→ 文本响应 → 显示
  ├─→ 工具调用 → Tool.execute() → 权限检查 → 执行
  └─→ 子代理调用 → TaskTool.execute() → 创建新会话
  ↓
更新消息历史
  ↓
检查是否需要压缩 (compaction、title、summary)
  ↓
完成/继续循环
```

### 5. 代理销毁

代理不会被显式销毁，它们在整个应用生命周期中存在。但：

- 用户可以通过配置 `disable: true` 禁用代理
- 重启应用会重新加载所有代理配置

## 子代理调用机制

### Task 工具

子代理调用通过 `task` 工具实现：

```typescript
// packages/opencode/src/tool/task.ts

export const TaskTool = Tool.define("task", async (ctx) => {
  // 1. 获取所有子代理
  const agents = await Agent.list().then((x) => x.filter((a) => a.mode !== "primary"))

  // 2. 根据调用代理的权限过滤
  const caller = ctx?.agent
  const accessibleAgents = caller
    ? agents.filter((a) => PermissionNext.evaluate("task", a.name, caller.permission).action !== "deny")
    : agents

  // 3. 构建工具描述
  const description = DESCRIPTION.replace(
    "{agents}",
    accessibleAgents
      .map((a) => `- ${a.name}: ${a.description ?? "This subagent should only be called manually by the user."}`)
      .join("\n"),
  )

  return {
    description,
    parameters: z.object({
      description: z.string(),
      prompt: z.string(),
      subagent_type: z.string(),
      session_id: z.string().optional(),
      command: z.string().optional(),
    }),

    async execute(params, ctx) {
      // 4. 权限检查
      await ctx.ask({
        permission: "task",
        patterns: [params.subagent_type],
        always: ["*"],
        metadata: {
          description: params.description,
          subagent_type: params.subagent_type,
        },
      })

      // 5. 获取目标代理
      const agent = await Agent.get(params.subagent_type)
      if (!agent) {
        throw new Error(`Unknown agent type: ${params.subagent_type} is not a valid agent type`)
      }

      // 6. 检查代理是否有 task 权限
      const hasTaskPermission = agent.permission.some((rule) => rule.permission === "task")

      // 7. 创建子会话
      const session = await Session.create({
        parentID: ctx.sessionID, // 关联父会话
        title: params.description + ` (@${agent.name} subagent)`,
        permission: [
          {
            permission: "todowrite",
            pattern: "*",
            action: "deny",
          },
          {
            permission: "todoread",
            pattern: "*",
            action: "deny",
          },
          ...(hasTaskPermission
            ? []
            : [
                {
                  permission: "task",
                  pattern: "*",
                  action: "deny", // 防止嵌套调用
                },
              ]),
        ],
      })

      // 8. 订阅子会话事件
      const parts = {}
      const unsub = Bus.subscribe(MessageV2.Event.PartUpdated, async (evt) => {
        if (evt.properties.part.sessionID !== session.id) return
        const part = evt.properties.part
        parts[part.id] = {
          id: part.id,
          tool: part.tool,
          state: {
            status: part.state.status,
            title: part.state.status === "completed" ? part.state.title : undefined,
          },
        }
        ctx.metadata({
          title: params.description,
          metadata: {
            summary: Object.values(parts).sort((a, b) => a.id.localeCompare(b.id)),
            sessionId: session.id,
          },
        })
      })

      // 9. 执行子代理
      const model = agent.model ?? {
        modelID: msg.info.modelID,
        providerID: msg.info.providerID,
      }

      const result = await SessionPrompt.prompt({
        messageID,
        sessionID: session.id,
        model: {
          modelID: model.modelID,
          providerID: model.providerID,
        },
        agent: agent.name,
        tools: {
          todowrite: false,
          todoread: false,
          ...(hasTaskPermission ? {} : { task: false }),
        },
        parts: promptParts,
      })

      unsub()

      // 10. 返回结果
      const messages = await Session.messages({ sessionID: session.id })
      const summary = messages
        .filter((x) => x.info.role === "assistant")
        .flatMap((msg) => msg.parts.filter((x) => x.type === "tool"))
        .map((part) => ({
          id: part.id,
          tool: part.tool,
          state: {
            status: part.state.status,
            title: part.state.status === "completed" ? part.state.title : undefined,
          },
        }))

      const text = result.parts.findLast((x) => x.type === "text")?.text ?? ""
      const output = text + "\n\n" + ["<task_metadata>", `session_id: ${session.id}`, "</task_metadata>"].join("\n")

      return {
        title: params.description,
        metadata: {
          summary,
          sessionId: session.id,
        },
        output,
      }
    },
  }
})
```

### 调用流程

```
主代理 (build)
  ↓
调用 task 工具
  ↓
  ├─→ 权限检查 (PermissionNext.evaluate)
  │   └─→ ask/allow/deny
```

## 权限系统集成

### 权限规则结构

```typescript
export const Rule = z.object({
  permission: z.string(), // 权限类型（工具名称）
  pattern: z.string(), // 模式（支持 glob）
  action: z.enum(["allow", "deny", "ask"]), // 动作
})

export const Ruleset = Rule.array()
```

### 权限动作

| 动作    | 描述 | 行为                       |
| ------- | ---- | -------------------------- |
| `allow` | 允许 | 直接执行操作，无需用户确认 |
| `deny`  | 拒绝 | 拒绝操作，抛出错误         |
| `ask`   | 询问 | 等待用户确认后再执行       |

### 代理权限配置

每个代理都有一个 `permission` 字段，包含一组权限规则：

```typescript
{
  name: "my-agent",
  permission: [
    {
      permission: "bash",
      pattern: "*",
      action: "ask"
    },
    {
      permission: "edit",
      pattern: "*.ts",
      action: "allow"
    },
    {
      permission: "edit",
      pattern: "*.env",
      action: "deny"
    }
  ]
}
```

### 权限评估机制

```typescript
// packages/opencode/src/permission/next.ts

export function evaluate(
  permission: string, // 工具名称
  pattern: string, // 操作对象
  ruleset: Ruleset, // 权限规则集
  approved: Ruleset, // 用户批准的权限
): Rule {
  // 1. 匹配用户批准的权限
  for (const rule of approved) {
    if (Wildcard.match(permission, rule.permission) && Wildcard.match(pattern, rule.pattern)) {
      return { ...rule, action: "allow" as const }
    }
  }

  // 2. 匹配权限规则
  for (const rule of ruleset) {
    if (Wildcard.match(permission, rule.permission) && Wildcard.match(pattern, rule.pattern)) {
      return rule
    }
  }

  // 3. 默认拒绝
  return {
    permission,
    pattern,
    action: "deny",
  }
}
```

### 工具执行时的权限检查

```typescript
// 在工具执行上下文中
ctx.ask({
  permission: "bash", // 工具名称
  patterns: ["ls -la"], // 操作对象
  always: ["*"], // 总是批准的模式
  metadata: {
    // 元数据
  },
})
```

### 权限匹配优先级

1. **用户批准的权限**（最高优先级）
   - 用户在对话框中选择 "Always allow" 的权限
   - 存储在 `Storage.permission[projectID]`

2. **代理权限配置**
   - 在代理定义中的 `permission` 字段
   - 包含 allow/deny/ask 规则

3. **默认权限**
   - 如果没有匹配的规则，默认 deny

### 权限继承

子会话继承父会话的权限，但可以添加额外限制：

```typescript
// 父会话权限
const parentPermission = [{ permission: "*", pattern: "*", action: "allow" }]

// 子会话权限
const childPermission = [
  { permission: "todowrite", pattern: "*", action: "deny" },
  { permission: "todoread", pattern: "*", action: "deny" },
  // ... 继承父会话的其他权限
]
```

### 权限隔离

不同代理的权限完全隔离：

```typescript

{
  permission: [{ permission: "edit", pattern: "*", action: "deny" }]

// explore 代理

  permission: [{ permission: "*", pattern: "*", action: "deny" }]
}
```

### 提示词注入机制

提示词在会话启动时注入：

```typescript
// packages/opencode/src/session/prompt.ts

export async function resolvePromptParts(input: string) {
  // 1. 解析输入
  // 2. 替换变量
  // 3. 添加系统提示词
  // 4. 返回消息部分
}

export async function prompt(input: {
  sessionID: string
  model: { modelID: string; providerID: string }
  agent: string
  tools: Record<string, boolean>
  parts: MessageV2.Part[]
}) {
  const agent = await Agent.get(input.agent)

  // 1. 获取系统提示词
  const systemPrompt = SystemPrompt.header(input.model.providerID)

  // 2. 添加代理特定提示词
  if (agent.prompt) {
    systemPrompt.push(agent.prompt)
  }

  // 3. 添加工具描述
  const tools = await getAvailableTools(input.sessionID, input.tools)

  // 4. 构建 LLM 消息
  const messages = [
    ...systemPrompt.map((item) => ({
      role: "system" as const,
      content: item,
    })),
    ...input.parts,
  ]

  // 5. 调用 LLM
  return await LLM.stream({
    model,
    messages,
    tools,
  })
}
```

### 代理选择策略

#### 1. 根据任务类型选择

| 任务类型 | 推荐代理    | 原因                 |

### 代理组合模式

#### 1. 管道模式（Pipeline）

```
User Request
  ↓
explore (find files)
  ↓
general (analyze)
  ↓
plan (design solution)
  ↓
build (implement)
```

#### 2. 分治模式（Divide and Conquer）

```
User Request
  ↓
general (split into tasks)
  ├─→ explore (task 1)
  ├─→ explore (task 2)
  └─→ explore (task 3)
  ↓
general (merge results)
```

#### 3. 专家模式（Specialist）

```
User Request
  ↓
build (analyze task)
  ↓
  ├─→ database-expert (DB queries)
  ├─→ frontend-expert (UI components)
  └─→ backend-expert (API routes)
  ↓
build (coordinate and integrate)
```

#### 2. 重试机制

```typescript
async function withRetry<T>(fn: () => Promise<T>, maxRetries = 3): Promise<T> {
  for (let i = 0; i < maxRetries; i++) {
    try {
      return await fn()
    } catch (error) {
      if (i === maxRetries - 1) throw error
      await delay(1000 * (i + 1))
    }
  }
  throw new Error("Max retries exceeded")
}
```

### 最佳实践总结

#### ✅ Do

1. **使用专业化代理**
   - explore 用于代码搜索
   - plan 用于分析和规划
   - general 用于复杂任务

2. **遵循权限最小化原则**
   - 只读任务使用只读代理
   - 高风险操作使用 ask 权限

3. **合理使用子代理调用**
   - 拆分复杂任务
   - 并行执行独立任务
   - 链式调用相关任务

4. **管理上下文和状态**
   - 使用 session_id 恢复会话
   - 通过 metadata 传递状态
   - 聚合子任务结果

5. **处理错误和恢复**
   - 捕获子代理错误
   - 提供恢复策略
   - 实现重试机制

#### ❌ Don't

1. **不要过度委托**
   - 简单任务直接执行
   - 避免不必要的子代理调用

2. **不要嵌套太深**
   - 避免超过 3 层嵌套
   - 考虑使用并行替代嵌套

3. **不要忽略错误**
   - 始终处理子代理错误
   - 提供有意义的错误消息

4. **不要破坏权限隔离**
   - 子代理不应超过父代理权限
   - 保持权限层级清晰

5. **不要滥用 steps 限制**
   - 合理设置最大步骤数
   - 避免过早终止代理

## 总结

OpenCode 的代理系统是一个强大而灵活的架构，它提供了：

1. **三种代理类型**：primary、subagent、all，满足不同使用场景
2. **完整的配置系统**：支持自定义提示词、模型、权限、参数
3. **强大的子代理机制**：支持任务委托、并行执行、上下文传递
4. **细粒度的权限控制**：每个代理有独立的权限规则
5. **灵活的提示词系统**：支持系统提示词和自定义提示词
6. **易于扩展**：用户可以轻松创建自定义代理

通过合理使用代理系统，可以：

- 提高任务专业化程度
- 增强安全性和权限隔离
- 支持复杂的工作流编排
- 优化性能和资源利用
