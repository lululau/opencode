## 整体架构

OpenCode 使用**客户端-服务器架构**，通过 HTTP API 和 **Server-Sent Events (SSE)** 实现流式通信。

### 架构层次

```
┌─────────────────┐
│   TUI 客户端   │
│  (SolidJS)     │
└────────┬────────┘
         │ HTTP/SSE
         ↓
┌─────────────────┐
│   HTTP 服务器  │
│   (Hono)      │
└────────┬────────┘
         │
         ↓
┌─────────────────┐
│ Session 层    │
│  (业务逻辑)   │
└────────┬────────┘
         │
         ↓
┌─────────────────┐
│ AI SDK        │
│ (Vercel AI)   │
└─────────────────┘
```

## 3. 服务器处理 Prompt 并流式响应

**核心处理逻辑**: `packages/opencode/src/session/prompt.ts`

### 3.1 入口函数

```typescript
// prompt.ts line 151-180
export const prompt = fn(PromptInput, async (input) => {
  const session = await Session.get(input.sessionID)

  // 1. 创建用户消息
  const message = await createUserMessage(input)
  await Session.touch(input.sessionID)

  // 2. 处理权限设置
  const permissions: PermissionNext.Ruleset = []
  for (const [tool, enabled] of Object.entries(input.tools ?? {})) {
    permissions.push({
      permission: tool,
      action: enabled ? "allow" : "deny",
      pattern: "*",
    })
  }
  if (permissions.length > 0) {
    session.permission = permissions
    await Session.update(session.id, (draft) => {
      draft.permission = permissions
    })
  }

  // 3. 如果 noReply=true，直接返回
  if (input.noReply === true) {
    return message
  }

  // 4. 否则启动处理循环
  return loop(input.sessionID)
})
```

### 3.2 核心处理循环

`loop()` 函数（line 258-637）是流式响应的核心：

```typescript
export const loop = fn(Identifier.schema("session"), async (sessionID) => {
  const abort = start(sessionID)
  if (!abort) {
    return new Promise<MessageV2.WithParts>((resolve, reject) => {
      const callbacks = state()[sessionID].callbacks
      callbacks.push({ resolve, reject })
    })
  }

  using _ = defer(() => cancel(sessionID))

  let step = 0
  const session = await Session.get(sessionID)

  while (true) {
    SessionStatus.set(sessionID, { type: "busy" })
    log.info("loop", { step, sessionID })

    if (abort.aborted) break

    // 获取消息历史
    let msgs = await MessageV2.filterCompacted(MessageV2.stream(sessionID))

    // 查找最后一条用户消息
    let lastUser: MessageV2.User | undefined
    for (let i = msgs.length - 1; i >= 0; i--) {
      if (msgs[i].info.role === "user") {
        lastUser = msgs[i].info as MessageV2.User
        break
      }
    }

    // 检查是否已完成
    if (!lastUser) throw new Error("No user message found")

    const lastAssistant = msgs.findLast((m) => m.info.role === "assistant")

    if (
      lastAssistant?.finish &&
      !["tool-calls", "unknown"].includes(lastAssistant.finish) &&
      lastUser.id < lastAssistant.id
    ) {
      log.info("exiting loop", { sessionID })
      break
    }

    // 处理逻辑
    const agent = await Agent.get(lastUser.agent)
    const model = await Provider.getModel(lastUser.model.providerID, lastUser.model.modelID)

    const processor = SessionProcessor.create({
      assistantMessage: (await Session.updateMessage({
        id: Identifier.ascending("message"),
        parentID: lastUser.id,
        role: "assistant",
        mode: agent.name,
        agent: agent.name,
        // ... 其他字段
      })) as MessageV2.Assistant,
      sessionID: sessionID,
      model,
      abort,
    })

    // 解析工具
    const tools = await resolveTools({
      agent,
      session,
      model,
      processor,
      bypassAgentCheck: false,
    })

    // 调用 AI 处理
    const result = await processor.process({
      user: lastUser,
      agent,
      abort,
      sessionID,
      system: [...(await SystemPrompt.environment()), ...(await SystemPrompt.custom())],
      messages: MessageV2.toModelMessages(msgs, model),
      tools,
      model,
    })

    if (result === "stop") break
    if (result === "compact") {
      await SessionCompaction.create({
        sessionID,
        agent: lastUser.agent,
        model: lastUser.model,
        auto: true,
      })
    }

    step++
  }

  // 返回最后的 assistant 消息
  for await (const item of MessageV2.stream(sessionID)) {
    if (item.info.role === "user") continue
    const queued = state()[sessionID]?.callbacks ?? []
    for (const q of queued) {
      q.resolve(item)
    }
    return item
  }
})
```

### 3.3 处理步骤

每次循环执行以下步骤：

1. **状态更新**: 设置 session 状态为 "busy"
2. **消息检索**: 从存储获取消息历史
3. **完成检查**: 检查是否已有完成的 assistant 响应
4. **工具解析**: 根据代理和模型解析可用工具
5. **AI 调用**: 通过 `SessionProcessor.process()` 与 LLM 交互
6. **结果处理**: 根据返回结果决定继续、停止或压缩

## 4. 流式响应的技术实现

服务器使用两种流式响应方式：

### 4.1 方式一：普通 JSON 流（用于 prompt 响应）

```typescript
// session.ts line 730-735
return stream(c, async (stream) => {
  const sessionID = c.req.valid("param").sessionID
  const body = c.req.valid("json")
  const msg = await SessionPrompt.prompt({ ...body, sessionID })
  stream.write(JSON.stringify(msg))
})
```

**特点**：

- 适用于单次完整响应的场景
- 使用 Hono 的 `stream()` 函数
- 响应完成后关闭连接

### 4.2 方式二：Server-Sent Events (SSE)

**SSE 端点**: `packages/opencode/src/server/server.ts`

```typescript
// server.ts line 444-499
.get(
  "/event",
  describeRoute({
    summary: "Subscribe to events",
    description: "Get events",
    operationId: "event.subscribe",
    responses: {
      200: {
        description: "Event stream",
        content: {
          "text/event-stream": {
            schema: resolver(BusEvent.payloads()),
          },
        },
      },
    },
  }),
  async (c) => {
    log.info("event connected")
    return streamSSE(c, async (stream) => {
      // 1. 发送连接事件
      stream.writeSSE({
        data: JSON.stringify({
          type: "server.connected",
          properties: {},
        }),
      })

      // 2. 订阅所有事件
      const unsub = Bus.subscribeAll(async (event) => {
        await stream.writeSSE({
          data: JSON.stringify(event),
        })
        if (event.type === Bus.InstanceDisposed.type) {
          stream.close()
        }
      })

      // 3. 心跳机制（每 30 秒）
      const heartbeat = setInterval(() => {
        stream.writeSSE({
          data: JSON.stringify({
            type: "server.heartbeat",
            properties: {},
          }),
        })
      }, 30000)

      // 4. 等待客户端断开
      await new Promise<void>((resolve) => {
        stream.onAbort(() => {
          clearInterval(heartbeat)
          unsub()
          resolve()
          log.info("event disconnected")
        })
      })
    })
  },
)
```

**SSE 特点**：

- **持久连接**: 保持长连接直到客户端断开
- **实时推送**: 服务器主动推送事件到客户端
- **心跳机制**: 每 30 秒发送心跳防止超时
- **事件类型**: 支持多种事件类型（消息、状态、错误等）

**SSE 格式**：

```
data: {"type":"server.connected","properties":{}}

data: {"type":"message.create","properties":{...}}

data: {"type":"server.heartbeat","properties":{}}
```

## 5. 客户端接收流式响应

### 5.1 SSE 客户端实现

**SDK SSE 客户端**: `packages/sdk/js/src/v2/gen/core/serverSentEvents.gen.ts`

```typescript
// serverSentEvents.gen.ts line 78-240
export const createSseClient = <TData = unknown>({
  url,
  onSseEvent,
  ...options
}: ServerSentEventsOptions): ServerSentEventsResult<TData> => {
  let lastEventId: string | undefined
  const sleep = sseSleepFn ?? ((ms: number) => new Promise((resolve) => setTimeout(resolve, ms)))

  const createStream = async function* () {
    let retryDelay: number = sseDefaultRetryDelay ?? 3000
    let attempt = 0
    const signal = options.signal ?? new AbortController().signal

    while (true) {
      if (signal.aborted) break
      attempt++

      // 1. 构建请求
      const headers = new Headers(options.headers as Record<string, string> | undefined)
      if (lastEventId !== undefined) {
        headers.set("Last-Event-ID", lastEventId)
      }

      try {
        const request = new Request(url, {
          redirect: "follow",
          ...options,
          body: options.serializedBody,
          headers,
          signal,
        })

        // 2. 发起 fetch 请求
        const _fetch = options.fetch ?? globalThis.fetch
        const response = await _fetch(request)

        if (!response.ok) throw new Error(`SSE failed: ${response.status} ${response.statusText}`)
        if (!response.body) throw new Error("No body in SSE response")

        // 3. 创建流读取器
        const reader = response.body.pipeThrough(new TextDecoderStream()).getReader()

        let buffer = ""

        const abortHandler = () => {
          try {
            reader.cancel()
          } catch {
            // noop
          }
        }
        signal.addEventListener("abort", abortHandler)

        try {
          // 4. 逐块读取
          while (true) {
            const { done, value } = await reader.read()
            if (done) break
            buffer += value

            // 5. 规范化行结尾
            buffer = buffer.replace(/\r\n/g, "\n").replace(/\r/g, "\n")

            // 6. 按 SSE 格式分割（\n\n）
            const chunks = buffer.split("\n\n")
            buffer = chunks.pop() ?? ""

            for (const chunk of chunks) {
              const lines = chunk.split("\n")
              const dataLines: Array<string> = []
              let eventName: string | undefined

              // 7. 解析 SSE 字段
              for (const line of lines) {
                if (line.startsWith("data:")) {
                  dataLines.push(line.replace(/^data:\s*/, ""))
                } else if (line.startsWith("event:")) {
                  eventName = line.replace(/^event:\s*/, "")
                } else if (line.startsWith("id:")) {
                  lastEventId = line.replace(/^id:\s*/, "")
                } else if (line.startsWith("retry:")) {
                  const parsed = Number.parseInt(line.replace(/^retry:\s*/, ""), 10)
                  if (!Number.isNaN(parsed)) {
                    retryDelay = parsed
                  }
                }
              }

              // 8. 解析 JSON 数据
              let data: unknown
              let parsedJson = false

              if (dataLines.length) {
                const rawData = dataLines.join("\n")
                try {
                  data = JSON.parse(rawData)
                  parsedJson = true
                } catch {
                  data = rawData
                }
              }

              // 9. 验证和转换
              if (parsedJson) {
                if (responseValidator) {
                  await responseValidator(data)
                }
                if (responseTransformer) {
                  data = await responseTransformer(data)
                }
              }

              // 10. 调用回调
              onSseEvent?.({
                data,
                event: eventName,
                id: lastEventId,
                retry: retryDelay,
              })

              if (dataLines.length) {
                yield data as any
              }
            }
          }
        } finally {
          signal.removeEventListener("abort", abortHandler)
          reader.releaseLock()
        }

        break
      } catch (error) {
        // 错误处理和重试
        onSseError?.(error)

        if (sseMaxRetryAttempts !== undefined && attempt >= sseMaxRetryAttempts) {
          break
        }

        // 指数退避重试
        const backoff = Math.min(retryDelay * 2 ** (attempt - 1), sseMaxRetryDelay ?? 30000)
        await sleep(backoff)
      }
    }
  }

  const stream = createStream()
  return { stream }
}
```

### 5.2 TUI 事件订阅

**TUI 接收事件**: `packages/opencode/src/cli/cmd/tui/context/sdk.tsx`

```typescript
// sdk.tsx line 57-85
onMount(async () => {
  const abort = new AbortController()
  const sdk = createOpencodeClient({
    baseUrl: props.url,
    signal: abort.signal,
    directory: props.directory,
    fetch: props.fetch,
  })

  const emitter = createGlobalEmitter<{
    [key in Event["type"]]: Extract<Event, { type: key }>
  }>()

  let queue: Event[] = []
  let timer: Timer | undefined
  let last = 0

  // 批量处理函数
  const flush = () => {
    if (queue.length === 0) return
    const events = queue
    queue = []
    timer = undefined
    last = Date.now()
    // 批量更新所有事件以减少渲染次数
    batch(() => {
      for (const event of events) {
        emitter.emit(event.type, event)
      }
    })
  }

  const handleEvent = (event: Event) => {
    queue.push(event)
    const elapsed = Date.now() - last

    if (timer) return
    // 如果刚刷新过（16ms 内），批量处理
    // 否则立即处理以避免延迟
    if (elapsed < 16) {
      timer = setTimeout(flush, 16)
      return
    }
    flush()
  }

  // 订阅 SSE 事件
  while (true) {
    if (abort.signal.aborted) break
    const events = await sdk.event.subscribe(
      {},
      {
        signal: abort.signal,
      },
    )

    for await (const event of events.stream) {
      handleEvent(event)
    }

    // 刷新剩余事件
    if (timer) clearTimeout(timer)
    if (queue.length > 0) {
      flush()
    }
  }

  onCleanup(() => {
    abort.abort()
    if (timer) clearTimeout(timer)
  })
})
```

## 8. 优化技术

### 8.1 批量更新

**目的**: 减少渲染次数，提升性能


**效果**：

- 多个高频事件合并为单次渲染
- 延迟不超过 16ms（60fps）

## 总结

OpenCode 的流式响应实现采用了以下关键技术：

1. **双重流式机制**:
   - 普通 JSON 流：用于简单 prompt 响应
   - SSE 持久连接：用于实时事件推送

2. **全链路异步**:
   - 客户端 → HTTP → 服务器 → AI SDK → LLM
   - 每层都支持流式处理

3. **性能优化**:
   - 批量更新减少渲染次数
   - 心跳机制防止超时
   - 指数退避实现可靠重连

4. **架构解耦**:
   - 事件总线解耦事件生产和消费
   - SDK 自动生成确保类型安全
   - 统一的流式接口（`stream()` / `streamSSE()`）

这种架构确保了用户能够实时看到 AI 响应的生成过程，同时保持了系统的可扩展性和可维护性。
