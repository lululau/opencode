## 概述

OpenCode 插件系统是一个轻量级但功能强大的扩展机制，允许开发者通过插件为 OpenCode 添加自定义工具、认证方法、钩子和事件处理程序。插件运行在共享的 Node.js/Bun 运行时中，直接访问 OpenCode API，无需沙箱隔离。

### 核心特性

- **共享运行时**: 所有插件在同一进程中运行，共享内存和资源
- **直接 API 访问**: 插件可以直接调用 OpenCode 的内部 API
- **灵活的钩子系统**: 支持多种生命周期钩子
- **动态发现**: 支持从 npm 包、本地文件和内置插件中发现
- **自动去重**: 智能处理重复插件，按优先级选择
- **无卸载机制**: 插件一旦加载即持久化，直到进程重启

## 插件接口与类型

### Plugin 类型

插件是一个异步函数，接收 `PluginInput` 并返回 `Hooks` 对象。

```typescript
// packages/plugin/src/index.ts
export type Plugin = (input: PluginInput) => Promise<Hooks>
```

### PluginInput

插件初始化时接收的上下文输入，包含所有必要的运行时信息。

```typescript
export type PluginInput = {
  client: ReturnType<typeof createOpencodeClient> // OpenCode SDK 客户端
  project: Project // 项目信息
  directory: string // 当前工作目录
  worktree: string // Git 工作树根目录
  serverUrl: URL // 服务器 URL
  $: BunShell // Shell 执行工具
}
```

**字段说明**:

| 字段        | 类型           | 描述                                              |
| ----------- | -------------- | ------------------------------------------------- |
| `client`    | OpenCodeClient | 用于调用 OpenCode API 的 SDK 客户端               |
| `project`   | Project        | 项目元数据（名称、ID、路径等）                    |
| `directory` | string         | 当前项目目录绝对路径                              |
| `worktree`  | string         | Git 工作树根目录（如果项目是 Git 仓库）           |
| `serverUrl` | URL            | OpenCode 服务器地址（默认 http://localhost:4096） |
| `$`         | BunShell       | 执行 shell 命令的工具                             |

### Hooks

插件可以实现的钩子集合，用于在不同时机介入 OpenCode 的执行流程。

```typescript
export interface Hooks {
  // 事件处理钩子
  event?: (input: { event: Event }) => Promise<void>

  // 配置修改钩子
  config?: (input: Config) => Promise<void>

  // 工具注册钩子
  tool?: {
    [key: string]: ToolDefinition
  }

  // 认证钩子
  auth?: AuthHook

  // 聊天消息处理钩子
  "chat.message"?: (
    input: {
      sessionID: string
      agent?: string
      model?: { providerID: string; modelID: string }
      messageID?: string
      variant?: string
    },
    output: { message: UserMessage; parts: Part[] },
  ) => Promise<void>

  // LLM 参数修改钩子
  "chat.params"?: (
    input: { sessionID: string; agent: string; model: Model; provider: ProviderContext; message: UserMessage },
    output: { temperature: number; topP: number; topK: number; options: Record<string, any> },
  ) => Promise<void>

  // HTTP 头修改钩子
  "chat.headers"?: (
    input: { sessionID: string; agent: string; model: Model; provider: ProviderContext; message: UserMessage },
    output: { headers: Record<string, string> },
  ) => Promise<void>

  // 权限询问钩子
  "permission.ask"?: (input: Permission, output: { status: "ask" | "deny" | "allow" }) => Promise<void>

  // 命令执行前钩子
  "command.execute.before"?: (
    input: { command: string; sessionID: string; arguments: string },
    output: { parts: Part[] },
  ) => Promise<void>

  // 工具执行前钩子
  "tool.execute.before"?: (
    input: { tool: string; sessionID: string; callID: string },
    output: { args: any },
  ) => Promise<void>

  // 工具执行后钩子
  "tool.execute.after"?: (
    input: { tool: string; sessionID: string; callID: string },
    output: {
      title: string
      output: string
      metadata: any
    },
  ) => Promise<void>

  // 实验性：消息转换钩子
  "experimental.chat.messages.transform"?: (
    input: {},
    output: {
      messages: {
        info: Message
        parts: Part[]
      }[]
    },
  ) => Promise<void>

  // 实验性：系统提示词转换钩子
  "experimental.chat.system.transform"?: (
    input: { sessionID: string },
    output: {
      system: string[]
    },
  ) => Promise<void>

  // 实验性：会话压缩钩子
  "experimental.session.compacting"?: (
    input: { sessionID: string },
    output: { context: string[]; prompt?: string },
  ) => Promise<void>

  // 实验性：文本补全钩子
  "experimental.text.complete"?: (
    input: { sessionID: string; messageID: string; partID: string },
    output: { text: string },
  ) => Promise<void>
}
```

## 插件生命周期

插件生命周期包含四个阶段：加载、初始化、触发和（隐式）卸载。

```
┌─────────────────────────────────────────────────────────────┐
│                  插件生命周期                            │
├─────────────────────────────────────────────────────────────┤
│                                                      │
│  1. 加载 (Load)                                       │
│     └─> 从配置、npm 包或内置插件列表中发现插件            │
│     └─> 调用 Plugin(input) 函数                          │
│     └─> 获取返回的 Hooks 对象                            │
│                                                      │
│  2. 初始化 (Initialize)                                  │
│     └─> 调用 plugin.config(config) 钩子                  │
│     └─> 订阅全局事件 Bus.subscribeAll()                  │
│     └─> 注册自定义工具 (tool 钩子)                        │
│                                                      │
│  3. 触发 (Trigger)                                     │
│     └─> 在适当的时机调用插件钩子                          │
│     └─> event: 事件发生时                               │
│     └─> tool.execute.before/after: 工具执行时             │
│     └─> chat.params/headers: LLM 调用时                 │
│     └─> permission.ask: 权限请求时                      │
│                                                      │
│  4. 卸载 (Unload) - 无显式机制                          │
│     └─> OpenCode 重启后卸载所有插件                      │
│     └─> 无热卸载 API                                    │
│     └─> Instance.dispose() 会清理资源                     │
│                                                      │
└─────────────────────────────────────────────────────────────┘
```

### 阶段详解

#### 1. 加载阶段

插件加载发生在 OpenCode 启动时的 `Plugin.state()` 初始化。

**代码位置**: `/packages/opencode/src/plugin/index.ts:23-96`

```typescript
const state = Instance.state(async () => {
  const input: PluginInput = {
    client: createOpencodeClient(...),
    project: Instance.project,
    worktree: Instance.worktree,
    directory: Instance.directory,
    serverUrl: Server.url(),
    $: Bun.$,
  }

  const hooks: Hooks[] = []

  // 加载内置插件
  for (const plugin of INTERNAL_PLUGINS) {
    const init = await plugin(input)
    hooks.push(init)
  }

  // 加载配置中的插件（npm 或本地文件）
  for (let pluginSpec of plugins) {
    if (!pluginSpec.startsWith("file://")) {
      // npm 包：安装并导入
      pluginSpec = await BunProc.install(pkg, version)
    }
    const mod = await import(pluginSpec)
    const init = await mod.default(input)
    hooks.push(init)
  }

  return { hooks, input }
})
```

#### 2. 初始化阶段

在 `Plugin.init()` 中调用，执行一次性设置。

**代码位置**: `/packages/opencode/src/plugin/index.ts:119-134`

```typescript
export async function init() {
  const hooks = await state().then((x) => x.hooks)
  const config = await Config.get()

  // 调用每个插件的 config 钩子
  for (const hook of hooks) {
    await hook.config?.(config)
  }

  // 订阅所有事件
  Bus.subscribeAll(async (input) => {
    const hooks = await state().then((x) => x.hooks)
    for (const hook of hooks) {
      hook["event"]?.({
        event: input,
      })
    }
  })
}
```

#### 3. 触发阶段

钩子在相应事件发生时被自动调用。

```typescript
// 示例：工具执行前触发
export async function trigger<Name extends keyof Hooks>(
  name: Name,
  input: Parameters<Required<Hooks>[Name]>[0],
  output: Parameters<Required<Hooks>[Name]>[1],
): Promise<ReturnType<Required<Hooks>[Name]>> {
  for (const hook of await state().then((x) => x.hooks)) {
    const fn = hook[name]
    if (!fn) continue
    await fn(input, output)
  }
  return output
}
```

#### 4. 无卸载机制

OpenCode **不支持**运行时插件卸载。原因：

- **共享运行时**: 插件和主进程共享内存，安全卸载困难
- **钩子引用**: 钩子函数被多个系统组件引用
- **状态清理**: 无法保证插件正确清理所有副作用

**解决方案**: 重启 OpenCode 以应用插件更改。

## 插件注册机制

### 发现方式

插件通过多种方式被发现和加载：

```
插件来源
│
├─ 1. 内置插件 (INTERNAL_PLUGINS)
│   └─ CodexAuthPlugin
│   └─ CopilotAuthPlugin
│
├─ 2. 配置文件
│   ├─ 全局: ~/.config/opencode/opencode.json
│   ├─ 项目: .opencode/opencode.json
│   └─ .opencode/plugin/*.ts, .js
│
├─ 3. npm 包
│   ├─ "package-name@version"
│   ├─ "@scope/package@version"
│   └─ 自动安装到 node_modules
│
└─ 4. 本地文件
    └─ "file:///absolute/path/to/plugin.js"
```

### 注册顺序

插件按以下顺序加载（低优先级 → 高优先级）：

```typescript
// packages/opencode/src/plugin/index.ts
const plugins = [
  ...(config.plugin ?? []), // 用户配置
  ...(builtin ?? []), // 内置插件（如果未禁用）
]
```

**详细优先级**:

1. **内置插件**（`INTERNAL_PLUGINS`）
   - CodexAuthPlugin
   - CopilotAuthPlugin
   - 始终首先加载

2. **配置文件中的插件**（`config.plugin`）
   - `BUILTIN` 列表中的默认插件
   - 用户在 `opencode.json` 中指定的插件

3. **本地插件目录**（`.opencode/plugin/`）
   - 自动发现 `.ts` 和 `.js` 文件
   - 转换为 `file://` URL

4. **插件去重**
   - 后加载的同名插件会覆盖先加载的

### 去重机制

插件使用 `getPluginName()` 和 `deduplicatePlugins()` 进行去重。

**代码位置**: `/packages/opencode/src/config/config.ts:381-421`

```typescript
export function getPluginName(plugin: string): string {
  if (plugin.startsWith("file://")) {
    return path.parse(new URL(plugin).pathname).name
  }
  const lastAt = plugin.lastIndexOf("@")
  if (lastAt > 0) {
    return plugin.substring(0, lastAt)
  }
  return plugin
}

export function deduplicatePlugins(plugins: string[]): string[] {
  const seenNames = new Set<string>()
  const uniqueSpecifiers: string[] = []

  for (const specifier of plugins.toReversed()) {
    const name = getPluginName(specifier)
    if (!seenNames.has(name)) {
      seenNames.add(name)
      uniqueSpecifiers.push(specifier)
    }
  }

  return uniqueSpecifiers.toReversed()
}
```

**去重规则**:

- **npm 包**: `package-name@1.0.0` → `package-name`
- **作用域包**: `@scope/package@1.0.0` → `@scope/package`
- **本地文件**: `file:///path/to/my-plugin.js` → `my-plugin`
- **优先级**: 后加载的同名插件胜出

### 内置插件列表

**代码位置**: `/packages/opencode/src/plugin/index.ts:18`


## 插件隔离方案

OpenCode 插件系统采用**共享运行时**模式，**不提供沙箱隔离**。

### 架构特点

```
┌─────────────────────────────────────────────────────┐
│           OpenCode 主进程                           │
│                                                    │
│  ┌────────────────────────────────────────────┐    │
│  │         插件运行时 (共享)                   │    │
│  │                                           │    │
│  │  ┌──────────┐  ┌──────────┐            │    │
│  │  │ Plugin A │  │ Plugin B │  ...       │    │
│  │  └────┬─────┘  └────┬─────┘            │    │
│  │       │              │                   │    │
│  │  ┌────▼──────────────▼────┐             │    │
│  │  │   OpenCode API        │             │    │
│  │  │   (client, storage)   │             │    │
│  │  └───────────────────────┘             │    │
│  └────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

### 直接 API 访问

插件可以直接访问：

```typescript
const Plugin = async (input: PluginInput) => {
  // 直接调用 SDK API
  const sessions = await input.client.session.list()

  // 直接执行 shell 命令
  const result = await input.$`ls -la`

  // 直接访问文件系统
  await Bun.file("./config.json").text()

  return {
    // 注册自定义工具
    tool: {
      myTool: {
        description: "My custom tool",
        parameters: z.object({...}),
        async execute(args, ctx) {
          // 直接访问数据库、网络等
        }
      }
    }
  }
}
```

### 安全考虑

由于无沙箱隔离，插件安全性依赖于：

1. **权限系统**: 通过 `permission.ask` 钩子可以拦截危险操作
2. **代码审查**: 用户应只信任可信来源的插件
3. **签名验证**（未来）: 计划添加插件签名机制

### 性能影响

共享运行时的优势：

- ✅ **零开销**: 无进程间通信
- ✅ **快速启动**: 无需启动独立进程
- ✅ **内存共享**: 可共享数据结构

劣势：

- ❌ **单一故障点**: 一个插件崩溃可能影响整个进程
- ❌ **资源竞争**: 插件间可能竞争 CPU/内存

## 插件钩子类型与执行流程

### 钩子执行顺序

完整的请求流程中的钩子调用顺序：

```
用户请求
  │
  ├─> [permission.ask] ── 权限检查
  │
  ├─> [command.execute.before] ── 命令执行前
  │
  ├─> [chat.message] ── 消息处理
  │
  ├─> [experimental.chat.system.transform] ── 系统提示词转换
  │
  ├─> [experimental.chat.messages.transform] ── 消息转换
  │
  ├─> [chat.params] ── LLM 参数设置
  │
  ├─> [chat.headers] ── HTTP 头设置
  │
  ├─> AI 响应
  │
  ├─> [tool.execute.before] ── 工具执行前
  │
  ├─> 工具执行
  │
  ├─> [tool.execute.after] ── 工具执行后
  │
  └─> [event] ── 事件发布
```

### 关键钩子详解

#### 1. config 钩子

在配置加载后调用，允许插件修改配置。

```typescript
const myPlugin: Plugin = async (input) => {
  return {
    async config(config) {
      // 添加自定义配置
      config.provider = {
        ...config.provider,
        myProvider: {
          options: { apiKey: "..." },
        },
      }
    },
  }
}
```

#### 2. event 钩子

订阅所有系统事件。

```typescript
return {
  async event({ event }) {
    if (event.type === "session.created") {
      console.log("New session:", event.properties.sessionID)
    }
  },
}
```

#### 3. tool 钩子

注册自定义工具。

```typescript
return {
  tool: {
    myTool: {
      description: "My custom tool",
      parameters: z.object({
        filePath: z.string().describe("File path"),
      }),
      async execute(args, ctx) {
        const content = await Bun.file(args.filePath).text()
        return {
          title: `Read ${args.filePath}`,
          output: content,
          metadata: {},
        }
      },
    },
  },
}
```

#### 4. auth 钩子

添加认证方法（OAuth 或 API Key）。

```typescript
return {
  auth: {
    provider: "my-provider",
    methods: [
      {
        type: "oauth",
        label: "Sign in with My Provider",
        async authorize(inputs) {
          // 实现 OAuth 流程
          return {
            method: "auto",
            url: "https://...",
            callback: async (code) => ({ ... })
          }
        }
      }
    ]
  }
}
```

#### 5. permission.ask 钩子

修改权限决策。

```typescript
return {
  async "permission.ask"(input, output) {
    if (input.permission === "bash" && input.patterns.some((p) => p.includes("/safe"))) {
      output.status = "allow" // 允许安全目录的 bash 命令
    }
  },
}
```

## 代码示例

### 基础插件示例

创建一个简单的日志插件，记录所有工具调用。

**文件**: `.opencode/plugin/logger.ts`

```typescript
import type { Plugin, Hooks, ToolDefinition } from "@opencode-ai/plugin"
import z from "zod"

const LoggerPlugin: Plugin = async (input) => {
  const logs: any[] = []

  return {
    event: async ({ event }) => {
      if (event.type === "tool.call") {
        logs.push({
          timestamp: new Date().toISOString(),
          tool: event.properties.tool,
          args: event.properties.args,
        })
      }
    },

    tool: {
      showLogs: {
        description: "Show all logged tool calls",
        parameters: z.object({}),
        async execute() {
          return {
            title: "Tool Call Logs",
            output: JSON.stringify(logs, null, 2),
            metadata: { count: logs.length },
          }
        },
      } satisfies ToolDefinition,
    },
  }
}

export default LoggerPlugin
```

### 工具插件示例

创建一个 Git 历史分析工具。

**文件**: `.opencode/plugin/git-analyzer.ts`

```typescript
import type { Plugin, Hooks, ToolDefinition } from "@opencode-ai/plugin"
import z from "zod"

const GitAnalyzerPlugin: Plugin = async (input) => {
  return {
    tool: {
      gitHistory: {
        description: "Analyze Git commit history",
        parameters: z.object({
          since: z.string().optional().describe("Git ref (e.g., 'main', 'HEAD~10')"),
          limit: z.number().optional().default(10).describe("Number of commits"),
        }),
        async execute(args, ctx) {
          const result =
            await input.$`git log ${args.since || ""} -n ${args.limit} --pretty=format:"%h|%s|%an|%ad" --date=iso`.text()

          const commits = result
            .trim()
            .split("\n")
            .map((line) => {
              const [hash, subject, author, date] = line.split("|")
              return { hash, subject, author, date }
            })

          return {
            title: `Git History (${commits.length} commits)`,
            output: JSON.stringify(commits, null, 2),
            metadata: { commitCount: commits.length },
          }
        },
      } satisfies ToolDefinition,
    },
  }
}

export default GitAnalyzerPlugin
```

## 最佳实践

### 1. 错误处理

始终使用 try-catch 包裹异步操作，避免插件崩溃影响整个系统。

```typescript
const SafePlugin: Plugin = async (input) => {
  return {
    async event({ event }) {
      try {
        // 插件逻辑
      } catch (error) {
        console.error("Plugin error:", error)
        // 不重新抛出，避免影响 OpenCode
      }
    },
  }
}
```

### 2. 工具命名

使用描述性、小写的工具名称。

```typescript
// 好的命名
git - status
file - search
database - query

// 避免的命名
gs
fs
db
```

### 3. 参数验证

使用 Zod schema 进行严格的参数验证。

```typescript
parameters: z.object({
  filePath: z
    .string()
    .min(1)
    .describe("Absolute file path")
    .refine((path) => path.startsWith("/"), "Must be absolute path"),
  line: z.number().int().positive().describe("Line number (1-indexed)"),
})
```

### 4. 权限检查

在工具内部再次检查权限（防御性编程）。

```typescript
async execute(args, ctx) {
  await ctx.ask({
    permission: "bash",
    patterns: [args.command],
    always: [],
    metadata: {}
  })

  // 执行命令
}
```

### 5. 资源清理

如果插件创建资源（如定时器、连接），考虑使用 `event` 钩子监听 `session.closed` 事件进行清理。

```typescript
event: async ({ event }) => {
  if (event.type === "session.closed") {
    // 清理会话相关资源
  }
}
```

在 `description` 中提供清晰的使用说明。

```typescript
description: `Execute a shell command.

Important rules:
- Use quotes around arguments with spaces
- Prefer absolute paths
- Return only the essential output (limit to 2000 lines)

  command: ls -la /home/user`
```
