## 概述

本指南帮助您安全地将 OpenCode 从一个版本升级到另一个版本。OpenCode 提供了多种升级方式，并包含自动化的数据迁移机制，确保您的配置和会话数据在升级过程中得到妥善处理。

### 升级前注意事项

- ✅ 备份重要数据（配置文件、项目会话历史）
- ✅ 查看目标版本的破坏性变更
- ✅ 在测试环境中验证升级流程
- ✅ 记录当前的配置和环境设置

### 迁移系统

OpenCode 内置了自动化的数据迁移系统，位于 `packages/opencode/src/storage/storage.ts` 中的 `MIGRATIONS` 数组。当您升级到新版本时，系统会：

1. 检测当前数据版本（通过 `storage/migration` 文件）
2. 按顺序执行未运行的迁移脚本
3. 更新迁移版本号
4. 记录迁移日志

## 版本升级方式

OpenCode 支持多种升级方式，您可以根据自己的安装方式选择合适的方法。

### 方法 1：使用 CLI 命令（推荐）

```bash
# 升级到最新版本
opencode upgrade

# 升级到特定版本
opencode upgrade 1.1.31
opencode upgrade v1.1.31

# 指定升级方法
opencode upgrade --method npm
opencode upgrade --method brew
opencode upgrade --method curl
```

### 方法 2：使用包管理器

#### npm/pnpm/yarn

```bash
npm install -g opencode-ai@latest
# 或特定版本
npm install -g opencode-ai@1.1.31
```

#### Bun

```bash
bun install -g opencode-ai@latest
```

#### Homebrew

```bash
# 官方 brew formula（更新频率较低）
brew upgrade opencode

# anomalyco/tap（推荐，总是最新）
brew upgrade anomalyco/tap/opencode
```

#### Scoop（Windows）

```bash
scoop update opencode
```

#### Chocolatey（Windows）

```bash
choco upgrade opencode
```

### 方法 3：使用安装脚本

```bash
# 升级到最新版本
curl -fsSL https://opencode.ai/install | bash

# 升级到特定版本
VERSION=1.1.31 curl -fsSL https://opencode.ai/install | bash
```

### 方法 4：下载预编译二进制文件

从 [GitHub Releases](https://github.com/anomalyco/opencode/releases) 下载适合您平台的二进制文件，替换现有的可执行文件。

## 历史破坏性变更

以下列出 OpenCode 重要的破坏性变更，按时间倒序排列。

### v1.1.31 及之后

#### 权限系统重构

- **变更日期**: 2024年
- **影响范围**: 所有使用自定义权限配置的用户
- **变更内容**: 权限系统从旧 API 迁移到新的 `PermissionNext` API
- **迁移方式**: 自动迁移
- **详情**:

旧权限格式：

```json
{
  "permission": {
    "bash": true,
    "edit": false
  }
}
```

新权限格式：

```json
{
  "permission": {
    "bash": "allow",
    "edit": "deny"
  }
}
```

#### 项目表迁移

- **变更日期**: 2024年
- **影响范围**: 所有项目配置
- **变更内容**: 项目表从 JSON 迁移到结构化列以提高查询性能
- **迁移方式**: 自动迁移
- **影响**: 迁移后项目查询速度显著提升

### v1.1.30

#### OpenTUI 升级到 v0.1.74

- **影响范围**: TUI 用户
- **变更**: 修复了 tmux kitty 键盘回归问题
- **兼容性**: 需要重新编译 TUI 组件

### v1.1.29

#### OpenTUI 升级到 v0.1.73

- **影响范围**: TUI 用户，CJK（中日韩）语言用户
- **变更**: 修复 CJK 单词换行和泰语文本渲染问题
- **兼容性**: 非-tmux 环境

### v1.1.28

#### Bun 版本升级

- **影响范围**: 所有用户
- **变更**: Bun 运行时从 1.3.5 升级到 1.3.6
- **影响**: 修复了多个 Bun 运行时 bug

### v1.1.27 及之前

#### 存储结构调整

- **影响范围**: 所有用户
- **变更**: 项目和会话存储结构重构
- **迁移方式**: 自动迁移（MIGRATIONS 数组）
- **详情**:
  - 项目存储从 `project/<name>` 迁移到 `project/<git-id>.json`
  - 会话数据分离存储到独立目录
  - 消息和附件分别存储

## 配置迁移

### 配置文件位置

OpenCode 配置存储在以下位置（按优先级）：

```
~/.local/share/opencode/    # Linux
~/Library/Application Support/opencode/  # macOS
%APPDATA%/opencode/         # Windows
```

### 配置迁移步骤

#### 1. 备份现有配置

```bash
# 创建备份目录
mkdir -p ~/opencode-backup/$(date +%Y%m%d)

# 备份配置文件
cp -r ~/.local/share/opencode ~/opencode-backup/$(date +%Y%m%d)/

# 或 macOS
cp -r ~/Library/Application\ Support/opencode ~/opencode-backup/$(date +%Y%m%d)/
```

#### 2. 升级后验证配置

```bash
# 检查配置文件
opencode config list

# 验证权限配置
opencode config get permission

# 验证 AI 提供商配置
opencode provider list
```

#### 3. 配置格式更新

OpenCode 会自动迁移旧配置格式，但某些自定义配置可能需要手动调整：

**旧版代理配置**:

```json
{
  "agent": {
    "my-agent": {
      "model": "claude-sonnet-4",
      "permission": true
    }
  }
}
```

**新版代理配置**:

```json
{
  "agent": {
    "my-agent": {
      "mode": "primary",
      "model": {
        "modelID": "claude-sonnet-4-20250514",
        "providerID": "anthropic"
      },
      "permission": {
        "*": "allow"
      }
    }
  }
}
```

### 环境变量迁移

如果您使用环境变量配置 OpenCode，检查以下变更：

| 环境变量                   | 状态 | 说明                        |
| -------------------------- | ---- | --------------------------- |
| `OPENCODE_API_KEY`         | 保持 | API 密钥配置                |
| `OPENCODE_MODEL`           | 保持 | 默认模型配置                |
| `OPENCODE_INSTALL_DIR`     | 保持 | 安装目录配置                |
| `OPENCODE_SERVER_PASSWORD` | 新增 | 服务器密码（认证）          |
| `OPENCODE_SERVER_USERNAME` | 新增 | 服务器用户名（认证）        |
| `OPENCODE_CHANNEL`         | 新增 | 发布频道（latest/beta/dev） |

## 数据迁移

### 会话数据迁移

OpenCode 会自动迁移会话数据，包括：

#### 迁移内容

- ✅ 会话元数据（标题、创建时间、父会话 ID）
- ✅ 消息历史
- ✅ 附件和文件部分
- ✅ 项目关联
- ✅ 代码变更摘要

#### 迁移流程

1. **检测旧数据**: 系统扫描 `storage/session/` 目录
2. **解析旧格式**: 读取 JSON 格式的会话文件
3. **转换为新格式**: 将数据写入新的存储结构
4. **验证完整性**: 检查所有消息和附件是否迁移成功
5. **更新版本号**: 写入新的迁移版本

#### 迁移日志

迁移过程中的日志位置：

```
~/.local/share/opencode/logs/
~/Library/Application Support/opencode/logs/
```

查看迁移日志：

```bash
tail -f ~/.local/share/opencode/logs/opencode.log | grep migration
```

### 项目数据迁移

#### Git 工作树迁移

旧版本使用项目名称标识项目，新版本使用 Git 仓库的根 commit ID：

```typescript
// 旧格式
{
  "id": "my-project",
  "worktree": "/path/to/project"
}

// 新格式
{
  "id": "a1b2c3d4e5f6...",  // Git root commit hash
  "vcs": "git",
  "worktree": "/path/to/project",
  "time": {
    "created": 1234567890,
    "initialized": 1234567890
  }
}
```

迁移过程：

1. 扫描所有项目目录
2. 提取 Git 根 commit ID
3. 重新生成项目 JSON 文件
4. 迁移关联的会话数据

#### 权限规则迁移

权限规则自动转换为新的 `PermissionNext` 格式：

| 旧格式  | 新格式    | 说明         |
| ------- | --------- | ------------ |
| `true`  | `"allow"` | 允许操作     |
| `false` | `"deny"`  | 拒绝操作     |
| `"ask"` | `"ask"`   | 请求用户确认 |

### MCP 服务器配置迁移

如果您配置了 MCP 服务器，可能需要更新连接方式：

**旧配置方式**（某些版本）:

```bash
opencode mcp add my-server node my-server.js
```

**新配置方式**:

```bash
opencode mcp add my-server --command node --args my-server.js
```

## 回滚策略

### 回滚方案 1：使用包管理器回滚

#### npm/pnpm/yarn

```bash
# 查看已安装版本
npm list -g opencode-ai

# 回滚到指定版本
npm install -g opencode-ai@1.1.30

# 或查看可用版本
npm view opencode-ai versions --json
```

#### Bun

```bash
# 回滚到特定版本
bun install -g opencode-ai@1.1.30
```

#### Homebrew

```bash
# 查看已安装的版本
brew list --versions opencode

# 安装特定版本（需要查找历史版本）
# Homebrew 不直接支持版本回滚，可以手动安装
brew install opencode@1.1.30

# 或使用 anomalyco/tap
brew install anomalyco/tap/opencode@1.1.30
```

### 回滚方案 2：从备份恢复

#### 恢复配置文件

```bash
# 停止 OpenCode
pkill opencode

# 从备份恢复配置
cp -r ~/opencode-backup/20240122/opencode/* ~/.local/share/opencode/

# 重启 OpenCode
opencode
```

#### 恢复会话数据

```bash
# 恢复特定会话
cp ~/opencode-backup/20240122/opencode/session/*/* \
   ~/.local/share/opencode/session/

# 恢复消息数据
cp -r ~/opencode-backup/20240122/opencode/message/* \
   ~/.local/share/opencode/message/
```

### 回滚方案 3：重置迁移状态

如果迁移失败导致数据损坏，可以重置迁移状态：

```bash
# 停止 OpenCode
pkill opencode

# 重置迁移版本号
echo 0 > ~/.local/share/opencode/storage/migration

# 恢复备份数据
cp -r ~/opencode-backup/20240122/opencode/* ~/.local/share/opencode/

# 重启（将重新运行所有迁移）
opencode
```

⚠️ **警告**: 重置迁移状态会重新运行所有迁移脚本，可能导致数据重复或冲突。仅在确保数据备份的情况下使用。

## 最佳实践

### 1. 定期备份

建议设置自动备份脚本：

```bash
#!/bin/bash
# ~/bin/opencode-backup.sh

BACKUP_DIR="$HOME/opencode-backup/$(date +%Y%m%d)"
OPENCODE_DIR="$HOME/.local/share/opencode"

mkdir -p "$BACKUP_DIR"
cp -r "$OPENCODE_DIR" "$BACKUP_DIR/"

# 保留最近 7 天的备份
find "$HOME/opencode-backup" -type d -mtime +7 -exec rm -rf {} \;

echo "Backup completed: $BACKUP_DIR"
```

添加到 crontab：

```bash
# 每天凌晨 2 点备份
0 2 * * * /bin/bash ~/bin/opencode-backup.sh >> ~/opencode-backup.log 2>&1
```

### 9. 自动化升级

对于企业环境，可以自动化升级流程：

```bash
#!/bin/bash
# auto-upgrade.sh

CURRENT=$(opencode --version | grep -oP '\d+\.\d+\.\d+')
LATEST=$(curl -s https://api.github.com/repos/anomalyco/opencode/releases/latest | grep -oP '"tag_name": "\K[^"]*')

if [ "$CURRENT" != "$LATEST" ]; then
  echo "New version available: $LATEST"
  # 备份
  ~/bin/opencode-backup.sh
  # 升级
  opencode upgrade
  # 验证
  opencode --version
else
  echo "Already up to date: $CURRENT"
fi
```

## 常见问题

### Q1: 升级后配置丢失怎么办？

**A**: OpenCode 会自动迁移配置，但如果配置丢失：

1. 检查备份目录
2. 从备份恢复配置文件
3. 使用 `opencode config list` 查看当前配置

### Q2: 会话数据损坏如何恢复？

**A**:

1. 停止 OpenCode
2. 从备份恢复 `~/.local/share/opencode/`
3. 重置迁移版本：`echo 0 > ~/.local/share/opencode/storage/migration`
4. 重启 OpenCode（会重新运行迁移）

### Q3: 升级失败如何回滚？

**A**: 参见[回滚策略](#回滚策略)部分，选择合适的回滚方案：

- 使用包管理器回滚到旧版本
- 从备份恢复数据
- 重置迁移状态

### Q4: 迁移过程中出现错误怎么办？

**A**:

1. 查看迁移日志：`tail -f ~/.local/share/opencode/logs/opencode.log`
2. 检查错误信息和堆栈跟踪
3. 确认磁盘空间充足
4. 如果权限错误，检查文件系统权限
5. 在社区寻求帮助

### Q5: 如何跳过某些迁移？

**A**: 不建议跳过迁移，但如果需要：

1. 修改 `~/.local/share/opencode/storage/migration` 文件
2. 设置为目标迁移索引（慎用）
3. 可能导致数据不一致

### Q6: 升级后某些工具无法使用？

**A**:

1. 检查工具配置是否正确迁移
2. 验证 AI 提供商连接
3. 查看 `opencode --print-logs` 输出
4. 如果 MCP 工具，检查 MCP 服务器状态

### Q7: 升级后性能下降？

**A**:

1. 检查系统资源使用情况
2. 清理旧数据：`opencode session prune`
3. 调整 AI 模型参数（temperature, max tokens）
4. 更新系统依赖（Bun, Node.js）

### Q8: 如何验证升级成功？

**A**:

1. 检查版本：`opencode --version`
2. 运行测试：`opencode config list`
3. 验证功能：尝试基本操作
4. 查看日志：确保无错误
5. 对比配置：确认迁移正确
