## 概述

OpenCode 的权限系统是一个细粒度的访问控制机制，用于管理 AI 代理可以执行的操作。系统设计遵循最小权限原则，确保代理只能执行明确允许的操作，同时为用户提供灵活的控制选项。

### 主要特性

- **细粒度控制**：可以针对每个工具、每个文件路径设置权限
- **三种动作类型**：`allow`（允许）、`deny`（拒绝）、`ask`（询问用户）
- **模式匹配**：支持通配符模式进行灵活的路径匹配
- **自动记忆**：用户可以一次性授权，后续相同操作自动允许
- **层级配置**：支持全局、项目、代理三层配置覆盖
- **实时通知**：通过事件总线向客户端发送权限请求和响应

## 核心概念

### Action（动作）

权限动作定义了对特定操作的处理方式：

| 动作    | 描述 | 行为                           |
| ------- | ---- | ------------------------------ |
| `allow` | 允许 | 操作立即执行，无需用户干预     |
| `deny`  | 拒绝 | 操作被阻止，抛出异常终止执行   |
| `ask`   | 询问 | 暂停执行，等待用户确认后再决定 |

### Pattern（模式）

模式用于匹配文件路径、命令或其他标识符：

```typescript
// 通配符支持
"*" // 匹配所有
"*.ts" // 匹配所有 TypeScript 文件
"src/**" // 匹配 src 目录及子目录
"~/.config/*" // 匹配用户配置目录

// 字面量匹配
"package.json" // 仅匹配 package.json
```

### Ruleset（规则集）

规则集是一组权限规则的集合，按优先级顺序评估：

```typescript
type Ruleset = Rule[]

type Rule = {
  permission: string // 工具或操作名称
  pattern: string // 匹配模式
  action: "allow" | "deny" | "ask"
}
```

## 权限模型

### 层级结构

OpenCode 的权限系统采用三层配置模型，从低到高优先级：

```
1. 默认权限（Defaults）
   └─> 2. 用户全局权限（User Global）
       └─> 3. 代理权限（Agent Permissions）
           └─> 4. 运行时批准（Runtime Approved）
```

### 配置来源

#### 1. 默认权限

为每个代理预定义的基础权限规则，确保基本安全性：

```typescript
const defaults = PermissionNext.fromConfig({
  "*": "allow", // 默认允许所有操作
  doom_loop: "ask", // 检测无限循环需要确认
  external_directory: {
    "*": "ask", // 访问外部目录需要确认
    [TRUNCATE.DIR]: "allow", // 数据目录始终允许
    [TRUNCATE.GLOB]: "allow", // 数据目录通配符允许
  },
  question: "deny", // 禁止内部问题机制
  plan_enter: "deny", // 禁止内部计划进入
  plan_exit: "deny", // 禁止内部计划退出
  read: {
    "*": "allow", // 默认允许读取
    "*.env": "ask", // .env 文件需要确认
    "*.env.*": "ask", // .env 变体文件需要确认
    "*.env.example": "allow", // .env 示例文件允许
  },
})
```

#### 2. 用户全局权限

在 `~/.opencode/config.json` 中定义，应用于所有项目：

```json
{
  "permission": {
    "bash": "ask", // 所有 bash 命令需要确认
    "edit": {
      "*": "ask", // 编辑文件需要确认
      "*.md": "allow" // 但 Markdown 文件允许直接编辑
    },
    "read": {
      "*/node_modules/**": "deny" // 拒绝读取 node_modules
    }
  }
}
```

#### 3. 项目权限

在项目的 `.opencode/config.json` 或 `opencode.json` 中定义，仅应用于当前项目：

```json
{
  "permission": {
    "bash": "allow", // 项目级别允许所有 bash 命令
    "external_directory": {
      "./scripts/**": "allow" // 允许访问 scripts 目录
    }
  }
}
```

#### 4. 运行时批准

用户在会话中批准的权限，可以自动保存并重用：

```typescript
// 用户选择 "Always Allow"
s.approved.push({
  permission: "read",
  pattern: "/path/to/file",
  action: "allow",
})
```

### 权限合并

使用 `PermissionNext.merge()` 合并多个规则集：

```typescript
const merged = PermissionNext.merge(
  defaults, // 第一层
  userGlobal, // 第二层
  projectConfig, // 第三层
  agentOverride, // 第四层（最高优先级）
)
```

**合并原则**：

- 后定义的规则覆盖先定义的规则
- 同一匹配条件，后添加的规则生效
- 无匹配时，默认为 `ask`（询问）

## 规则定义

### 简单规则

对工具的所有操作应用相同动作：

```json
{
  "permission": {
    "bash": "allow", // 允许所有 bash 命令
    "write": "ask", // 询问所有写入操作
    "codesearch": "deny" // 拒绝所有代码搜索
  }
}
```

### 模式规则

对特定路径应用不同动作：

```json
{
  "permission": {
    "read": {
      "*": "allow", // 默认允许读取
      "*.env": "ask", // 但 .env 文件需要确认
      "**/secret/**": "deny" // secret 目录拒绝访问
    },
    "edit": {
      "*": "deny", // 默认拒绝编辑
      "*.md": "allow", // 但 Markdown 文件允许编辑
      "src/**": "ask" // src 目录需要确认
    }
  }
}
```

### 通配符语法

| 模式          | 说明                     | 匹配示例                                    |
| ------------- | ------------------------ | ------------------------------------------- |
| `*`           | 任意字符（非斜杠）       | `foo`, `bar`, `test.txt`                    |
| `**`          | 任意字符（包括斜杠）     | `foo/bar`, `src/components/Button.tsx`      |
| `*.ts`        | .ts 扩展名               | `index.ts`, `utils.ts`                      |
| `src/**`      | src 下所有               | `src/index.ts`, `src/components/Button.tsx` |
| `~/.config/*` | 用户配置目录             | `~/.config/opencode`, `~/.config/nvim`      |
| `* ?`         | 以空格和问号结尾（可选） | `ls`, `ls -la`, `ls -R`                     |

### 特殊权限

#### Doom Loop（无限循环检测）

```json
{
  "permission": {
    "doom_loop": "ask"
  }
}
```

- **目的**：检测代理重复调用同一工具并产生无限循环
- **触发**：当检测到相同工具调用超过阈值时
- **行为**：暂停并询问用户是否继续

#### External Directory（外部目录）

```json
{
  "permission": {
    "external_directory": {
      "*": "ask", // 默认询问外部目录访问
      "~/Downloads": "allow", // 但允许访问 Downloads
      "/usr": "deny" // 明确拒绝系统目录
    }
  }
}
```

- **目的**：控制对项目目录之外文件的访问
- **范围**：包括 shell 命令的工作目录、文件读写路径
- **例外**：`TRUNCATE.DIR`（数据目录）始终允许

#### LSP Permissions

```json
{
  "permission": {
    "lsp": {
      "*": "allow", // 默认允许所有 LSP 操作
      "**/node_modules/**": "deny" // 但拒绝 LSP 查询 node_modules
    }
  }
}
```

## 权限评估

### 评估流程

```
用户调用工具
     │
     ▼
工具调用 ctx.ask()
     │
     ▼
PermissionNext.ask()
     │
     ├─> 遍历所有 patterns
     │       │
     │       ▼
     │   evaluate(permission, pattern, ruleset)
     │       │
     │       ├─> 查找匹配的规则
     │       │   (按优先级，从后往前)
     │       │
     │       ├─> action = "deny" ?
     │       │   └─> 抛出 DeniedError
     │       │
     │       ├─> action = "ask" ?
     │       │   └─> 发布 Event.Asked
     │       │       等待用户回复
     │       │
     │       └─> action = "allow" ?
     │           └─> 继续执行
     │
     ▼
继续下一个 pattern 或完成
```

### 模式匹配算法

使用 `Wildcard.match()` 函数进行通配符匹配：

```typescript
export function match(str: string, pattern: string): boolean {
  let escaped = pattern
    .replace(/[.+^${}()|[\]\\]/g, "\\$&") // 转义特殊字符
    .replace(/\*/g, ".*") // * → .*
    .replace(/\?/g, ".") // ? → .

  // 特殊处理：" *"（空格+通配符）使尾部可选
  if (escaped.endsWith(" .*")) {
    escaped = escaped.slice(0, -3) + "( .*)?"
  }

  return new RegExp("^" + escaped + "$", "s").test(str)
}
```

### 规则优先级

规则在评估时遵循以下优先级：

1. **最新规则优先**：在 Ruleset 数组中，后添加的规则覆盖先添加的
2. **更具体优先**：更具体的模式优先于更通用的模式

   ```typescript
   ;["*.ts", "*"][("src/**", "*/**")] // *.ts 优先 // src/** 优先
   ```

3. **显式配置优先**：用户配置优先于默认配置
4. **代理覆盖优先**：代理特定权限优先于全局权限

### 评估示例

```typescript
const ruleset = [
  { permission: "read", pattern: "*", action: "allow" },
  { permission: "read", pattern: "*.env", action: "ask" },
  { permission: "read", pattern: "**/secret/**", action: "deny" },
]

evaluate("read", "package.json", ruleset)
// → { action: "allow" }  // 匹配 "*"

evaluate("read", ".env", ruleset)
// → { action: "ask" }    // 匹配 "*.env"（更具体）

evaluate("read", "src/secret/config.ts", ruleset)
// → { action: "deny" }   // 匹配 "**/secret/**"（最具体）
```

## 用户交互

### 权限请求流程

```
1. 工具调用 ctx.ask()
   ↓
2. 系统检查权限规则
   ↓ (如果需要确认)
3. 发布 Event.Asked 事件
   ↓
4. 客户端收到通知
   ↓
5. 显示权限请求对话框
   ↓
6. 用户选择：
   - Once（仅此一次）
   - Always（总是允许）
   - Reject（拒绝）
   ↓
7. 调用 PermissionNext.reply()
   ↓
8. 发布 Event.Replied 事件
   ↓
9. 解析等待的 Promise
   ↓ (如果允许)
10. 工具继续执行
   ↓ (如果拒绝)
11. 抛出异常，终止执行
```

### 请求事件结构

```typescript
interface PermissionRequest {
  id: string // 唯一请求 ID
  sessionID: string // 会话 ID
  permission: string // 工具/操作名称
  patterns: string[] // 需要匹配的模式
  always: string[] // 如果用户选择 "Always"，
  这些模式将被自动批准
  metadata: Record<string, any> // 额外的上下文信息
  tool?: {
    // 工具调用信息（可选）
    messageID: string
    callID: string
  }
}
```

### 回复选项

| 选项     | 描述             | 后续行为                                   |
| -------- | ---------------- | ------------------------------------------ |
| `once`   | 仅此一次允许     | 工具执行，下次相同操作仍需确认             |
| `always` | 总是允许这些模式 | 模式添加到 approved 列表，自动批准后续请求 |
| `reject` | 拒绝             | 抛出异常，终止工具执行                     |

### 批量自动批准

当用户选择 "Always" 时，系统自动批准该会话中的其他等待请求：

```typescript
if (reply === "always") {
  // 1. 添加到已批准列表
  for (const pattern of existing.info.always) {
    s.approved.push({
      permission: existing.info.permission,
      pattern,
      action: "allow"
    })
  }

  // 2. 自动批准该会话的其他等待请求
  for (const [id, pending] of Object.entries(s.pending)) {
    if (pending.info.sessionID !== sessionID) continue
    const ok = pending.info.patterns.every(
      (pattern) => evaluate(...).action === "allow"
    )
    if (ok) {
      delete s.pending[id]
      Bus.publish(Event.Replied, {
        sessionID: pending.info.sessionID,
        requestID: pending.info.id,
        reply: "always"
      })
      pending.resolve()
    }
  }
}
```

### 错误类型

#### RejectedError

用户简单拒绝，无附加信息：

```typescript
throw new RejectedError()
// 消息："The user rejected permission to use this specific tool call."
```

- **行为**：立即终止执行
- **用途**：用户明确不希望执行该操作

#### CorrectedError

用户拒绝并提供修正建议：

```typescript
throw new CorrectedError("请使用 git add 而不是 git commit")
// 消息："The user rejected permission to use this specific tool call with following feedback: 请使用 git add 而不是 git commit"
```

- **行为**：终止执行，但将用户反馈传递给 AI
- **用途**：用户希望纠正 AI 的理解

#### DeniedError

权限规则自动拒绝（配置明确禁止）：

```typescript
throw new DeniedError(ruleset)
// 消息："The user has specified a rule which prevents you from using this specific tool call. Here are some of the relevant rules [...]"
```

- **行为**：立即终止执行
- **用途**：配置已禁止此操作，无需询问用户

## 配置系统

### 配置格式

权限配置支持多种格式：

#### 简单字符串格式

```json
{
  "permission": {
    "bash": "allow",
    "read": "ask",
    "write": "deny"
  }

```

#### 对象格式（带模式）

```json
{
  "permission": {

    },

      "*": "allow",
      "*.env": "ask"
    }
  }
}
```

#### 混合格式

```json
{
  "permission": {

      // 对象格式
      "*": "allow",
      "*.env": "ask"
    }
  }

```

### 配置解析

使用 Zod schema 验证和转换配置：

```typescript
export const Permission = z.preprocess(
  // 1. 预处理：保留原始键顺序
  (val) => {
    if (typeof val === "object" && val !== null) {
      return { __originalKeys: Object.keys(val), ...val }
    }
    return val
  },
  // 2. Schema 定义
  z
    .object({
      read: PermissionRule.optional(),
      edit: PermissionRule.optional(),
      bash: PermissionRule.optional(),
      // ... 其他工具
    })
    // 3. 转换：恢复原始键顺序
    .transform((x) => {
      const result = {}
      for (const key of x.__originalKeys) {
        if (key in x) result[key] = x[key]
      }
      return result
    }),
)
```

### 配置转换

将配置转换为规则集：

```typescript
export function fromConfig(permission: Config.Permission): Ruleset {
  const ruleset: Ruleset = []

  for (const [key, value] of Object.entries(permission)) {
    if (typeof value === "string") {
      // 简单格式：转换为通配符规则
      ruleset.push({
        permission: key,
        action: value,
        pattern: "*",
      })
      continue
    }

    // 对象格式：每个模式一个规则
    ruleset.push(
      ...Object.entries(value).map(([pattern, action]) => ({
        permission: key,
        pattern: expand(pattern), // 展开 ~/ 和 $HOME
        action,
      })),
    )
  }

  return ruleset
}
```

### 路径展开

支持常见的路径缩写：

```typescript
function expand(pattern: string): string {
  if (pattern.startsWith("~/")) return os.homedir() + pattern.slice(1)
  if (pattern === "~") return os.homedir()
  if (pattern.startsWith("$HOME/")) return os.homedir() + pattern.slice(5)
  if (pattern.startsWith("$HOME")) return os.homedir() + pattern.slice(5)
  return pattern
}
```

示例：

- `~/.config` → `/home/user/.config`
- `$HOME/Documents` → `/home/user/Documents`

## 工具集成

### 工具接口

权限系统通过工具上下文暴露：

```typescript
export type Context = {
  sessionID: string
  messageID: string
  agent: string
  abort: AbortSignal
  callID?: string
  extra?: { [key: string]: any }
  metadata(input: { title?: string; metadata?: any }): void

  // 权限请求方法
  ask(input: Omit<PermissionRequest, "id" | "sessionID" | "tool">): Promise<void>
}
```

### 权限请求模式

#### 单一模式

```typescript
await ctx.ask({
  permission: "read",
  patterns: ["/path/to/file.ts"],
  always: ["*"],
  metadata: {},
})
```

#### 多模式

```typescript
await ctx.ask({
  permission: "external_directory",
  patterns: ["/usr/local", "/opt/tools"],
  always: ["/usr/local/*", "/opt/tools/*"],
  metadata: {},
})
```

#### Bash 工具集成示例

```typescript
async execute(params, ctx) {
  // 1. 解析命令，提取路径和模式
  const tree = await parser().then((p) => p.parse(params.command))
  const directories = extractDirectories(tree)
  const commands = extractCommands(tree)

  // 2. 请求外部目录权限
  if (directories.size > 0) {
    await ctx.ask({
      permission: "external_directory",
      patterns: Array.from(directories),
      always: Array.from(directories).map((x) => path.dirname(x) + "*"),
      metadata: {},
    })
  }

  // 3. 请求 bash 命令权限
  if (commands.size > 0) {
    await ctx.ask({
      permission: "bash",
      patterns: Array.from(commands),
      always: Array.from(commands).map((x) => prefix(x) + "*"),
      metadata: {},
    })
  }

  // 4. 执行命令
  return await executeCommand(params)
}
```

#### Read 工具集成示例

```typescript
async execute(params, ctx) {
  // 1. 构建文件路径
  const filepath = resolvePath(params.filePath)

  // 2. 请求读取权限
  await ctx.ask({
    permission: "read",
    patterns: [filepath],
    always: ["*"],  // 如果允许一次，则允许所有读取
    metadata: {},
  })

  // 3. 执行读取
  const content = await Bun.file(filepath).text()

  // 4. 返回结果
  return { title: filepath, output: content, metadata: {} }
}
```

### 权限检查时机

工具应在以下时机调用 `ctx.ask()`：

1. **参数解析后**：在提取所有需要的路径/模式后
2. **实际操作前**：在执行文件操作、命令等之前
3. **批量处理**：一次请求多个相关权限（如 bash 工具）
4. **验证通过后**：确保参数有效后再请求权限

## 代理权限

### 内置代理权限

#### Build 代理

默认开发代理，具有完整访问权限：

```typescript
build: {
  permission: PermissionNext.merge(
    defaults, // 默认权限
    PermissionNext.fromConfig({
      question: "allow", // 允许使用问题工具
      plan_enter: "allow", // 允许进入计划
    }),
    user, // 用户配置覆盖
  )
}
```

- **特点**：高权限，适合日常开发
- **权限**：允许几乎所有工具，除特定敏感操作

#### Plan 代理

只读代理，用于代码分析和规划：

```typescript
plan: {
  permission: PermissionNext.merge(
    defaults,
    PermissionNext.fromConfig({
      question: "allow",
      plan_exit: "allow",
      external_directory: {
        [path.join(Global.Path.data, "plans", "*")]: "allow", // 允许保存计划
      },
      edit: {
        "*": "deny", // 拒绝编辑
        [path.join(".opencode", "plans", "*.md")]: "allow", // 但允许保存计划
      },
    }),
    user,
  )
}
```

- **特点**：只读，不能修改代码
- **权限**：禁止编辑，允许读取和搜索

#### General 子代理

通用代理，用于复杂多步骤任务：

```typescript
general: {
  permission: PermissionNext.merge(
    defaults,
    PermissionNext.fromConfig({
      todoread: "deny", // 禁止读取 todo
      todowrite: "deny", // 禁止写入 todo
    }),
    user,
  )
}
```

- **特点**：执行复杂任务，不直接操作 todo
- **限制**：禁止 todo 相关操作

#### Explore 子代理

代码探索专家：

```typescript
explore: {
  permission: PermissionNext.merge(
    defaults,
    PermissionNext.fromConfig({
      "*": "deny", // 默认拒绝所有
      grep: "allow", // 但允许搜索
      glob: "allow", // 和文件查找
      list: "allow", // 和列出
      bash: "allow", // 和 bash
      webfetch: "allow", // 和网络获取
      websearch: "allow", // 和网络搜索
      codesearch: "allow", // 和代码搜索
      read: "allow", // 和读取
      external_directory: {
        [TRUNCATE.DIR]: "allow",
        [TRUNCATE.GLOB]: "allow",
      },
    }),
    user,
  )
}
```

- **特点**：快速探索，专注只读操作
- **用途**：查找文件、搜索代码、理解项目结构

### 代理权限覆盖

用户可以在代理配置中覆盖权限：

```json
{
  "agent": {
    "plan": {
      "permission": {
        "read": {
          "*": "allow", // plan 代理默认只读
          "*.env": "deny" // 但明确拒绝 .env
        }
      }
    }
  }
}
```

### 权限继承

自定义代理如果没有指定权限，继承默认配置：

```typescript
// 用户自定义代理
{
  "agent": {
    "my-agent": {
      "mode": "primary",
      // 如果没有 permission 字段
    }
  }
}

// 系统行为
const permission = PermissionNext.merge(
  defaults,    // 默认权限
  user,        // 用户全局配置
  agentOverride ?? {}  // 代理特定配置（空）
)
// 结果：继承 defaults + user
```

## 最佳实践

### 1. 遵循最小权限原则

```json
// ❌ 不推荐：过于宽松
{
  "permission": {
    "*": "allow"
  }
}

// ✅ 推荐：明确授权
{
  "permission": {
    "read": {
      "*": "allow",
      "*.env": "ask"
    },
    "edit": {
      "*.ts": "ask",
      "*.md": "allow"
    }
  }
}
```

### 2. 使用具体模式而非通配符

```json
// ❌ 不推荐：过于宽泛
{
  "permission": {
    "bash": "allow"  // 允许所有 bash 命令
  }
}

// ✅ 推荐：限制特定操作
{
  "permission": {
    "bash": {
      "*": "ask",
      "npm install": "allow",    // 明确允许的命令
      "npm run build": "allow",
      "npm run test": "allow"
    }
  }
}
```

### 3. 保护敏感文件

```json
{
  "permission": {
    "read": {
      "*": "allow",
      "*.env": "deny", // 拒绝所有 .env 文件
      "*.pem": "deny", // 拒绝证书
      "*.key": "deny", // 拒绝私钥
      "**/credentials/**": "deny", // 拒绝凭证目录
      "**/secret/**": "deny" // 拒绝秘密目录
    }
  }
}
```

### 4. 代理特定配置

```json
{
  "agent": {
    "plan": {
      "permission": {
        "edit": "deny", // plan 代理禁止编辑
        "read": "allow" // 允许读取
      }
    },
    "build": {
      "permission": {
        "edit": "allow", // build 代理允许编辑
        "bash": "ask" // 但 bash 需要确认
      }
    }
  }
}
```

### 5. 使用项目配置覆盖全局

```
~/.opencode/config.json          # 全局配置：保守
{
  "permission": {
    "*": "ask"
  }
}

project/.opencode/config.json     # 项目配置：宽松
{
  "permission": {
    "*": "allow"
  }
}

// 结果：该项目使用宽松配置，其他项目使用保守配置
```

### 6. 分层配置策略

```json
// 第一层：全局（保守）
~/.opencode/config.json
{
  "permission": {
    "bash": "ask",
    "edit": {
      "*": "ask",
      "~/**": "deny"     // 全局禁止编辑用户目录
    }
  }
}

// 第二层：项目（适度）
project/opencode.json
{
  "permission": {
    "edit": {
      "*.ts": "allow",        // 项目允许编辑 .ts
      "*.tsx": "allow"
    }
  }
}

// 第三层：代理（精确）
agent configuration
{
  "agent": {
    "build": {
      "permission": {
        "bash": "allow"         // build 代理允许所有 bash
      }
    }
  }
}
```

### 7. 正确处理通配符

```json
{
  "permission": {
    "read": {
      // ✅ 正确：特定模式在前
      "*.env": "deny",
      "*/node_modules/**": "deny",

      // ❌ 错误：通配符在前会覆盖所有
      "**/*.env": "deny"
    }
  }
}
```

## 常见场景

### 场景 1：安全的新手配置

**需求**：刚接触 AI 编码助手的用户，希望控制每次操作

```json
{
  "permission": {
    "bash": "ask",
    "edit": "ask",
    "write": "ask",
    "read": "ask"
  }
}
```

**效果**：所有操作都需要确认，确保用户了解每次变化

---

### 场景 2：信任的项目配置

**需求**：个人项目，完全信任 AI 的操作

```json
{
  "permission": {
    "*": "allow",
    "external_directory": {
      "~/**": "deny"
    }
  }
}
```

**效果**：项目内所有操作允许，但禁止访问用户目录外的文件

---

### 场景 3：团队共享配置

**需求**：团队项目，需要保护敏感信息

```json
{
  "permission": {
    "read": {
      "*": "allow",
      "*.env": "deny",
      "**/secret/**": "deny",
      "**/credentials/**": "deny"
    },
    "edit": {
      "*.ts": "ask",
      "*.tsx": "ask",
      "*.md": "allow"
    },
    "bash": {
      "*": "ask",
      "git *": "allow", // 允许 git 操作
      "npm run *": "allow" // 允许 npm scripts
    }
  }
}
```

**效果**：保护敏感文件，编辑需确认，常见操作自动允许

---

### 场景 4：只读分析代理

**需求**：使用 plan 代理分析代码，但不希望修改任何东西

**配置**：plan 代理默认配置即可

```json
{
  "agent": {
    "plan": {
      "permission": {
        "edit": { "*": "deny" } // 默认已禁止编辑
      }
    }
  }
}
```

**效果**：plan 代理只能读取文件，不能修改任何代码

---

### 场景 5：不同代理不同权限

**需求**：

- `build` 代理：完全控制
- `plan` 代理：只读
- `explore` 代理：快速探索，只读

**配置**：

```json
{
  "agent": {
    "build": {
      "permission": {
        "*": "allow"
      }
    },
    "plan": {
      "permission": {
        "edit": { "*": "deny" },
        "read": { "*": "allow" }
      }
    },
    "explore": {
      "permission": {
        "*": "deny",
        "grep": "allow",
        "glob": "allow",
        "read": "allow"
      }
    }
  }
}
```

**效果**：每个代理适合其用途，安全且高效

---

### 场景 6：保护系统目录

**需求**：禁止 AI 访问系统关键目录

```json
{
  "permission": {
    "external_directory": {
      "/": "deny", // 拒绝根目录
      "/usr": "deny", // 拒绝系统目录
      "/etc": "deny", // 拒绝配置目录
      "/home": "deny", // 拒绝用户主目录
      "~/": "allow", // 但允许自己的主目录
      "~/Projects": "allow", // 和项目目录
      "~/Downloads": "allow" // 和下载目录
    }
  }
}
```

**效果**：AI 只能访问用户明确允许的目录

---

### 场景 7：允许特定命令

**需求**：允许常用的 npm/git 命令，其他需要确认

```json
{
  "permission": {
    "bash": {
      "*": "ask",
      "git": "allow",
      "git *": "allow",
      "npm": "allow",
      "npm install": "allow",
      "npm run *": "allow",

      "npm run test": "allow"
    }
  }
```

**效果**：常用命令自动执行，未知命令需要确认

## 总结

OpenCode 的权限系统提供了一个强大而灵活的访问控制机制：

### 核心优势

1. **细粒度控制**：针对工具、路径、操作类型的精确控制
2. **三层配置**：默认 → 全局 → 代理 → 运行时，灵活覆盖
3. **用户友好**：实时通知，简单确认，支持自动记忆
4. **安全默认**：内置保护敏感文件，限制危险操作
5. **易于扩展**：工具和代理可以轻松集成权限检查

### 关键组件

- **PermissionNext**：权限评估和用户交互核心
- **Wildcard**：灵活的模式匹配引擎
- **Config**：多层配置系统和验证
- **Event Bus**：客户端和服务器的实时通信

### 使用建议

- 新手用户：使用保守配置，`ask` 一切
- 信任项目：使用宽松配置，`allow` 项目内操作
- 团队协作：明确保护敏感文件和目录
- 定期审查：检查权限配置是否符合当前需求
