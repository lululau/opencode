## 概述

OpenCode 的存储层是一个基于文件系统的键值存储系统，设计用于持久化会话、项目、消息、权限等核心数据。它采用 JSON 格式存储，通过文件系统路径层级来组织数据，提供简单而强大的 CRUD 操作接口。

### 设计目标

- **简洁性**：基于 JSON 文件，易于理解和调试
- **性能**：使用 Bun 的高性能 I/O，支持并发读写
- **安全性**：内置读写锁机制，防止数据损坏
- **可迁移性**：结构化的数据便于迁移和备份
- **可扩展性**：支持数据结构演进和迁移

### 技术特点

- ✅ **零依赖**：仅依赖 Bun 内置的文件系统 API
- ✅ **类型安全**：基于 TypeScript 和 Zod 的完整类型支持
- ✅ **原子性**：通过锁机制保证操作的原子性
- ✅ **错误恢复**：完善的错误处理和恢复机制
- ✅ **自动迁移**：支持数据结构的自动演进

## 存储 API

### 1. 读取数据（read）

从存储中读取指定键的数据。

#### 签名

```typescript
export async function read<T>(key: string[]): Promise<T>
```

#### 参数

- `key: string[]` - 键路径数组，映射到文件系统路径
- 泛型 `T` - 返回数据的类型

#### 返回值

返回解析后的 JSON 数据，类型为 `T`。

#### 异常

如果键不存在，抛出 `Storage.NotFoundError`。

#### 示例

```typescript
import { Storage } from "@/storage/storage"

// 读取会话信息
const session = await Storage.read<Session.Info>(["session", projectID, sessionID])

// 读取项目配置
const project = await Storage.read<Project.Info>(["project", projectID])

// 读取权限规则
const permissions = await Storage.read<PermissionNext.Ruleset>(["permission", projectID])
```

#### 实现细节

```typescript
export async function read<T>(key: string[]) {
  const dir = await state().then((x) => x.dir)
  const target = path.join(dir, ...key) + ".json"
  return withErrorHandling(async () => {
    using _ = await Lock.read(target) // 获取读锁
    const result = await Bun.file(target).json()
    return result as T
  })
}
```

**关键点**：

- 自动添加 `.json` 扩展名
- 使用读锁保证并发安全
- 自动解析 JSON
- 返回类型化数据

### 2. 写入数据（write）

将数据写入指定键。

#### 签名

```typescript
export async function write<T>(key: string[], content: T): Promise<void>
```

#### 参数

- `key: string[]` - 键路径数组
- `content: T` - 要写入的数据

#### 返回值

无返回值。

#### 异常

- 写入失败会抛出异常
- 文件权限问题会抛出系统错误

#### 示例

```typescript
import { Storage } from "@/storage/storage"

// 创建新会话
await Storage.write(["session", projectID, sessionID], {
  id: sessionID,
  projectID,
  title: "New Session",
  time: {
    created: Date.now(),
    updated: Date.now(),
  },
  // ... 其他字段
})

// 保存权限规则
await Storage.write(["permission", projectID], ruleset)

// 存储待办事项
await Storage.write(["todo", sessionID], todos)
```

#### 实现细节

```typescript
export async function write<T>(key: string[], content: T) {
  const dir = await state().then((x) => x.dir)
  const target = path.join(dir, ...key) + ".json"
  return withErrorHandling(async () => {
    using _ = await Lock.write(target) // 获取写锁
    await Bun.write(target, JSON.stringify(content, null, 2))
  })
}
```

**关键点**：

- 自动添加 `.json` 扩展名
- 使用写锁保证互斥访问
- JSON 格式化（缩进 2 个空格）
- 覆盖已存在的文件

### 3. 更新数据（update）

基于现有数据执行更新操作。

#### 签名

```typescript
export async function update<T>(key: string[], fn: (draft: T) => void): Promise<T>
```

#### 参数

- `key: string[]` - 键路径数组
- `fn: (draft: T) => void` - 更新函数，接收数据草稿

#### 返回值

返回更新后的数据。

#### 异常

如果键不存在，抛出 `Storage.NotFoundError`。

#### 示例

```typescript
import { Storage } from "@/storage/storage"

// 更新会话时间戳
await Storage.update(["session", projectID, sessionID], (draft) => {
  draft.time.updated = Date.now()
})

// 更新项目配置
await Storage.update(["project", projectID], (draft) => {
  if (!draft.icon) {
    draft.icon = {
      url: "https://example.com/icon.png",
    }
  }
  draft.sandboxes = draft.sandboxes.filter((id) => id !== sandboxID)
})

// 增量更新摘要
await Storage.update(["session", projectID, sessionID], (draft) => {
  if (draft.summary) {
    draft.summary.files += 1
    draft.summary.additions += 10
    draft.summary.deletions += 5
  }
})
```

#### 实现细节

```typescript
export async function update<T>(key: string[], fn: (draft: T) => void) {
  const dir = await state().then((x) => x.dir)
  const target = path.join(dir, ...key) + ".json"
  return withErrorHandling(async () => {
    using _ = await Lock.write(target) // 获取写锁
    const content = await Bun.file(target).json()
    fn(content) // 直接修改对象
    await Bun.write(target, JSON.stringify(content, null, 2))
    return content as T
  })
}
```

**关键点**：

- 原子读-修改-写操作
- 在锁保护下执行
- 支持对象引用修改
- 自动序列化回写

### 4. 删除数据（remove）

删除指定键的数据。

#### 签名

```typescript
export async function remove(key: string[]): Promise<void>
```

#### 参数

- `key: string[]` - 键路径数组

#### 返回值

无返回值。

#### 示例

```typescript
import { Storage } from "@/storage/storage"

// 删除会话
await Storage.remove(["session", projectID, sessionID])

// 删除消息
await Storage.remove(["message", sessionID, messageID])

// 删除消息部分
await Storage.remove(["part", messageID, partID])
```

#### 实现细节

```typescript
export async function remove(key: string[]) {
  const dir = await state().then((x) => x.dir)
  const target = path.join(dir, ...key) + ".json"
  return withErrorHandling(async () => {
    await fs.unlink(target).catch(() => {})
  })
}
```

**关键点**：

- 静默处理文件不存在的情况
- 不使用锁（删除操作是原子的）
- 仅删除单个文件，不删除目录

### 5. 列出数据（list）

列出指定前缀下的所有键。

#### 签名

```typescript
export async function list(prefix: string[]): Promise<string[][]>
```

#### 参数

- `prefix: string[]` - 键前缀数组

#### 返回值

返回键数组（二维数组），每个键是一个字符串数组。

#### 示例

```typescript
import { Storage } from "@/storage/storage"

// 列出所有项目
const projects = await Storage.list(["project"])
// [["project", "abc123"], ["project", "def456"], ...]

// 列出项目的所有会话
const sessions = await Storage.list(["session", projectID])
// [["session", "abc123", "session1"], ["session", "abc123", "session2"], ...]

// 列出会话的所有消息
const messages = await Storage.list(["message", sessionID])
// [["message", "session1", "msg1"], ["message", "session1", "msg2"], ...]
```

#### 实现细节

```typescript
const glob = new Bun.Glob("**/*")

export async function list(prefix: string[]) {
  const dir = await state().then((x) => x.dir)
  try {
    const result = await Array.fromAsync(
      glob.scan({
        cwd: path.join(dir, ...prefix),
        onlyFiles: true,
      }),
    ).then((results) => results.map((x) => [...prefix, ...x.slice(0, -5).split(path.sep)]))
    result.sort() // 按字母顺序排序
    return result
  } catch {
    return [] // 目录不存在时返回空数组
  }
}
```

**关键点**：

- 使用 Bun.Glob 进行模式匹配
- 自动去除 `.json` 扩展名
- 返回完整键路径
- 结果按字母顺序排序
- 静默处理错误（返回空数组）

## 并发控制

### 读写锁机制

OpenCode 使用读写锁来确保并发访问的安全性。锁机制位于 `packages/opencode/src/util/lock.ts`。

#### 锁状态

每个文件（锁键）可以有以下状态：

| 状态   | 读锁数 | 写锁数 | 等待读 | 等待写 |
| ------ | ------ | ------ | ------ | ------ |
| 无锁   | 0      | 0      | 0      | 0      |
| 读状态 | > 0    | 0      | ≥ 0    | ≥ 0    |
| 写状态 | 0      | 1      | ≥ 0    | ≥ 0    |

#### 锁规则

1. **读锁共享**：多个读操作可以同时进行
2. **写锁互斥**：写操作独占访问
3. **读写互斥**：写操作时不能读，读操作时不能写
4. **写者优先**：为防止写者饥饿，写操作优先于等待的读操作

#### 锁 API

```typescript
// 获取读锁
export async function read(key: string): Promise<Disposable>

// 获取写锁
export async function write(key: string): Promise<Disposable>
```

#### 使用模式

使用 TypeScript 的 `using` 关键字自动释放锁：

```typescript
import { Lock } from "@/util/lock"

// 读取操作
{
  using lock = await Lock.read("/path/to/file")
  // 安全地读取文件
  const data = await Bun.file("/path/to/file").text()
  // 锁在块结束时自动释放
}

// 写入操作
{
  using lock = await Lock.write("/path/to/file")
  // 独占访问写入
  await Bun.write("/path/to/file", content)
  // 锁在块结束时自动释放
}
```

#### 在 Storage 中的应用

```typescript
// read() 使用读锁
using _ = await Lock.read(target)
const result = await Bun.file(target).json()

// write() 使用写锁
using _ = await Lock.write(target)
await Bun.write(target, JSON.stringify(content, null, 2))

// update() 使用写锁（读-修改-写）
using _ = await Lock.write(target)
const content = await Bun.file(target).json()
fn(content)
await Bun.write(target, JSON.stringify(content, null, 2))
```

#### 并发场景示例

**场景 1：多个会话同时读取**


## 迁移系统

### 迁移机制

OpenCode 支持数据结构的自动迁移，当检测到新版本时，会按顺序执行迁移脚本。

### 迁移状态

迁移版本存储在 `storage/migration` 文件中：

```bash
# 查看当前迁移版本
cat $XDG_DATA_HOME/opencode/storage/migration
# 输出: 2  (表示已经执行了前2个迁移)
```

### 迁移执行流程

```typescript
const state = lazy(async () => {
  const dir = path.join(Global.Path.data, "storage")
  const migration = await Bun.file(path.join(dir, "migration"))
    .json()
    .then((x) => parseInt(x))
    .catch(() => 0)

  // 从当前版本开始执行所有未执行的迁移
  for (let index = migration; index < MIGRATIONS.length; index++) {
    log.info("running migration", { index })
    const migration = MIGRATIONS[index]
    await migration(dir).catch(() => log.error("failed to run migration", { index }))
    await Bun.write(path.join(dir, "migration"), (index + 1).toString())
  }

  return { dir }
})
```

### 已有迁移

#### 迁移 0：项目 ID 重新计算

**目的**：将旧的目录名项目 ID 改为基于 Git 根提交哈希的 ID。

**执行逻辑**：

1. 扫描旧的项目目录
2. 从会话消息中提取工作树路径
3. 计算 Git 仓库的根提交哈希
4. 使用根提交哈希作为新的项目 ID
5. 迁移所有会话、消息和部分数据到新路径

**代码示例**：

```typescript
;async (dir) => {
  const project = path.resolve(dir, "../project")
  for await (const projectDir of new Bun.Glob("*").scan({ cwd: project })) {
    let projectID = projectDir
    const worktree = extractWorktree(projectDir)

    if (worktree && (await Filesystem.isDir(worktree))) {

        .cwd(worktree)
        .text()
        .then((x) => x.split("\n").filter(Boolean).toSorted())

      }
    }
```

#### 迁移 1：会话差异分离

**目的**：将会话摘要中的 diffs 数据分离到独立文件，优化存储和加载性能。

**执行逻辑**：

1. 扫描所有会话文件
2. 提取 summary.diffs 数据
3. 写入到 `session_diff/<sessionID>.json`
4. 更新会话文件，只保留统计信息

**代码示例**：

```typescript
;async (dir) => {
  for await (const item of new Bun.Glob("session/*/*.json").scan({ cwd: dir })) {
    const session = await Bun.file(item).json()
    if (!session.projectID || !session.summary?.diffs) continue

    const { diffs } = session.summary

    // 写入独立文件
    await Bun.file(path.join(dir, "session_diff", session.id + ".json")).write(JSON.stringify(diffs))

    // 更新会话文件
    await Bun.file(path.join(dir, "session", session.projectID, session.id + ".json")).write(
      JSON.stringify({
        ...session,
        summary: {
          additions: diffs.reduce((sum, x) => sum + x.additions, 0),
          deletions: diffs.reduce((sum, x) => sum + x.deletions, 0),
        },
      }),
    )
  }
}
```

#### 定义

```typescript
export const NotFoundError = NamedError.create(
  "NotFoundError",
  z.object({
    message: z.string(),
  }),
```

#### 使用示例

```typescript
import { Storage } from "@/storage/storage"

try {
  const session = await Storage.read(["session", projectID, sessionID])
} catch (error) {
  if (error instanceof Storage.NotFoundError) {
    console.log("Session not found:", error.message)
    // 处理不存在的情况
  } else {
    throw error // 重新抛出其他错误
  }
}
```

#### 实现细节

```typescript
async function withErrorHandling<T>(body: () => Promise<T>) {
  return body().catch((e) => {
    if (!(e instanceof Error)) throw e
    const errnoException = e as NodeJS.ErrnoException

    // ENOENT = No such file or directory
    if (errnoException.code === "ENOENT") {
      throw new NotFoundError({
        message: `Resource not found: ${errnoException.path}`,
      })
    }
    throw e
  })
}
```

### 常见错误

| 错误类型        | 原因         | 处理方式                   |
| --------------- | ------------ | -------------------------- |
| `NotFoundError` | 文件不存在   | 捕获后返回默认值或提示用户 |
| `EACCES`        | 权限不足     | 检查文件权限               |
| `ENOSPC`        | 磁盘空间不足 | 清理磁盘空间或提示用户     |
| `EIO`           | I/O 错误     | 重试或报告错误             |

无冲突时直接获取锁，避免不必要的等待：

```typescript
export async function read(key: string): Promise<Disposable> {
  const lock = get(key)

  return new Promise((resolve) => {
    // 快速路径：无写锁时直接获得读锁
    if (!lock.writer && lock.waitingWriters.length === 0) {
      lock.readers++
      resolve(createDisposable())
    }
    // 慢速路径：需要等待
    else {
      lock.waitingReaders.push(() => { ... })
    }
  })
}
```

## 最佳实践

### 1. 键命名规范

使用一致的、有意义的键结构：

```typescript
// ✅ 好：清晰的层级
await Storage.read(["session", projectID, sessionID])
await Storage.read(["message", sessionID, messageID])
await Storage.read(["part", messageID, partID])

// ❌ 不好：扁平结构
await Storage.read([`${projectID}_${sessionID}`])
```

### 2. 错误处理

始终处理可能的 `NotFoundError`：

```typescript
// ✅ 好：优雅处理
const session = await Storage.read(["session", projectID, sessionID])
  .catch(() => null)

if (!session) {
  console.log("Session not found, creating new one...")
  session = await createNewSession(...)
}

// ❌ 不好：未处理错误
const session = await Storage.read(["session", projectID, sessionID])
console.log(session.title)  // 可能崩溃！
```

### 3. 类型安全

使用 Zod schema 定义数据结构：

```typescript
// ✅ 好：类型安全
import { Storage } from "@/storage/storage"
import z from "zod"

const SessionInfo = z.object({
  id: z.string(),
  title: z.string(),
  time: z.object({
    created: z.number(),
    updated: z.number(),
  }),
})

const session = await Storage.read(["session", ...])
const validated = SessionInfo.parse(session)

// ❌ 不好：类型不安全
const session = await Storage.read(["session", ...])
console.log(session.unknownField)  // 类型检查无法捕获
```

### 4. 原子操作

使用 `update` 而非 `read + write`：

```typescript
// ✅ 好：原子操作
await Storage.update(["project", projectID], (draft) => {
  draft.time.updated = Date.now()
  draft.version = "2.0.0"
})

// ❌ 不好：非原子操作
const project = await Storage.read(["project", projectID])
project.time.updated = Date.now()
// 这里可能被其他进程修改！
await Storage.write(["project", projectID], project)
```

### 5. 批量操作

使用批量操作减少 I/O：

```typescript
// ✅ 好：批量删除
const messageKeys = await Storage.list(["message", sessionID])
await Promise.all(messageKeys.map((key) => Storage.remove(key)))

// ❌ 不好：逐个删除
const messageKeys = await Storage.list(["message", sessionID])
for (const key of messageKeys) {
  await Storage.remove(key) // 串行，慢！
}
```

### 6. 数据验证

在写入前验证数据：

```typescript
// ✅ 好：写入前验证
function saveProject(project: Project.Info) {
  const validated = ProjectInfo.parse(project)
  return Storage.write(["project", project.id], validated)
}

// ❌ 不好：直接写入可能无效的数据
await Storage.write(["project", id], { ... })  // 可能缺少必需字段
```

### 缓存策略

实现多级缓存以提升性能：

```typescript
class CachedStorage {
  private memoryCache = new Map<string, any>()
  private cacheTimers = new Map<string, NodeJS.Timeout>()

  async read<T>(key: string[]): Promise<T> {
    const cacheKey = key.join("/")

    // 检查内存缓存
    if (this.memoryCache.has(cacheKey)) {
      return this.memoryCache.get(cacheKey) as T
    }

    // 从存储读取
    const value = await Storage.read<T>(key)

    // 缓存结果（5分钟过期）
    this.memoryCache.set(cacheKey, value)
    this.scheduleExpiry(cacheKey, 5 * 60 * 1000)

    return value
  }

  async write<T>(key: string[], content: T): Promise<void> {
    await Storage.write(key, content)

    // 更新缓存
    const cacheKey = key.join("/")
    this.memoryCache.set(cacheKey, content)
    this.scheduleExpiry(cacheKey, 5 * 60 * 1000)
  }

  private scheduleExpiry(key: string, ttl: number) {
    if (this.cacheTimers.has(key)) {
      clearTimeout(this.cacheTimers.get(key)!)
    }

    const timer = setTimeout(() => {
      this.memoryCache.delete(key)
      this.cacheTimers.delete(key)
    }, ttl)

    this.cacheTimers.set(key, timer)
  }

  invalidate(key: string[]) {
    const cacheKey = key.join("/")
    this.memoryCache.delete(cacheKey)
  }
}
```

## 故障排查

### 常见问题

#### 问题 1：读取时出现 ENOENT 错误

**症状**：

```
NotFoundError: Resource not found: /path/to/storage/session/abc123/session_001.json
```

**原因**：尝试读取不存在的文件。

**解决方案**：

```typescript
// 检查文件是否存在
const keys = await Storage.list(["session", projectID])
if (!keys.some(k => k.includes(sessionID))) {
  console.log("Session does not exist")
  return
}

// 或者使用 try-catch
try {
  const session = await Storage.read(["session", ...])
} catch (error) {
  if (error instanceof Storage.NotFoundError) {
    // 处理不存在的情况
  }
}
```

#### 问题 2：写入操作卡住

**症状**：`Storage.write()` 长时间不返回。

**原因**：另一个进程持有写锁。

**解决方案**：

```bash
# 查找持有锁的进程
lsof | grep opencode

# 或重启 OpenCode
```

#### 问题 3：迁移失败

**症状**：日志显示 "failed to run migration"。

**原因**：迁移脚本执行错误。

**解决方案**：

1. 检查日志中的具体错误
2. 手动备份数据：`cp -r ~/.local/share/opencode/storage ~/backup`
3. 重置迁移状态：`rm ~/.local/share/opencode/storage/migration`
4. 重启 OpenCode 重新执行迁移

#### 问题 4：存储占用过大

**症状**：`du -sh ~/.local/share/opencode/storage` 显示很大。

**原因**：

- 大量会话历史
- 大消息内容
- 未清理的临时数据

**解决方案**：

```typescript
// 删除旧会话
async function cleanupOldSessions(projectID: string, days = 30) {
  const cutoff = Date.now() - days * 24 * 60 * 60 * 1000

  const sessionKeys = await Storage.list(["session", projectID])
  for (const key of sessionKeys) {
    const session = await Storage.read(key)
    if (session.time.created < cutoff) {
      console.log("Deleting old session:", session.id)

      // 删除会话、消息和部分
      await Storage.remove(key)
      const msgKeys = await Storage.list(["message", session.id])
      await Promise.all(msgKeys.map((k) => Storage.remove(k)))
    }
  }
}

// 压缩会话差异
async function compactSessionDiffs() {
  const diffKeys = await Storage.list(["session_diff"])
  for (const key of diffKeys) {
    const diffs = await Storage.read(key)
    // 只保留最近 100 个差异
    const compacted = diffs.slice(-100)
    await Storage.write(key, compacted)
  }
}
```
