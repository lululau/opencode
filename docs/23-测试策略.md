## 概述

OpenCode 采用多层次测试策略，确保代码质量和功能可靠性：

- **单元测试**：使用 Bun Test 测试单个函数和组件
- **集成测试**：测试多个组件的交互
- **E2E 测试**：使用 Playwright 测试完整用户流程
- **CI 测试**：在 GitHub Actions 中自动化运行所有测试

## 单元测试

### Bun Test 框架

OpenCode 使用 Bun 内置的测试框架：

```bash
# 运行所有单元测试
bun test

# 运行特定测试文件
bun test test/tool/bash.test.ts

# 运行带覆盖率的测试
bun test --coverage

# 运行特定测试模式
bun test --test-name-pattern="bash"
```

### 测试配置

**主配置 (`packages/opencode/bunfig.toml`):**

```toml
[test]
preload = ["./test/preload.ts"]
timeout = 10000
coverage = true
```

- `preload`：预加载测试环境设置
- `timeout`：测试超时时间（毫秒）
- `coverage`：启用覆盖率收集

**根目录保护 (`bunfig.toml`):**

```toml
[test]
root = "./do-not-run-tests-from-root"
```

防止从根目录意外运行测试。

### 单元测试模式

```typescript
import { describe, expect, test, beforeEach, afterEach } from "bun:test"
import { Instance } from "../../src/project/instance"

      fn: async () => {

      },
    })
```
```typescript
  })
})
```

### 测试固定装置 (Fixtures)

**临时目录工具 (`packages/opencode/test/fixture/fixture.ts`):**

```typescript
import { tmpdir } from "bun:test"

export async function tmpdir<T>(options?: {
  git?: boolean
  config?: Partial<Config.Info>
  init?: (dir: string) => Promise<T>
  dispose?: (dir: string) => Promise<T>
}): Promise<{ using: AsyncDisposable; value: T; dir: string }> {
  const dir = await fs.mkdtemp(path.join(tmpdir(), "opencode-test-"))

  if (options?.git) {
    await $`git init`.cwd(dir)
    await $`git config user.email "test@opencode.ai"`.cwd(dir)
    await $`git config user.name "Test"`.cwd(dir)
  }

  if (options?.config) {
    await fs.writeFile(path.join(dir, ".opencode.json"), JSON.stringify(options.config))
  }

  const value = options?.init ? await options.init(dir) : (undefined as T)

  return {
    dir,
    value,
    using: {
      async [Symbol.asyncDispose]() {
        await options?.dispose?.(dir)
        await fs.rm(dir, { recursive: true, force: true })
      },
    },
  }
}
```

**使用示例：**

```typescript
test("with git directory", async () => {
  await using fixture = await tmpdir({
    git: true,
    init: async (dir) => {
      await fs.writeFile(path.join(dir, "test.ts"), "content")
      return "initialized"
    },
  })

  // fixture.dir 是临时目录
  // fixture.value 是 "initialized"

  // 测试完成后自动清理
})
```

## 集成测试

集成测试测试多个组件之间的交互。OpenCode 的集成测试使用相同的 Bun Test 框架，但测试更复杂的工作流。

### 会话管理测试

```typescript
describe("session.started event", () => {
  test("should emit session.started event when session is created", async () => {
    await Instance.provide({
      directory: projectRoot,
      fn: async () => {
        let eventReceived = false
        let receivedInfo: Session.Info | undefined

        const unsub = Bus.subscribe(Session.Event.Created, (event) => {
          eventReceived = true
          receivedInfo = event.properties.info as Session.Info
        })

        const session = await Session.create({})

        await new Promise((resolve) => setTimeout(resolve, 100))

        unsub()

        expect(eventReceived).toBe(true)
        expect(receivedInfo).toBeDefined()
        expect(receivedInfo?.id).toBe(session.id)
      },
    })
  })
})
```

### 工具集成测试

```typescript
describe("Tool Integration", () => {
  test("read → edit → read sequence", async () => {
    await Instance.provide({
      directory: projectRoot,
      fn: async () => {
        const readTool = await ReadTool.init()
        const editTool = await EditTool.init()

        const filePath = path.join(projectRoot, "test.txt")

        // 1. 读取文件
        const read1 = await readTool.execute({ filePath }, ctx)
        expect(read1.output).toBe("initial content")

        // 2. 编辑文件
        const edit = await editTool.execute(
          {
            filePath,
            oldString: "initial content",
            newString: "updated content",
          },
          ctx,
        )
        expect(edit.metadata.status).toBe("applied")

        // 3. 验证更新
        const read2 = await readTool.execute({ filePath }, ctx)
        expect(read2.output).toBe("updated content")
      },
    })
  })
})
```

```typescript
  },

```

### E2E 测试固定装置

```typescript
// packages/app/e2e/fixtures.ts
import { test as base } from "@playwright/test"

type TestFixtures = {
  sdk: ReturnType<typeof createSdk>
  gotoSession: (sessionID?: string) => Promise<void>
}

type WorkerFixtures = {
  directory: string
  slug: string
}

export const test = base.extend<TestFixtures, WorkerFixtures>({
  // 设置工作目录
  directory: async ({}, use) => {
    const dir = await getWorktree()
    await use(dir)
  },

  // 计算 slug
  slug: async ({ directory }, use) => {
    const slug = dirSlug(directory)
    await use(slug)
  },

  // 创建 SDK 客户端
  sdk: async ({ directory, slug }, use) => {
    const sdk = createSdk({
      url: baseURL,
    })
    await use(sdk)
  },

  // 导航到会话
  gotoSession: async ({ page, sdk, slug }, use) => {
    const goto = async (sessionID?: string) => {
      const id = sessionID ?? slug
      await page.goto(`${baseURL}/${id}`)
    }
    await use(goto)
  },
})
```

### E2E 测试模式

**发送提示并接收响应：**

```typescript
test("can send a prompt and receive a reply", async ({ page, sdk, gotoSession }) => {
  test.setTimeout(120_000)

  await gotoSession()

  // 点击提示输入框
  const prompt = page.locator(promptSelector)
  await prompt.click()

  // 输入文本
  await page.keyboard.type("Reply with exactly: TEST_TOKEN")

  // 提交
  await page.keyboard.press("Enter")

  // 等待导航到会话
  await expect(page).toHaveURL(/\/session\/[^/?#]+/, { timeout: 30_000 })

  // 轮询检查响应
  const messages = await expect.poll(
    async () => {
      const msgs = await sdk.session.messages({ sessionID, limit: 50 })
      return msgs
        .filter((m) => m.info.role === "assistant")
        .flatMap((m) => m.parts)
        .filter((p) => p.type === "text")
        .map((p) => p.text)
        .join("\n")
    },
    { timeout: 90_000 },
  )

  expect(messages).toContain("TEST_TOKEN")
})
```

**UI 交互测试：**

```typescript
test("can create a new session", async ({ page, directory }) => {
```

## 编写测试

### 测试命名规范

- **文件命名**：`*.test.ts` 或 `*.spec.ts` (E2E)
- **测试套件**：`describe("Feature Name", () => {})`
- **测试用例**：`test("should do something", () => {})`

### 测试组织

```
packages/opencode/test/
├── agent/          # 代理系统测试
│   └── agent.test.ts
├── session/         # 会话管理测试
│   ├── session.test.ts
│   └── message-v2.test.ts
├── tool/            # 工具测试
│   ├── bash.test.ts
│   ├── read.test.ts
│   └── ...
├── permission/      # 权限系统测试
│   └── next.test.ts

    └── fixture.ts

packages/app/e2e/
├── fixtures.ts     # E2E 固定装置
├── utils.ts        # E2E 工具函数
├── prompt.spec.ts   # 提示功能测试
├── session.spec.ts  # 会话功能测试
└── ...
```

### 测试最佳实践

1. **使用测试固定装置**：
   - 自动创建和清理临时资源
   - 隔离测试环境

2. **AAA 模式**：

   ```typescript
   test("feature", async () => {
     // Arrange (准备)
     const tool = await Tool.init()
     const params = { ... }

     // Act (执行)
     const result = await tool.execute(params, ctx)

     // Assert (断言)
     expect(result).toBe(...)
   })
   ```

3. **描述性测试名**：
   - ✅ Good: "should return 404 when session not found"
   - ❌ Bad: "test session"

4. **一个测试一个关注点**：
   - 每个测试验证一个特定的行为

5. **使用 expect.poll() 处理异步**：

   ```typescript
   await expect
     .poll(
       async () => {
         return await sdk.session.messages({ sessionID })
       },
       { timeout: 30_000 },
     )
     .toContain(expectedMessage)
   ```

6. **Mock 外部依赖**：
   - 使用 `spyOn()` 和 `mock()` 隔离外部服务

7. **测试边界情况**：
   - 空输入、null 值、极端值

8. **清理资源**：
   - 使用 `afterEach` 或 `await using` 模式

## 常见问题

### 测试超时

**问题**：测试在 CI 中超时

**解决方案**：

```bash
# 增加超时时间
test.setTimeout(120_000) // 2 分钟

# 或在测试文件中
test("slow test", async () => {
  test.setTimeout(180_000)
  // ... 测试逻辑
})
```

### Mock 不生效

**问题**：Mock 未被调用

**解决方案**：

```typescript
// 确保 mock 在使用前设置
beforeEach(() => {
  askSpy = spyOn(QuestionModule.Question, "ask")
})

// 确保清理
afterEach(() => {
  askSpy.mockRestore()
})

// 确保导入顺序正确
import { QuestionModule } from "./question"
import { spyOn } from "bun:test"
```

### E2E 测试不稳定

**问题**：测试在本地通过但在 CI 中失败

**解决方案**：

1. **增加重试次数**：

   ```typescript
   // playwright.config.ts
   retries: process.env.CI ? 2 : 0
   ```

2. **增加超时**：

   ```typescript
   test.setTimeout(90_000) // 1.5 分钟
   await expect(element).toBeVisible({ timeout: 30_000 })
   ```

3. **使用 wait 和 poll**：

   ```typescript
   await expect
     .poll(async () => {
       return await page.textContent(selector)
     })
     .toBe(expected)
   ```

4. **等待网络请求完成**：
   ```typescript
   await page.waitForLoadState("networkidle")
   ```

### 覆盖率不准确

**问题**：覆盖率报告显示某些文件未被覆盖

**解决方案**：

1. **检查导入路径**：

   ```typescript
   // 确保使用相对导入
   import { Tool } from "./tool" // ✅
   import { Tool } from "@opencode-ai/opencode/tool" // ❌ 可能未被包含
   ```

2. **排除测试文件**：
   ```bash
   bun test --coverage --exclude="test/**"
   ```

### CI 环境变量问题

**问题**：CI 测试失败，本地通过

**解决方案**：

检查 CI 环境变量配置：

```yaml
- name: Set OS-specific paths
  run: |
    export XDG_DATA_HOME=${{ runner.temp }}/opencode-e2e/share
    export XDG_CACHE_HOME=${{ runner.temp }}/opencode-e2e/cache
    export XDG_CONFIG_HOME=${{ runner.temp }}/opencode-e2e/config
```

## 总结

OpenCode 的测试策略提供：

- ✅ **快速反馈**：单元测试使用 Bun Test，执行速度快
- ✅ **真实场景**：E2E 测试使用 Playwright，模拟真实用户
- ✅ **自动化 CI**：GitHub Actions 自动运行所有测试
- ✅ **覆盖率追踪**：内置覆盖率支持
- ✅ **环境隔离**：测试环境完全隔离，避免副作用

### 测试命令速查

| 命令                              | 描述                   |
| --------------------------------- | ---------------------- |
| `bun test`                        | 运行所有单元测试       |
| `bun test --coverage`             | 运行测试并生成覆盖率   |
| `bun test test/tool/bash.test.ts` | 运行特定测试文件       |
| `bun turbo test`                  | 运行所有包的测试       |
| `bun turbo typecheck`             | 运行类型检查           |
| `bun run test:e2e:local`          | 运行本地 E2E 测试      |
| `bun run test:e2e:ui`             | 运行 E2E 测试 UI       |
| `bunx playwright install`         | 安装 Playwright 浏览器 |
