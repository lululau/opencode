## 概述

OpenCode 是一个模块化、可扩展的 AI 编码助手平台，采用客户端-服务器架构。其核心设计理念是将 AI 能力与代码操作解耦，通过清晰的层次结构和灵活的扩展机制，支持多种客户端界面、AI 提供商和外部工具。

### 核心设计原则

1. **模块化**: 每个子系统（代理、工具、权限、会话等）独立封装，通过明确定义的接口通信
2. **可扩展性**: 通过 MCP 协议、插件系统和代理配置轻松扩展功能
3. **安全性**: 细粒度的权限控制系统，支持用户交互式审批
4. **可观测性**: 事件驱动的架构，完整的日志和调试支持
5. **性能**: 异步非阻塞设计，支持实时事件流和并行执行

### 客户端类型

#### 1. **TUI (Terminal User Interface)**

- **技术栈**: SolidJS + OpenTUI
- **位置**: `packages/opencode/src/cli/cmd/tui/`
- **特点**:
  - 原生终端渲染
  - 键盘交互
  - 支持高分辨率终端
  - 与服务器通过 WebSocket/SSE 通信
  - 离线缓存支持

#### 2. **Web 应用**

- **技术栈**: SolidJS + Vite + Tailwind CSS
- **位置**: `packages/app/`
- **特点**:
  - 响应式设计
  - 实时通信（WebSocket）
  - 支持多标签页
  - 浏览器原生 API 集成

#### 3. **桌面应用**

- **技术栈**: Tauri + Rust + SolidJS
- **位置**: `packages/desktop/`
- **特点**:
  - 原生系统集成（拖拽、菜单、通知）
  - 本地存储和缓存
  - 系统托盘支持
  - 独立打包和分发

### SDK 层

- **位置**: `packages/sdk/js/`
- **生成方式**: 从服务器 OpenAPI 规范自动生成
- **用途**: 为所有客户端提供类型安全的 API 访问
- **更新触发**: 修改 `packages/opencode/src/server/server.ts` 后运行 `./script/generate.ts`

## 核心组件

### 1. 服务器层 (Server Layer)

#### 框架与配置

- **框架**: Hono (轻量级、高性能 HTTP 框架)
- **主文件**: `packages/opencode/src/server/server.ts`
- **端口**: 默认 4096

#### 中间件栈

```typescript
// 中间件执行顺序
app.onError(...)           // 1. 错误处理
app.use(basicAuth(...))  // 2. 基本认证
app.use(loggingMiddleware)  // 3. 请求日志
app.use(cors(...))        // 4. CORS 处理
```

**中间件功能**:

1. **错误处理**: 将 NamedError 转换为 HTTP 响应
2. **认证**: 基于 Basic Auth（可选，通过环境变量配置）
3. **日志**: 记录请求方法和路径，计时请求处理时间
4. **CORS**: 允许本地开发、特定域名和白名单

#### 路由组织

| 路由前缀        | 文件位置                 | 功能描述               |
| --------------- | ------------------------ | ---------------------- |
| `/global`       | `routes/global.ts`       | 全局配置和状态         |
| `/session`      | `routes/session.ts`      | 会话创建、消息、事件流 |
| `/project`      | `routes/project.ts`      | 项目信息、工作区管理   |
| `/config`       | `routes/config.ts`       | 配置读写               |
| `/provider`     | `routes/provider.ts`     | AI 提供商管理          |
| `/mcp`          | `routes/mcp.ts`          | MCP 服务器管理         |
| `/file`         | `routes/file.ts`         | 文件操作端点           |
| `/permission`   | `routes/permission.ts`   | 权限请求和响应         |
| `/question`     | `routes/question.ts`     | 用户问题交互           |
| `/pty`          | `routes/pty.ts`          | PTY (伪终端) 支持      |
| `/tui`          | `routes/tui.ts`          | TUI 专用端点           |
| `/experimental` | `routes/experimental.ts` | 实验性功能             |

#### 实时通信

**SSE (Server-Sent Events)**:

- 使用 Hono 的 `streamSSE` 实现
- 用于实时推送 AI 响应、工具执行进度、权限请求
- 支持断线重连

**WebSocket**:

- 支持 Hono WebSocket (`@hono/bun/websocket`)
- 用于双向通信（如实时协作、状态同步）

#### OpenAPI 规范

- 使用 `hono-openapi` 自动生成
- 端点: `/doc`
- 版本: OpenAPI 3.1.1
- SDK 生成源

### 2. 代理系统 (Agent System)

代理是 OpenCode 的核心抽象，代表不同能力配置的 AI 助手。

#### 代理类型

```typescript
// packages/opencode/src/agent/agent.ts
type AgentMode = "subagent" | "primary" | "all"
```

| 类型         | 描述                           | 示例             |
| ------------ | ------------------------------ | ---------------- |
| **primary**  | 用户可直接切换的主要代理       | build, plan      |
| **subagent** | 由其他代理内部调用的子代理     | general, explore |
| **all**      | 既可作为主要也可作为子代理使用 | -                |

#### 内置代理

| 代理      | 类型     | 描述                                   | 默认 |
| --------- | -------- | -------------------------------------- | ---- |
| `build`   | primary  | 默认开发代理，完整访问权限             | ✅   |
| `plan`    | primary  | 只读代理，用于分析和规划，拒绝文件编辑 | ❌   |
| `general` | subagent | 通用代理，用于复杂多步骤任务           | -    |
| `explore` | subagent | 代码探索专家，专注于查找和分析代码库   | -    |

#### 代理配置结构

```typescript
interface AgentInfo {
  name: string // 代理名称
  description?: string // 描述
  mode: "subagent" | "primary" | "all" // 类型
  native?: boolean // 是否内置代理
  hidden?: boolean // 是否在 UI 中隐藏
  permission: PermissionNext.Ruleset // 权限规则
  model?: {
    // 可选模型配置
    modelID: string
    providerID: string
  }
  prompt?: string // 系统提示词
  options: Record<string, any> // 其他选项
  temperature?: number // 温度参数 (0-1)
  topP?: number // Top P 参数
  steps?: number // 最大执行步骤数
}
```

#### 权限合并

代理的权限由三层合并而成：

```typescript
// packages/opencode/src/agent/agent.ts
const defaults = PermissionNext.fromConfig({
  "*": "allow",
  "*.env": "ask", // 读取 .env 需要确认
  external_directory: { "*": "ask" },
})

const user = PermissionNext.fromConfig(cfg.permission ?? {})

const merged = PermissionNext.merge(defaults, agentSpecific, user)
```

**合并优先级**: `user > agentSpecific > defaults`

#### 子代理调用机制

主代理可以通过 `@agent-name` 语法调用子代理：

```
User: Search the codebase for all API endpoints
AI: I'll search for API endpoints using the explore agent

[delegates to @explore with search parameters]

Explore Agent: Found 15 API endpoints in routes/
```

**流程**:

1. 主代理识别需要子代理的任务
2. 创建子会话（或复用现有会话）
3. 将子代理调用消息加入消息历史
4. 子代理执行并返回结果
5. 主代理整合子代理结果

### 3. 工具系统 (Tool System)

工具是代理可以执行的操作，提供了与外部世界交互的接口。

#### 工具接口

```typescript
// packages/opencode/src/tool/tool.ts
interface ToolInfo<Parameters extends ZodType, Metadata> {
  id: string // 工具唯一标识
  init: (ctx?: InitContext) => Promise<{
    description: string
    parameters: Parameters // Zod schema
    execute(
      args: z.infer<Parameters>,
      ctx: Context,
    ): Promise<{
      title: string
      metadata: Metadata
      output: string
      attachments?: FilePart[]
    }>
    formatValidationError?(error: ZodError): string
  }>
}
```

#### 工具定义示例

```typescript
import { Tool } from "./tool"
import z from "zod"

export const ReadTool = Tool.define("read", {
  description: "Read a file from the filesystem",
  parameters: z.object({
    filePath: z.string().describe("Absolute path to the file"),
  }),
  async execute(args, ctx) {
    // 1. 权限检查（自动）
    // 2. 执行工具逻辑
    const content = await Bun.file(args.filePath).text()

    return {
      title: `Read ${args.filePath}`,
      output: content,
      metadata: {},
    }
  },
})
```

#### 执行上下文 (Context)

```typescript
interface Context {
  sessionID: string // 当前会话 ID
  messageID: string // 当前消息 ID
  agent: string // 执行工具的代理名称
  abort: AbortSignal // 中止信号
  callID?: string // 调用 ID（用于关联请求）
  extra?: Record<string, any> // 额外元数据
  metadata(input: { title?: string; metadata?: any }): void
  ask(input: Omit<PermissionRequest, "id" | "sessionID" | "tool">): Promise<void>
}
```

#### 工具类别

| 类别         | 示例工具                                 | 功能                 |
| ------------ | ---------------------------------------- | -------------------- |
| **文件操作** | read, write, edit, glob, grep            | 文件读写、搜索、编辑 |
| **Shell**    | bash                                     | 执行 shell 命令      |
| **Web**      | webfetch, websearch                      | 网络请求和搜索       |
| **LSP**      | lsp_goto_definition, lsp_find_references | 代码智能             |
| **会话管理** | todowrite, todoread                      | 待办事项管理         |
| **权限交互** | question                                 | 用户问题交互         |

#### 参数验证

所有工具参数使用 Zod schema 验证：

```typescript
export const EditTool = Tool.define("edit", {
  parameters: z.object({
    filePath: z.string(),
    oldString: z.string(),
    newString: z.string(),
  }),

    // Zod 在 execute 之前自动验证
    // 验证失败时返回友好的错误消息

```

**自定义错误格式化**:

```typescript

```

#### 结果截断

大型工具输出会被自动截断，以控制上下文大小：

```typescript
// packages/opencode/src/tool/truncation.ts
async function truncateOutput(output: string, context: TruncateContext) {
  if (output.length <= LIMIT) return { content: output, truncated: false }

  const truncated = output.substring(0, LIMIT)
  const filePath = await saveToDisk(truncated)

  return {
    content: truncated,
    truncated: true,
    outputPath: filePath,
  }
}
```

### 5. 权限系统 (Permission System)

OpenCode 使用细粒度的权限系统控制代理可以执行的操作。

#### 权限规则

```typescript
// packages/opencode/src/permission/next.ts
interface Rule {
  permission: string // 权限名称（如 "bash", "edit"）
  pattern: string // 匹配模式（支持通配符）
  action: "allow" | "deny" | "ask" // 动作
}

type Ruleset = Rule[]
```

#### 权限动作

| 动作  | 行为                         |
| ----- | ---------------------------- |
| allow | 直接允许操作，无需确认       |
| deny  | 拒绝操作，返回错误           |
| ask   | 请求用户确认，等待响应后执行 |

#### 配置示例

```json
{
  "permission": {
    "bash": "ask", // 执行 bash 需要确认
    "edit": "allow", // 允许所有编辑
    "read": {
      "*": "allow", // 允许读取所有文件
      "*.env": "ask", // .env 文件需要确认
      "*.env.example": "allow" // .env.example 允许
    },
    "external_directory": {
      "/usr": "deny", // 拒绝访问 /usr
      "~/Downloads": "allow" // 允许访问 Downloads
    }
  }
}
```

#### 权限评估流程

```
┌─────────────────────────────────────────────────────────────┐
│              权限评估流程                                │
├─────────────────────────────────────────────────────────────┤
│                                                     │
│  1. 工具调用准备                                      │
│     └─> agent.invokeTool(toolName, args)              │
│                                                     │
│  2. 提取相关规则                                       │
│     └─> 扫描 agent.permission + session.permission      │
│                                                     │
│  3. 模式匹配                                          │
│     └─> 使用 Wildcard 匹配 pattern                   │
│     └─> 找到最具体的匹配规则                          │
│                                                     │
│  4. 动作决定                                          │
│     └─> 如果是 allow -> 继续执行                      │
│     └─> 如果是 deny -> 返回权限拒绝错误                │
│     └─> 如果是 ask -> 发送权限请求给客户端             │
│                                                     │
│  5. 用户交互（仅 ask 动作）                            │
│     └─> 客户端显示权限请求                          │
│     └─> 用户选择: once | always | reject            │
│     └─> 将响应发送回服务器                           │
│                                                     │
│  6. 结果处理                                          │
│     └─> once: 执行一次，不保存决定                  │
│     └─> always: 执行并保存为永久规则                  │
│     └─> reject: 返回拒绝错误                        │
│                                                     │
└─────────────────────────────────────────────────────────────┘
```

#### 权限请求事件

```typescript
// packages/opencode/src/permission/next.ts

  id: string // 请求 ID
  sessionID: string // 会话 ID
  permission: string // 权限名称
  patterns: string[] // 匹配的模式

  always: string[] // 永久允许的模式

    // 工具相关信息

  }
}
```

### 6. MCP 集成 (MCP Integration)

MCP (Model Context Protocol) 允许 OpenCode 连接到外部服务器，使用额外的工具和资源。

#### MCP 传输类型

| 传输类型  | 使用场景                    |
| --------- | --------------------------- |
| **HTTP**  | 远程 MCP 服务器（REST API） |
| **SSE**   | 服务器推送事件（流式数据）  |
| **Stdio** | 本地进程（标准输入/输出）   |

#### MCP 客户端初始化

```typescript
// packages/opencode/src/mcp/index.ts
import { Client } from "@modelcontextprotocol/sdk/client/index.js"
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js"

// 创建 stdio 传输
const transport = new StdioClientTransport({
```

```typescript
// packages/opencode/src/lsp/
import * as rpc from "vscode-jsonrpc"

class LSPClient {
  private connection: rpc.MessageConnection

  async connect(command: string, args: string[]) {
    const serverProcess = spawn(command, args)

    this.connection = rpc.createMessageConnection(
      new rpc.StreamMessageReader(serverProcess.stdout),
      new rpc.StreamMessageWriter(serverProcess.stdin),
```

## 高层设计决策

### 1. 为什么选择客户端-服务器架构？

**优势**:

- ✅ **多客户端支持**: TUI、Web、Desktop 共享同一后端
- ✅ **远程访问**: 可以在不同设备上访问同一会话
- ✅ **集中管理**: 配置、会话、权限集中存储
- ✅ **资源隔离**: 服务器可以独立部署和扩展
- ✅ **API 可复用**: 第三方应用可以通过 API 集成

**权衡**:

- ❌ 增加网络延迟
- ❌ 需要服务器进程
- ❌ 离线能力受限

### 2. 为什么使用 Hono 框架？

**优势**:

- ✅ **轻量级**: 小体积，快速启动
- ✅ **TypeScript 原生支持**: 完整类型推导
- ✅ **中间件生态**: 丰富的中间件（CORS、认证等）
- ✅ **SSE 原生支持**: 内置 `streamSSE`
- ✅ **高性能**: 优化的路由和处理

**权衡**:

- ❌ 生态不如 Express 完善
- ❌ 相对较新的框架

### 3. 为什么使用基于代理的设计？

**优势**:

- ✅ **专业化**: 不同代理针对不同任务优化
- ✅ **权限隔离**: 每个代理有独立权限
- ✅ **可扩展**: 用户可创建自定义代理
- ✅ **可组合**: 主代理可以调用子代理

**权衡**:

- ❌ 增加系统复杂度
- ❌ 需要管理多个代理配置

### 4. 为什么采用细粒度权限系统？

**优势**:

- ✅ **安全性**: 用户对每个操作有完全控制
- ✅ **灵活性**: 可以为不同代理、文件设置不同权限
- ✅ **透明性**: 所有权限请求都可见
- ✅ **可学习**: 用户可以永久授权常用操作

**权衡**:

- ❌ 增加交互成本（频繁确认）
- ❌ 配置复杂度高

### 5. 为什么选择 MCP 协议？

**优势**:

- ✅ **标准化**: 官方协议，生态不断完善
- ✅ **互操作性**: 可连接多种 MCP 服务器
- ✅ **扩展性**: 轻松添加新工具和资源
- ✅ **认证支持**: 内置 OAuth 流程

**权衡**:

- ❌ 依赖外部服务器
- ❌ 增加网络依赖

### 6. 为什么选择 Vercel AI SDK？

**优势**:

- ✅ **统一接口**: 支持多个 AI 提供商
- ✅ **流式支持**: 原生流式对象生成
- ✅ **工具调用**: 内置工具调用支持
- ✅ **类型安全**: 完整 TypeScript 类型

**权衡**:

- ❌ 抽象层可能隐藏提供商特性
- ❌ 依赖第三方库

### 7. 为什么使用事件总线架构？

**优势**:

- ✅ **解耦**: 组件间松耦合
- ✅ **可扩展**: 轻松添加新事件订阅者
- ✅ **可测试**: 可以模拟事件进行测试

**权衡**:

- ❌ 调试难度增加（异步、事件流）
- ❌ 需要管理订阅者生命周期

## 架构权衡

### 1. 性能 vs 安全性

**权限检查**:

- 每个工具调用都需要权限评估
- **权衡**: 增加延迟，但确保安全

**解决方案**:

- 缓存权限评估结果
- 使用高效的通配符匹配算法

### 2. 灵活性 vs 复杂性

**代理系统**:

- 支持自定义代理、子代理调用
- **权衡**: 高灵活性，但增加理解和维护成本

**缓解措施**:

- 提供清晰文档和示例
- 默认代理覆盖常见场景

### 3. 本地 vs 远程执行

**工具执行**:

- 工具在服务器执行（本地），AI 提供商在云端
- **权衡**: 文件操作快速，但 AI 响应有网络延迟

**优化**:

- 并行执行多个工具
- 使用流式响应减少等待时间

### 4. 同步 vs 异步

**API 设计**:

- 主 API 使用异步 SSE 推送响应
- **权衡**: 更好的实时性，但增加客户端复杂度

**优势**:

- 实时进度反馈
- 支持长时间运行任务
- 可以中断操作

### 5. 内存 vs 持久化

**会话存储**:

- 消息存储在磁盘，但在内存中缓存
- **权衡**: 启动快速，但内存占用较高

**优化**:

- 会话压缩（定期合并旧消息）
- 按需加载历史

### 6. 单体 vs 微服务

**架构选择**:

- OpenCode 是单体架构（单一服务器进程）
- **权衡**: 简单部署，但扩展性有限

**未来方向**:

- 可以拆分为多个微服务（会话、工具、权限等）
- 支持水平扩展

这种架构使 OpenCode 既适合个人开发者快速上手，也能满足团队协作和复杂场景的需求。随着生态的发展，OpenCode 将持续演进，为用户提供更强大、更安全的 AI 编码助手体验。
