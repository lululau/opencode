## 概述

本文档提供了 OpenCode 中所有错误代码的完整参考。每个错误代码包含：

- **错误名称**：错误的唯一标识符
- **错误原因**：错误发生的原因
- **错误上下文**：错误发生的上下文信息
- **解决方案**：修复错误的建议步骤
- **预防措施**：避免错误再次发生的方法

**错误类型系统：**

OpenCode 使用 `NamedError` 基类创建结构化错误：

```typescript
// 错误结构
interface NamedError {
  name: string // 错误名称
  data: {
    // 错误数据
    // 特定于错误类型的字段
  }
  cause?: Error // 原始错误（如果有的话）
}

// 错误示例
Provider.ModelNotFoundError({
  providerID: "anthropic",
  modelID: "gpt-5",
  suggestions: ["claude-3-5-sonnet-20241022"],
})
```

## Provider 错误

### Provider.ModelNotFoundError

**错误名称：** `Provider.ModelNotFoundError`

**错误原因：**

- 指定的 provider/model 组合不存在
- 模型 ID 拼写错误
- 模型已被弃用或重命名

**错误上下文：**

```typescript
{
  providerID: string,      // 提供商 ID
  modelID: string,        // 模型 ID
  suggestions: string[]    // 建议的替代模型
}
```

**示例：**

```
Error: Model not found: openai/gpt-5

Try: opencode models

Suggested models:
- openai/gpt-4-turbo
- openai/gpt-3.5-turbo
```

**解决方案：**

1. **列出可用模型：**

   ```bash
   opencode models
   ```

2. **验证模型格式：**

   ```bash
   # 正确格式：provider/model
   openai/gpt-4-turbo
   anthropic/claude-3-5-sonnet-20241022
   ```

3. **更新配置：**

   ```bash
   opencode config set models.default "anthropic/claude-3-5-sonnet-20241022"
   ```

4. **检查提供商文档：**
   - [Anthropic Models](https://docs.anthropic.com/claude/docs/models-overview)
   - [OpenAI Models](https://platform.openai.com/docs/models)

**预防措施：**

- ✅ 使用 `opencode models` 验证模型
- ✅ 从提供商文档复制准确的模型 ID
- ✅ 避免使用 "最新" 或 "best" 模型引用
- ✅ 定期更新 OpenCode 获取最新模型

### Provider.InitError

**错误名称：** `Provider.InitError`

**错误原因：**

- Provider 初始化失败
- API Key 无效或缺失
- 网络连接问题
- Provider 服务不可用

**错误上下文：**

```typescript
{
  providerID: string,     // 提供商 ID
  cause?: Error          // 原始错误
}
```

**示例：**

```
Error: Failed to initialize provider 'anthropic'

Cause: Invalid API key
```

**解决方案：**

1. **验证 API Key：**

   ```bash
   # 测试 API Key
   curl https://api.anthropic.com/v1/models \
     -H "x-api-key: $ANTHROPIC_API_KEY"
   ```

2. **重新配置 API Key：**

   ```bash
   opencode auth add
   # 选择 provider 并输入新的 API Key
   ```

3. **检查网络连接：**

   ```bash
   ping api.anthropic.com
   ping api.openai.com
   ```

4. **检查服务状态：**
   - [Anthropic Status](https://status.anthropic.com/)
   - [OpenAI Status](https://status.openai.com/)

**预防措施：**

- ✅ 定期轮换 API Keys
- ✅ 在生产环境使用环境变量存储密钥
- ✅ 监控提供商服务状态页面
- ✅ 实现重试逻辑（已内置）

### Provider.ModelInitError

**错误名称：** `Provider.ModelInitError`

**错误原因：**

- 模型特定初始化失败
- 模型参数无效
- 模型访问权限不足

**解决方案：**

1. **检查模型访问权限：**

   ```bash
   # 某些模型需要特殊权限
   opencode models | grep "enterprise"
   ```

2. **验证模型参数：**

   ```bash
   opencode config get models.default
   ```

3. **降级到标准模型：**
   ```bash
   opencode config set models.default "anthropic/claude-3-haiku-20240307"
   ```

## Config 错误

### Config.JsonError

**错误名称：** `Config.JsonError`

**错误原因：**

- 配置文件不是有效的 JSON
- JSON 语法错误
- 文件编码问题

**错误上下文：**

```typescript
{
  path: string,          // 配置文件路径
  message: string       // 错误消息
}
```

**示例：**

```
Error: Config file at ~/.opencode/config.json is not valid JSON(C):
Unexpected token } in JSON at position 123
```

**解决方案：**

1. **验证 JSON：**

   ```bash
   # 使用 jq
   cat ~/.opencode/config.json | jq .

   # 或使用在线工具
   # https://jsonlint.com/
   ```

2. **修复常见错误：**

   ```json
   // ❌ 错误：末尾逗号
   {
     "key": "value",
   }

   // ✅ 正确
   {
     "key": "value"
   }

   // ❌ 错误：单引号
   {
     'key': 'value'
   }

   // ✅ 正确
   {
     "key": "value"
   }
   ```

3. **创建新配置：**

   ```bash
   # 备份旧配置
   mv ~/.opencode/config.json ~/.opencode/config.json.backup

   # 创建新配置
   opencode config init
   ```

**预防措施：**

- ✅ 使用 JSON 验证器编辑配置
- ✅ 使用 `opencode config set` 而不是手动编辑
- ✅ 在版本控制中管理配置
- ✅ 使用 JSON5 支持（支持注释）的编辑器

### Config.InvalidError

**错误名称：** `Config.InvalidError`

**错误原因：**

- 配置字段值无效
- 配置结构不正确
- 缺少必需字段

**错误上下文：**

```typescript
{
  path: string,          // 配置路径
  message: string,       // 错误消息
  issues: ZodIssue[]     // 验证问题列表
}
```

**示例：**

```
Error: Invalid configuration

Issues:
- Field 'models.default' is required
- Field 'agent.max_tokens' must be a number
```

**解决方案：**

1. **检查配置：**

   ```bash
   opencode config check
   ```

2. **修复特定字段：**

   ```bash
   opencode config set models.default "anthropic/claude-3-5-sonnet-20241022"
   opencode config set agent.max_tokens 4096
   ```

3. **查看默认配置：**
   ```bash
   opencode config init --force
   ```

**预防措施：**

- ✅ 使用 `opencode config check` 验证
- ✅ 遵循配置文档中的类型
- ✅ 使用环境变量覆盖敏感值
- ✅ 定期备份配置

### Config.ConfigDirectoryTypoError

**错误名称：** `Config.ConfigDirectoryTypoError`

**错误原因：**

- 配置目录名称拼写错误
- 目录不存在

**错误上下文：**

```typescript
{
  dir: string,          // 错误的目录名
  path: string,         // 配置文件路径
  suggestion: string     // 建议的正确目录名
}
```

**示例：**

```
Error: Possible typo in config directory 'providors'

Did you mean 'providers'?

Config file: ~/.opencode/providors/anthropic.json
```

**解决方案：**

1. **重命名目录：**

   ```bash
   mv ~/.opencode/providors ~/.opencode/providers
   ```

2. **验证配置：**
   ```bash
   opencode config check
   ```

**预防措施：**

- ✅ 使用 `opencode config add` 创建配置
- ✅ 参考文档中的目录名
- ✅ 启用配置拼写检查（如果可用）

## Session 错误

### Session.BusyError

**错误名称：** `Session.BusyError`

**错误原因：**

- 会话正在处理请求
- 一次只能处理一个请求

**错误上下文：**

```typescript
{
  sessionID: string // 会话 ID
}
```

**示例：**

```
Error: Session is currently processing a request

Session ID: abc123
```

**解决方案：**

1. **等待当前请求完成：**

   ```bash
   # 查看会话状态
   opencode session show abc123
   ```

2. **创建新会话：**

   ```bash
   opencode session fork abc123
   ```

3. **检查状态：**
   ```bash
   tail -f ~/.local/share/opencode/logs/dev.log | grep "session.*status"
   ```

**预防措施：**

- ✅ 避免在处理中使用同一会话
- ✅ 为不同任务使用不同会话
- ✅ 监控会话状态

### Session.AbortedError

**错误名称：** `MessageV2.AbortedError`

**错误原因：**

- 用户取消操作
- 超时导致中止
- AbortSignal 触发

**解决方案：**

1. **重试操作：**

   ```bash
   opencode session continue abc123
   ```

2. **增加超时时间：**
   ```bash
   opencode config set agent.timeout 120000
   ```

### Session.APIError

**错误名称：** `MessageV2.APIError`

**错误原因：**

- Provider API 调用失败
- 网络错误
- API 限制

**错误上下文：**

```typescript
{
  message: string,
  statusCode: number,          // HTTP 状态码
  isRetryable: boolean,        // 是否可重试
  responseHeaders?: {
    "retry-after"?: string,   // 重试延迟
    "retry-after-ms"?: number
  },
  responseBody?: string,
  metadata?: Record<string, any>
}
```

**示例：**

```
Error: API call failed

Status: 429 (Too Many Requests)
Retryable: true
Retry-After: 60s

Message: Rate limit exceeded
```

**解决方案：**

1. **检查状态码：**
   - 429: 等待 `retry-after` 时间
   - 500+: 重试（已内置重试逻辑）
   - 400: 检查请求参数

2. **等待并重试：**

   ```bash
   # 系统会自动重试可重试的错误
   # 可以手动重试不可重试的错误
   ```

3. **检查限制：**
   ```bash
   # 查看提供商限制
   opencode provider limits anthropic
   ```

**预防措施：**

- ✅ 实现请求节流
- ✅ 监控 API 使用量
- ✅ 使用合理的请求频率
- ✅ 实现退避策略（已内置）

## Permission 错误

### Permission.DeniedError

**错误名称：** `Permission.DeniedError`

**错误原因：**

- 权限规则拒绝操作
- 权限不匹配

**错误上下文：**

```typescript
{
  ruleset: Permission[]   // 拒绝的权限规则
}
```

**示例：**

```
Error: Permission denied

Denied by rules:
- Action: bash
- Pattern: rm -rf *
```

**解决方案：**

1. **检查权限规则：**

   ```bash
   opencode config get permission
   ```

2. **更新权限规则：**

   ```json
   {
     "permission": [
       {
         "action": "allow",
         "permission": "bash",
         "patterns": ["npm install", "git status"]
       }
     ]
   }
   ```

3. **切换代理：**
   ```bash
   opencode agent switch build  // 完全访问
   opencode agent switch plan   // 只读
   ```

### Permission.RejectedError

**错误名称：** `Permission.RejectedError`

**错误原因：**

- 用户手动拒绝权限请求
- 权限提示被取消

**解决方案：**

1. **重新请求权限：**

   ```bash
   # 系统会再次提示
   ```

2. **配置自动允许：**
   ```json
   {
     "permission": [
       {
         "action": "allow",
         "permission": "bash",
         "patterns": ["*"] // 自动允许所有
       }
     ]
   }
   ```

### Permission.CorrectedError

**错误名称：** `Permission.CorrectedError`

**错误原因：**

- 权限请求被自动纠正
- 规则匹配到更安全的操作

**解决方案：**

1. **查看纠正的权限：**

   ```bash
   # 查看日志
   tail -f ~/.local/share/opencode/logs/dev.log | grep Permission
   ```

2. **如果不正确，更新规则：**
   ```bash
   opencode config edit permission
   ```

## 解决方案和预防

### 通用错误处理策略

#### 2. 重试策略

```typescript
// 自动重试可重试的错误
async function withRetry<T>(fn: () => Promise<T>): Promise<T> {
  let attempt = 0
  const maxAttempts = 3

  while (attempt < maxAttempts) {
    try {
      return await fn()
    } catch (error) {
      attempt++
      if (attempt >= maxAttempts || !isRetryable(error)) {
        throw error
      }
      const delay = Math.pow(2, attempt) * 1000 // 指数退避
      await sleep(delay)
    }
  }
}
```
