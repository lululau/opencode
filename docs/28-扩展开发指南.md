## 概述

OpenCode 支持多种扩展类型，为开发者提供灵活的方式来扩展系统功能。扩展包括插件、代理、命令和 SDK 集成，每种类型都有特定的清单格式和分发机制。

### 扩展架构

```
OpenCode 扩展生态
│
├─ 插件 (Plugins)
│   ├─ TypeScript/JavaScript 模块
│   ├─ 直接访问 API
│   └─ 通过 config.plugin 配置
│
├─ 代理 (Agents)
│   ├─ Markdown 文件 (.opencode/agent/*.md)
│   ├─ YAML frontmatter + Markdown 内容
│   └─ 定义行为、权限、提示词
│
├─ 命令 (Commands)
│   ├─ Markdown 文件 (.opencode/command/*.md)
│   ├─ 模板化提示词
│   └─ 快捷执行常见任务
│
└─ 编辑器扩展 (Editor Extensions)
    ├─ Zed: extension.toml
    ├─ VSCode: package.json
    └─ ACP (Agent Client Protocol): 原生支持
```

## 扩展类型

### 1. 插件 (Plugins)

插件是最强大的扩展类型，提供完整的编程接口。

**特性**:

- ✅ TypeScript/JavaScript 编写
- ✅ 直接访问 OpenCode API
- ✅ 自定义工具注册
- ✅ 事件和钩子订阅
- ✅ 认证方法扩展

**适用场景**:

- 集成外部服务 API
- 实现自定义认证
- 添加复杂工具（如数据库查询、Web 请求）
- 监听和响应系统事件

**代码位置**: `/packages/plugin/src/index.ts`

### 2. 代理 (Agents)

代理是行为配置，定义 AI 如何响应特定类型的任务。

**特性**:

- ✅ Markdown + YAML frontmatter
- ✅ 独立权限规则
- ✅ 自定义系统提示词
- ✅ 模型和参数配置
- ✅ 可作为主代理或子代理

**适用场景**:

- 专业化任务（如代码审查、文档生成）
- 只读/只写代理
- 特定技术栈的专家代理

**代码位置**: `/packages/opencode/src/config/config.ts:279-317`

### 3. 命令 (Commands)

命令是预定义的提示词模板，用于快速执行常见任务。

**特性**:

- ✅ Markdown + YAML frontmatter
- ✅ 模板化内容
- ✅ 可指定代理和模型
- ✅ 支持参数占位符

**适用场景**:

- 快速执行重复性任务
- 团队共享最佳实践
- 复杂操作的单键触发

**代码位置**: `/packages/opencode/src/config/config.ts:240-277`

### 4. 编辑器扩展 (Editor Extensions)

扩展 OpenCode 到各种编辑器和 IDE。

#### Zed 扩展

使用 ACP (Agent Client Protocol) 集成。

**清单格式**: TOML

**文件示例**: `/packages/extensions/zed/extension.toml`

```toml
id = "opencode"
name = "OpenCode"
description = "The open source coding agent."
version = "1.1.31"

[agent_servers.opencode]
name = "OpenCode"
icon = "./icons/opencode.svg"

[agent_servers.opencode.targets.darwin-aarch64]
archive = "https://github.com/anomalyco/opencode/releases/download/v1.1.31/opencode-darwin-arm64.zip"
cmd = "./opencode"
args = ["acp"]
```

#### VSCode 扩展

使用 Language Server Protocol 或 ACP。

**清单格式**: JSON (package.json)

```json
{
  "name": "opencode-vscode",
  "displayName": "OpenCode",
  "version": "1.0.0",
  "engines": {
    "vscode": "^1.80.0"
  },
  "contributes": {
    "commands": [...],
    "languages": [...]
  }
}
```

## 扩展清单格式

### 插件清单

**重要**: 插件**没有清单文件**。插件本身就是导出的函数。

**文件结构**:

```
my-plugin/
├── package.json          # npm 包清单
├── tsconfig.json
├── src/
│   └── index.ts        # 插件入口
└── dist/               # 编译输出
```

**package.json**:

```json
{
  "name": "my-opencode-plugin",
  "version": "1.0.0",
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "peerDependencies": {
    "@opencode-ai/plugin": "workspace:*"
  },
  "exports": {
    ".": "./dist/index.js"
  }
}
```

### 代理清单

代理使用 **Markdown 文件**，包含 YAML frontmatter。

**位置**: `.opencode/agent/*.md` 或 `.opencode/agents/**/*.md`

**示例**:

```markdown
---
name: code-reviewer
description: Review code for bugs, security issues, and best practices
mode: primary
model: anthropic/claude-sonnet-4
temperature: 0.1
permission:
  read: allow
  edit: ask
  bash: deny
color: "#FF5733"
---

You are a meticulous code reviewer. When reviewing code:

1. **Security**: Check for common vulnerabilities (XSS, SQL injection, etc.)
2. **Correctness**: Look for logic errors and edge cases
3. **Performance**: Identify inefficient algorithms or unnecessary computations
4. **Style**: Ensure adherence to project conventions
5. **Documentation**: Verify that changes are properly documented

Always provide:

- A summary of issues found
- Severity levels (critical, high, medium, low)
- Suggested fixes with code examples
```

**字段说明**:

| 字段          | 类型       | 必填 | 描述                                   |
| ------------- | ---------- | ---- | -------------------------------------- | ---------- | ----- |
| `name`        | string     | ✅   | 代理名称（唯一标识符）                 |
| `description` | string     | ❌   | 代理描述，显示在 UI 中                 |
| `mode`        | enum       | ❌   | `primary`                              | `subagent` | `all` |
| `model`       | string     | ❌   | 默认模型（provider/model 格式）        |
| `temperature` | number     | ❌   | 温度参数 (0-1)                         |
| `top_p`       | number     | ❌   | Top P 参数                             |
| `steps`       | number     | ❌   | 最大执行步骤数                         |
| `permission`  | Permission | ❌   | 权限规则                               |
| `color`       | string     | ❌   | UI 显示的颜色（hex 格式）              |
| `hidden`      | boolean    | ❌   | 是否在 @ 自动完成中隐藏（仅 subagent） |
| `disable`     | boolean    | ❌   | 是否禁用此代理                         |

### 命令清单

命令同样使用 **Markdown 文件**。

**位置**: `.opencode/command/*.md` 或 `.opencode/commands/**/*.md`

**示例**:

```markdown
---
name: fix-tests
description: Fix failing tests
agent: build
model: anthropic/claude-sonnet-4
subtask: false
---

Please analyze and fix the failing tests:

1. Run tests: `bun test`
2. Identify which tests are failing
3. Examine the error messages
4. Fix the underlying issues
5. Re-run tests to verify

Focus on the root cause rather than just making the tests pass by modifying assertions.
```

**字段说明**:

| 字段          | 类型    | 必填 | 描述               |
| ------------- | ------- | ---- | ------------------ |
| `name`        | string  | ✅   | 命令名称           |
| `description` | string  | ❌   | 命令描述           |
| `agent`       | string  | ❌   | 执行命令的代理     |
| `model`       | string  | ❌   | 使用的模型         |
| `subtask`     | boolean | ❌   | 是否作为子任务执行 |

## 扩展打包与分发

### npm 包分发（插件）

插件作为 npm 包分发是最常见的方式。

#### 打包流程

```bash
# 1. 初始化项目
npm init -y
npm install -D typescript @opencode-ai/plugin

# 2. 创建插件代码
# src/index.ts
export const MyPlugin: Plugin = async (input) => { ... }

# 3. 编译
npx tsc

# 4. 发布
npm publish
```

#### 用户安装

```json
// ~/.config/opencode/opencode.json
{
  "plugin": ["my-opencode-plugin@1.0.0", "@scope/another-plugin@^2.0.0"]
}
```

**OpenCode 会自动**:

1. 下载并安装到 `node_modules`
2. 动态导入插件模块
3. 调用插件函数获取 Hooks
4. 注册工具和钩子

### 本地文件分发

插件可以从本地文件系统加载。

#### 配置方式

```json
{
  "plugin": ["file:///absolute/path/to/plugin.js", "file:///absolute/path/to/another-plugin.ts"]
}
```

#### 自动发现

将 `.ts` 或 `.js` 文件放在以下目录，会自动被发现：

```
.opencode/plugin/
  ├── my-tool.ts
  └── another-tool.js
```

**代码位置**: `/packages/opencode/src/config/config.ts:356-369`

```typescript
const PLUGIN_GLOB = new Bun.Glob("{plugin,plugins}/*.{ts,js}")

async function loadPlugin(dir: string) {
  const plugins: string[] = []

  for await (const item of PLUGIN_GLOB.scan({ cwd: dir })) {
    plugins.push(pathToFileURL(item).href)
  }
  return plugins
}
```

### 依赖管理

#### 项目级依赖

`.opencode/package.json` 文件允许项目使用特定的依赖。

**代码位置**: `/packages/opencode/src/config/config.ts:204-225`

```typescript
export async function installDependencies(dir: string) {
  const pkg = path.join(dir, "package.json")
  await Bun.write(pkg, "{}")

  const gitignore = path.join(dir, ".gitignore")
  await Bun.write(gitignore, ["node_modules", "package.json", "bun.lock", ".gitignore"].join("\n"))

  // 安装 @opencode-ai/plugin 作为开发依赖
  await BunProc.run(["add", "@opencode-ai-plugin@latest", "--exact"], { cwd: dir })

  // 安装用户定义的依赖
  await BunProc.run(["install"], { cwd: dir })
}
```

插件可以声明自己的依赖：

```json

    "axios": "^1.6.0",
    "openai": "^4.20.0"
  }
}
```

OpenCode 会自动安装这些依赖到 `node_modules`。

## 安全模型与权限

### 权限系统

OpenCode 使用细粒度的权限系统，控制扩展可以执行的操作。

**代码位置**: `/packages/opencode/src/config/config.ts:486-551`

#### 权限动作

| 动作    | 描述                   |
| ------- | ---------------------- |
| `allow` | 允许操作，无需用户确认 |
| `deny`  | 拒绝操作               |
| `ask`   | 请求用户确认           |

#### 权限规则

```typescript
type PermissionRule = "allow" | "deny" | "ask" | Record<string, PermissionRule>

type Permission = {
  read?: PermissionRule
  edit?: PermissionRule
  bash?: PermissionRule
  glob?: PermissionRule
  grep?: PermissionRule
  webfetch?: PermissionRule
  websearch?: PermissionRule
  // ... 更多权限
}
```

#### 示例配置

```json
{
  "permission": {
    "read": "allow",
    "edit": {
      "*": "allow",
      "*.env": "ask",
      "*.example": "allow"
    },
    "bash": {
      "scripts/*": "allow",
      "*": "ask"
    },
    "webfetch": "allow",
    "websearch": "ask"
  }
}
```

### 扩展权限

插件可以通过钩子修改权限决策。

#### permission.ask 钩子

```typescript
const Plugin: Plugin = async (input) => {
  return {
    async "permission.ask"(input, output) {
      // 读取特定文件时自动允许
      if (input.permission === "read" && input.patterns.some((p) => p.endsWith(".md"))) {
        output.status = "allow"
      }

      // 危险操作始终询问
      if (input.permission === "bash" && input.patterns.some((p) => p.includes("rm -rf"))) {
        output.status = "deny"
      }
    },
  }
}
```

### 模式匹配

权限规则支持通配符模式匹配。

**支持的模式**:

```bash
# 通配符
*           # 匹配任意路径
**          # 匹配任意子目录
*.ts        # 匹配所有 .ts 文件
src/**/*.ts  # 匹配 src 下所有 .ts 文件
.env*       # 匹配 .env, .env.local 等

# 特定文件
package.json
README.md
src/index.ts
```

**匹配优先级**:

```
1. 最具体的模式优先
2. 后定义的规则覆盖先定义的
3. deny 优先级高于 ask
```

### 用户审批流程

当扩展需要执行权限为 `ask` 的操作时：

```
┌─────────────────────────────────────────────┐
│          用户审批流程                       │
├─────────────────────────────────────────────┤
│                                         │
│  1. 扩展请求权限                          │
│     └─> ctx.ask({ permission, patterns })   │
│                                         │
│  2. OpenCode 显示权限请求对话框              │
│     └─> "Allow <agent> to <action>?"     │
│     └─> 显示匹配的模式                      │
│                                         │
│  3. 用户选择                              │
│     ├─ Once: 允许此次操作                  │
│     ├─ Always: 永久允许此模式              │
│     └─ Reject: 拒绝操作                  │
│                                         │
│  4. 结果处理                              │
│     ├─ Once: 执行操作                      │
│     ├─ Always: 执行并保存到配置            │
│     └─ Reject: 返回权限错误                │
│                                         │
└─────────────────────────────────────────────┘
```

### 代理特定权限

代理可以定义自己的权限规则，与全局权限合并。

**代码位置**: `/packages/opencode/src/config/config.ts:562-642`

```markdown
---
name: safe-reviewer
mode: primary
permission:
  read: allow
  edit: deny
  bash: deny
---

You are a read-only code reviewer...
```

**合并顺序**:

```
最终权限 = Merge(全局权限, 代理权限)
```

**合并规则**:

- 代理权限优先
- `deny` 覆盖 `allow`
- `ask` 覆盖 `allow`

## 扩展发现与加载顺序

### 扫描目录

OpenCode 在以下目录扫描扩展：

**代码位置**: `/packages/opencode/src/config/config.ts:102-149`

```typescript
const directories = [
  Global.Path.config, // ~/.config/opencode
  // 项目 .opencode/ 目录（从项目目录到工作树根）
  ...(!Flag.OPENCODE_DISABLE_PROJECT_CONFIG
    ? await Array.fromAsync(
        Filesystem.up({
          targets: [".opencode"],
          start: Instance.directory,
          stop: Instance.worktree,
        }),
      )
    : []),
  // 全局 ~/.opencode/
  ...(await Array.fromAsync(
    Filesystem.up({
      targets: [".opencode"],
      start: Global.Path.home,
      stop: Global.Path.home,
    }),
  )),
]
```

### 加载顺序

#### 配置文件加载顺序（从低到高优先级）

1. **Remote well-known config** (`https://domain/.well-known/opencode`)
   - 组织提供的默认配置
   - 最低优先级

2. **Global config** (`~/.config/opencode/opencode.json`)
   - 用户全局配置
   - 可以覆盖远程配置

3. **Custom config path** (`OPENCODE_CONFIG` 环境变量)
   - 用户指定的配置文件
   - 覆盖全局配置

4. **Project config** (`opencode.json` / `opencode.jsonc`)
   - 从项目目录向上查找
   - 最高文件优先级

5. **Inline config content** (`OPENCODE_CONFIG_CONTENT` 环境变量)
   - 内联 JSON 配置
   - 最高优先级

#### 扩展类型加载顺序

```
1. 内置插件 (INTERNAL_PLUGINS)
2. 配置文件中的插件 (config.plugin)
3. .opencode/plugin/ 目录中的插件
4. .opencode/agent/ 目录中的代理
5. .opencode/command/ 目录中的命令
```

### 合并策略

**数组字段**: 连接而非替换

**代码位置**: `/packages/opencode/src/config/config.ts:36-44`

```typescript
function mergeConfigConcatArrays(target: Info, source: Info): Info {
  const merged = mergeDeep(target, source)

  // 插件列表合并（去重）
  if (target.plugin && source.plugin) {
    merged.plugin = Array.from(new Set([...target.plugin, ...source.plugin]))
  }

  // 指令列表合并（去重）
  if (target.instructions && source.instructions) {
    merged.instructions = Array.from(new Set([...target.instructions, ...source.instructions]))
  }

  return merged
}
```

**对象字段**: 深度合并

```typescript
// target
{
  "agent": {
    "build": { "temperature": 0.7 }
  }
}

// source
{
  "agent": {
    "build": { "steps": 10 },
    "reviewer": { "temperature": 0.1 }
  }
}

// merged
{
  "agent": {
    "build": { "temperature": 0.7, "steps": 10 },
    "reviewer": { "temperature": 0.1 }
  }
}
```

## 代码示例

### 创建插件（NPM 包）

**1. 初始化项目**

```bash
mkdir my-opencode-plugin
cd my-opencode-plugin
npm init -y
npm install -D typescript @opencode-ai/plugin
npm install zod
```

**2. 创建插件**

```typescript
// src/index.ts
import type { Plugin, ToolDefinition } from "@opencode-ai/plugin"
import z from "zod"

export const MyPlugin: Plugin = async (input) => {
  return {
    tool: {
      weather: {
        description: "Get current weather for a location",
        parameters: z.object({
          location: z.string().describe("City name or coordinates"),
        }),
        async execute(args, ctx) {
          const response = await fetch(`https://api.weather.com/current?location=${encodeURIComponent(args.location)}`)
          const data = await response.json()

          return {
            title: `Weather for ${args.location}`,
            output: JSON.stringify(data, null, 2),
            metadata: { location: args.location },
          }
        },
      } satisfies ToolDefinition,
    },
  }
}

export default MyPlugin
```

**3. 编译并发布**

```bash
npx tsc
npm publish
```

**4. 用户安装**

```json
{
  "plugin": ["my-opencode-plugin@1.0.0"]
}
```

### 创建 Zed 扩展

**文件**: `extension.toml`

```toml
[package]
name = "my-opencode-extension"
description = "Custom OpenCode integration"
version = "0.1.0"
authors = ["Your Name"]
repository = "https://github.com/user/repo"

[agent_servers.my-extension]
name = "My Extension"
icon = "./icons/extension.svg"

[agent_servers.my-extension.targets.darwin-aarch64]
archive = "https://github.com/user/repo/releases/download/v0.1.0/extension-darwin-arm64.zip"
cmd = "./my-extension"
args = ["acp"]
```

### 多类型扩展组合

一个项目可以包含多种扩展类型：

```
.my-extension/
├── extension.toml           # Zed 扩展清单
├── package.json             # npm 包清单（用于插件）
├── src/
│   └── index.ts            # 插件代码
├── opencode.json           # OpenCode 配置
└── .opencode/
    ├── agent/
    │   └── my-agent.md     # 代理定义
    ├── command/
    │   └── my-command.md   # 命令定义
    └── plugin/
        └── local-tool.ts   # 本地插件
```

## 最佳实践

### 1. 扩展命名

**插件（npm 包）**:

```bash
my-opencode-plugin          # 好的命名
@scope/opencode-feature    # 作用域包
```

**代理和命令**:

```bash
code-reviewer              # kebab-case
database-migrator         # 描述性
```

**Zed 扩展**:

```toml
id = "my-opencode-extension"
```

### 2. 版本管理

使用语义化版本：

```json
{
  "version": "1.2.3"
  // ^ 主版本：不兼容的 API 变更
  // | 次版本：向后兼容的功能新增
  // | 补丁：向后兼容的问题修复
}
```

### 3. 权限最小化

只请求必要的权限：

```json
{
  "permission": {
    "read": "allow",
    "edit": {
      "*.md": "allow",
      "*.ts": "ask"
    },
    "bash": "deny"
  }
}
```

### 4. 文档化

在清单中提供清晰描述：

```markdown
---
name: security-scanner
description: Scan code for security vulnerabilities
  - OWASP Top 10 checks
  - Dependency vulnerability detection
  - Secrets detection
---
```

### 5. 错误处理

在插件中处理所有错误：

```typescript
export const Plugin: Plugin = async (input) => {
  return {
    async event({ event }) {
      try {
        // 插件逻辑
      } catch (error) {
        console.error("Plugin error:", error)
        // 不重新抛出
      }
    },
  }
}
```

### 6. 测试

为扩展编写测试：

```typescript
// test/plugin.test.ts
import { describe, it, expect } from "bun:test"
import { MyPlugin } from "../src/index"

describe("MyPlugin", () => {
  it("should register weather tool", async () => {
    const hooks = await MyPlugin({} as any)
    expect(hooks.tool?.weather).toBeDefined()
  })
})
```

### 7. 依赖管理

明确声明所有依赖：

```json
{
  "dependencies": {
    "axios": "^1.6.0"
  },
  "peerDependencies": {
    "@opencode-ai/plugin": "*"
  },
  "devDependencies": {
    "typescript": "^5.0.0",
    "zod": "^3.0.0"
  }
}
```
