## 架构概述

OpenCode 服务器是整个系统的核心，基于 **Hono** HTTP 框架构建，提供 REST API 和 SSE (Server-Sent Events) 端点，支持多种客户端（TUI、Web、桌面应用）通过 HTTP/WebSocket 进行通信。

### 核心特性

- **高性能**：使用 Bun 运行时，极快的启动和执行速度
- **模块化路由**：每个功能模块独立的路由文件
- **实时通信**：SSE 事件流支持实时更新
- **类型安全**：完整的 TypeScript 类型支持，使用 Zod 验证
- **OpenAPI 集成**：自动生成 API 文档
- **错误处理**：统一的错误处理和格式化

## Hono 框架基础

### 什么是 Hono？

Hono 是一个轻量级、快速的 Web 框架，专为边缘计算和现代 JavaScript 运行时设计。OpenCode 选择 Hono 的原因：

1. **性能优秀**：极快的路由匹配
2. **TypeScript 优先**：完整的类型推导
3. **中间件生态**：丰富的中间件支持
4. **流式响应**：原生支持 SSE 和流式传输
5. **简单易用**：清晰的 API 设计

### Hono 初始化

```typescript
import { Hono } from "hono"

const app = new Hono()

app.get("/hello", (c) => {
  return c.json({ message: "Hello World" })
})
```

### 路由链式调用

Hono 支持链式中间件和路由定义：

```typescript
app
  .use(cors()) // CORS 中间件
  .use(logger()) // 日志中间件
  .get("/api", handler)
  .post("/api", handler)
```

## 中间件系统

OpenCode 服务器使用多个中间件来处理请求、验证、认证和日志。

### 中间件执行顺序

```typescript
app
  .onError(errorHandler) // 1. 错误处理
  .use(basicAuthMiddleware) // 2. Basic Auth
  .use(loggingMiddleware) // 3. 日志记录
  .use(corsMiddleware) // 4. CORS
  .route("/global", routes) // 5. 路由处理
```

### 1. 错误处理中间件

```typescript
.onError((err, c) => {
  log.error("failed", { error: err })

  // 处理命名错误
  if (err instanceof NamedError) {
    let status: ContentfulStatusCode
    if (err instanceof Storage.NotFoundError) status = 404
    else if (err instanceof Provider.ModelNotFoundError) status = 400
    else if (err.name.startsWith("Worktree")) status = 400
    else status = 500
    return c.json(err.toObject(), { status })
  }

  // 处理 HTTP 异常
  if (err instanceof HTTPException) return err.getResponse()

  // 处理未知错误
  const message = err instanceof Error && err.stack ? err.stack : err.toString()
  return c.json(new NamedError.Unknown({ message }).toObject(), {
    status: 500,
  })
})
```

**特点**：

- 捕获所有未处理的错误
- 根据错误类型返回适当的 HTTP 状态码
- 格式化错误响应
- 记录错误日志

### 2. Basic Auth 中间件

```typescript
.use(async (c, next) => {
  const password = Flag.OPENCODE_SERVER_PASSWORD
  if (!password) return next()  // 没有密码则跳过

  const username = Flag.OPENCODE_SERVER_USERNAME ?? "opencode"
  return basicAuth({ username, password })(c, next)
})
```

**特点**：

- 可选的服务器密码保护
- 通过环境变量配置
- 使用 Hono 的 `basicAuth` 中间件

**配置方式**：

```bash
export OPENCODE_SERVER_PASSWORD=your-password
export OPENCODE_SERVER_USERNAME=opencode
```

### 3. 日志中间件

```typescript
.use(async (c, next) => {
  const skipLogging = c.req.path === "/log"
  if (!skipLogging) {
    log.info("request", {
      method: c.req.method,
      path: c.req.path,
    })
  }

  const timer = log.time("request", {
    method: c.req.method,
    path: c.req.path,
  })

  await next()

  if (!skipLogging) {
    timer.stop()  // 记录请求耗时
  }
})
```

**特点**：

- 记录所有请求的方法和路径
- 跳过 `/log` 端点（避免循环）
- 使用性能计时器记录请求耗时

### 4. CORS 中间件

```typescript
.use(
  cors({
    origin(input) {
      if (!input) return

      // 允许 localhost
      if (input.startsWith("http://localhost:")) return input
      if (input.startsWith("http://127.0.0.1:")) return input

      // 允许 Tauri 应用
      if (input === "tauri://localhost" || input === "http://tauri.localhost") return input

      // 允许 *.opencode.ai (仅 HTTPS)
      if (/^https:\/\/([a-z0-9-]+\.)*opencode\.ai$/.test(input)) {
        return input
      }

      // 允许白名单域名
      if (_corsWhitelist.includes(input)) {
        return input
      }

      return undefined  // 拒绝其他来源
    },
  })
)
```

**特点**：

- 开发环境：允许 `localhost` 和 `127.0.0.1`
- 桌面应用：支持 Tauri 协议
- 生产环境：仅允许 `*.opencode.ai` 域名
- 白名单：可通过配置添加额外域名

### 5. 实例上下文中间件

```typescript
.use(async (c, next) => {
  // 从查询参数或 header 获取目录
  let directory =
    c.req.query("directory") ||
    c.req.header("x-opencode-directory") ||
    process.cwd()

  try {
    directory = decodeURIComponent(directory)
  } catch {
    // fallback to original value
  }

  // 使用 Instance.provide 提供项目实例
  return Instance.provide({
    directory,
    init: InstanceBootstrap,
    async fn() {
      return next()
    },
  })
})
```

**特点**：

- 自动解析工作目录
- 支持通过查询参数或 header 传入
- 使用依赖注入模式提供实例

### 路由定义示例

使用 `hono-openapi` 装饰器定义路由：

```typescript
import { Hono } from "hono"
import { describeRoute, validator, resolver } from "hono-openapi"
import z from "zod"

export const ProjectRoutes = lazy(() =>
  new Hono()
    .get(
      "/",
      describeRoute({
        summary: "List all projects",
        description: "Get a list of projects that have been opened with OpenCode.",
        operationId: "project.list",
        responses: {
          200: {
            description: "List of projects",
            content: {
              "application/json": {
                schema: resolver(Project.Info.array()),
              },
            },
          },
        },
      }),
      async (c) => {
        const projects = await Project.list()
        return c.json(projects)
      },
    )
    .get(
      "/current",
      describeRoute({
        summary: "Get current project",
        description: "Retrieve currently active project.",
        operationId: "project.current",
        responses: {
          200: {
            description: "Current project information",
            content: {
              "application/json": {
                schema: resolver(Project.Info),
              },
            },
          },
        },
      }),
      async (c) => {
        return c.json(Instance.project)
      },
    ),
)
```

**关键元素**：

1. **describeRoute**：提供 OpenAPI 文档信息
   - `summary`：简短摘要
   - `description`：详细描述
   - `operationId`：操作 ID
   - `responses`：响应定义

2. **validator**：验证请求参数
   - `"param"`：路径参数验证
   - `"query"`：查询参数验证
   - `"json"`：请求体验证

3. **resolver**：将 Zod schema 转换为 OpenAPI schema

4. **lazy**：延迟加载路由（避免循环依赖）

### 懒加载模式

```typescript

```

`lazy` 函数确保路由模块在使用时才初始化，避免 TypeScript 类型推断问题和循环依赖。

## 事件流系统

### SSE (Server-Sent Events)

SSE 用于服务器向客户端推送实时事件流。

### 事件订阅端点

```typescript
.get(
  "/event",
  describeRoute({
    summary: "Subscribe to events",
    description: "Get events",
    operationId: "event.subscribe",
    responses: {
      200: {
        description: "Event stream",
        content: {
          "text/event-stream": {
            schema: resolver(BusEvent.payloads()),
          },
        },
      },
    },
  }),
  async (c) => {
    log.info("event connected")

    return streamSSE(c, async (stream) => {
      // 发送连接成功事件
      stream.writeSSE({
        data: JSON.stringify({
          type: "server.connected",
          properties: {},
        }),
      })

      // 订阅所有事件
      const unsub = Bus.subscribeAll(async (event) => {
        await stream.writeSSE({
          data: JSON.stringify(event),
        })

        // 收到实例销毁事件时关闭流
        if (event.type === Bus.InstanceDisposed.type) {
          stream.close()
        }
      })

      // 发送心跳包防止超时（WKWebView 默认 60 秒超时）
      const heartbeat = setInterval(() => {
        stream.writeSSE({
          data: JSON.stringify({
            type: "server.heartbeat",
            properties: {},
          }),
        })
      }, 30000)  // 每 30 秒

      // 清理
      await new Promise<void>((resolve) => {
        stream.onAbort(() => {
          clearInterval(heartbeat)
          unsub()
          resolve()
          log.info("event disconnected")
        })
      })
    })
  }
)
```

**关键特性**：

1. **实时推送**：客户端订阅后，服务器主动推送事件
2. **心跳机制**：每 30 秒发送心跳包，防止连接超时
3. **自动清理**：连接断开时取消订阅和清理定时器
4. **事件类型**：支持所有 BusEvent 类型

### 事件系统 (Bus)

#### 事件定义

```typescript
import { BusEvent } from "@/bus/bus-event"
import z from "zod"

export const Event = {
  Connected: BusEvent.define("server.connected", z.object({})),
  Disposed: BusEvent.define("global.disposed", z.object({})),
}
```

#### 事件发布

```typescript
export async function publish<Definition extends BusEvent.Definition>(
  def: Definition,
  properties: z.output<Definition["properties"]>,
) {
  const payload = {
    type: def.type,
    properties,
  }

  log.info("publishing", { type: def.type })

  const pending = []

  // 通知特定类型的订阅者
  for (const key of [def.type, "*"]) {
    const match = state().subscriptions.get(key)
    for (const sub of match ?? []) {
      pending.push(sub(payload))
    }
  }

  // 通知全局总线
  GlobalBus.emit("event", {
    directory: Instance.directory,
    payload,
  })

  return Promise.all(pending)
}
```

#### 事件订阅

```typescript
export function subscribe<Definition extends BusEvent.Definition>(
  def: Definition,
  callback: (event: { type: Definition["type"]; properties: z.infer<Definition["properties"]> }) => void,
) {
  return raw(def.type, callback)
}

export function subscribeAll(callback: (event: any) => void) {
  return raw("*", callback)
}

export function once<Definition extends BusEvent.Definition>(
  def: Definition,
  callback: (event: { type: Definition["type"]; properties: z.infer<Definition["properties"]> }) => "done" | undefined,
) {
  const unsub = subscribe(def, (event) => {
    if (callback(event)) unsub()
  })
}
```

**使用示例**：

```typescript
// 订阅特定事件
const unsub = Bus.subscribe(SessionEvent.MessageComplete, (event) => {
  console.log("Message completed:", event)
})

// 订阅所有事件
const unsubAll = Bus.subscribeAll((event) => {
  console.log("Event:", event.type)
})

// 一次性订阅
Bus.once(SessionEvent.MessageComplete, (event) => {
  console.log("First message completed")
  return "done" // 触发取消订阅
})
```

### 事件类型

| 事件类型                   | 说明                 |
| -------------------------- | -------------------- |
| `server.connected`         | 客户端连接成功       |
| `server.heartbeat`         | 心跳事件（保持连接） |
| `server.instance.disposed` | 实例销毁             |
| `session.*`                | 会话相关事件         |
| `tui.*`                    | TUI 相关事件         |
| `tool.*`                   | 工具调用事件         |
| `permission.*`             | 权限请求事件         |

## 错误处理机制

### 错误响应格式

所有错误响应遵循统一格式：

```typescript
{
  success: false,
  data: null,
  errors: [
    {
      message: "Error description",
      code: "ERROR_CODE",
    }
  ]
}
```

### 错误定义

```typescript
export const ERRORS = {
  400: {
    description: "Bad request",
    content: {
      "application/json": {
        schema: resolver(
          z
            .object({
              data: z.any(),
              errors: z.array(z.record(z.string(), z.any())),
              success: z.literal(false),
            })
            .meta({
              ref: "BadRequestError",
            }),
        ),
      },
    },
  },
  404: {
    description: "Not found",
    content: {
      "application/json": {
        schema: resolver(Storage.NotFoundError.Schema),
      },
    },
  },
} as const

export function errors(...codes: number[]) {
  return Object.fromEntries(codes.map((code) => [code, ERRORS[code as keyof typeof ERRORS]]))
}
```

### 命名错误系统

OpenCode 使用命名错误来区分不同类型的错误：

```typescript
class NamedError {
  static NotFound(params: { resource: string })
  static ModelNotFound(params: { modelID: string })
  static Unauthorized(params: { reason: string })
  static Unknown(params: { message: string })

  toObject() {
    return {
      success: false,
      data: null,
      errors: [
        {
          message: this.message,
          name: this.name,
        },
      ],
    }
  }
}
```

### 错误处理流程

```
请求 → 中间件 → 路由处理器
               ↓
         发生错误
               ↓
      .onError 捕获
               ↓
    判断错误类型
               ↓
    ┌─────────┬─────────┬──────────┐
    ↓         ↓         ↓          ↓
NamedError  HTTPException  其他错误
    ↓         ↓          ↓
返回自定义   返回预定义  返回 500
状态码和    HTTP响应    错误信息
错误信息
```

### HTTP 状态码映射

| 错误类型                      | HTTP 状态码  | 示例              |
| ----------------------------- | ------------ | ----------------- |
| `Storage.NotFoundError`       | 404          | 会话或资源不存在  |
| `Provider.ModelNotFoundError` | 400          | 模型不存在        |
| `Worktree*` 错误              | 400          | Git worktree 问题 |
| `NamedError` (其他)           | 500          | 其他命名错误      |
| `HTTPException`               | 预定义状态码 | Hono HTTP 异常    |
| 未知错误                      | 500          | 未捕获的错误      |

## 服务器启动

### 监听函数

```typescript
export function listen(opts: { port: number; hostname: string; mdns?: boolean; cors?: string[] }) {
  _corsWhitelist = opts.cors ?? []

  const args = {
    hostname: opts.hostname,
    idleTimeout: 0, // 永不超时
    fetch: App().fetch,
    websocket: websocket,
  }

  // 尝试启动服务器
  const tryServe = (port: number) => {
    try {
      return Bun.serve({ ...args, port })
    } catch {
      return undefined
    }
  }

  // 端口 0 表示自动选择
  const server = opts.port === 0 ? (tryServe(4096) ?? tryServe(0)) : tryServe(opts.port)

  if (!server) throw new Error(`Failed to start server on port ${opts.port}`)

  _url = server.url

  // mDNS 发布
  const shouldPublishMDNS =
    opts.mdns &&
    server.port &&
    opts.hostname !== "127.0.0.1" &&
    opts.hostname !== "localhost" &&
    opts.hostname !== "::1"

  if (shouldPublishMDNS) {
    MDNS.publish(server.port!)
  } else if (opts.mdns) {
    log.warn("mDNS enabled but hostname is loopback; skipping mDNS publish")
  }

  // 拦截 stop 方法以清理 mDNS
  const originalStop = server.stop.bind(server)
  server.stop = async (closeActiveConnections?: boolean) => {
    if (shouldPublishMDNS) MDNS.unpublish()
    return originalStop(closeActiveConnections)
  }

  return server
}
```

### 启动选项

| 参数       | 类型       | 说明                                  |
| ---------- | ---------- | ------------------------------------- |
| `port`     | `number`   | 端口号，0 表示自动选择                |
| `hostname` | `string`   | 绑定地址（如 "0.0.0.0", "localhost"） |
| `mdns`     | `boolean`  | 是否发布 mDNS 服务                    |
| `cors`     | `string[]` | CORS 白名单域名                       |

### mDNS 服务发现

当启用 mDNS 且不绑定到回环地址时，OpenCode 会发布 mDNS 服务：

```typescript
if (shouldPublishMDNS) {
  MDNS.publish(server.port!)
}
```

这允许本地网络中的设备自动发现 OpenCode 服务器。

### 启动示例

```bash

# 指定端口

# 绑定到所有接口
bun dev --host 0.0.0.0
```

## 最佳实践

### 1. 路由组织

**推荐**：

- 按功能模块拆分路由文件
- 使用 `lazy()` 避免循环依赖
- 保持路由文件简洁

**示例**：

```typescript
// packages/opencode/src/server/routes/user.ts
export const UserRoutes = lazy(() => new Hono().get("/", listUsers).post("/", createUser).get("/:id", getUser))
```

### 2. 中间件顺序

**推荐顺序**：

1. 错误处理 (`onError`)
2. 认证
3. 日志
4. CORS
5. 实例上下文
6. 路由

### 3. 错误处理

**推荐**：

- 使用 `NamedError` 而非抛出原生 Error
- 返回适当的 HTTP 状态码
- 记录详细的错误日志

### 4. 事件使用

**推荐**：

- 发布事件使用 `Bus.publish`
- 订阅事件使用 `Bus.subscribe`
- 一次性订阅使用 `Bus.once`
- 及时取消订阅

### 5. 验证

**推荐**：

- 始终使用 Zod 验证输入
- 在路由中定义参数验证
- 使用 `resolver()` 生成 OpenAPI schema

## 性能优化

### 1. 懒加载

使用 `lazy()` 延迟加载路由模块，避免不必要的初始化。

### 2. 连接复用

Bun 的 HTTP 服务器自动处理连接复用。

### 3. 事件广播优化

`Bus.publish` 并行通知所有订阅者，使用 `Promise.all`。

### 4. 流式响应

使用 `streamSSE` 和 `stream` 避免内存累积。
