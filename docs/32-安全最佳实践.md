## 概述

OpenCode 实施了多层次的安全架构，从凭证管理到网络安全，全方位保护用户数据和系统安全。本文档详细说明了安全最佳实践，帮助运维工程师和安全团队安全部署和管理 OpenCode。

### 安全架构层次

```
┌─────────────────────────────────────────┐
│     应用层安全 (Application)          │
│  - 认证授权 (OAuth 2.0, API Key)  │
│  - 权限系统 (Actor-based RBAC)       │
│  - 会话管理 (Token, Refresh)         │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│     数据层安全 (Data)                 │
│  - 加密存储 (SHA-256, AES)          │
│  - 凭证管理 (SST Secrets)           │
│  - 文件权限 (0600, 0700)          │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│     网络层安全 (Network)            │
│  - TLS/HTTPS (证书验证)              │
│  - 防火墙规则 (UFW, iptables)      │
│  - 反向代理 (Nginx, Caddy)         │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│     基础设施安全 (Infrastructure)   │
│  - 容器安全 (Docker, K8s)         │
│  - 日志审计 (Cloudflare Logpush)     │
│  - 监控告警 (Honeycomb)            │
└─────────────────────────────────────────┘
```

### 核心安全原则

- **最小权限原则**：每个组件只授予必要的最小权限
- **纵深防御**：多层安全控制，单层失效不影响整体安全
- **零信任**：不信任任何网络流量，验证所有请求
- **审计追溯**：所有敏感操作可追溯、可审计
- **自动化防护**：使用自动化工具检测和预防安全威胁

## API 密钥管理

### 密钥生成

OpenCode 使用密码学安全的随机数生成器创建 API 密钥：

**实现位置**：`packages/console/core/src/key.ts`

```typescript
import crypto from "crypto"

export function generateApiKey(): string {
  const charset = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz"
  const randomBytes = crypto.getRandomValues(new Uint8Array(64))
  let result = ""
  for (let i = 0; i < 64; i++) {
    result += charset[randomBytes[i] % charset.length]
  }
  return "sk-" + result
}
```

**密钥格式**：

- 前缀：`sk-` (secret key)
- 长度：64 字符随机值
- 总长度：67 字符
- 示例：`sk-aB3xK9mNp2qR4sT6vW8yZ0cD1eF2gH3iJ4kL5mN6oP7qR8sT9uV0wX1yZ2aB3cD4eF5gH6`

## 认证安全

### OAuth 2.0 安全实现

OpenCode 实现了符合 RFC 6749 和 RFC 7636 的 OAuth 2.0 授权码流程。

**实现位置**：`packages/opencode/src/mcp/oauth-provider.ts`

#### 1. PKCE (Proof Key for Code Exchange)

PKCE 防止授权码拦截攻击：

```typescript
async function generatePKCE(): Promise<PkceCodes> {
  // 生成 43 字符随机验证器
  const verifier = generateRandomString(43)

  // SHA-256 哈希
  const encoder = new TextEncoder()
  const data = encoder.encode(verifier)
  const hash = await crypto.subtle.digest("SHA-256", data)

  // Base64URL 编码
  const challenge = base64UrlEncode(hash)

  return { verifier, challenge }
}

function base64UrlEncode(buffer: ArrayBuffer): string {
  const bytes = new Uint8Array(buffer)
  let binary = ""
  for (let i = 0; i < bytes.byteLength; i++) {
    binary += String.fromCharCode(bytes[i])
  }
  return btoa(binary).replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, "")
}
```

**安全特性**：

- code_verifier：高熵随机值（43 字符）
- code_challenge：SHA-256 哈希，不可逆
- Base64URL 安全编码：防止 URL 解析问题

#### 2. State 参数防止 CSRF

```typescript
function generateState(): string {
  // 生成 32 字符随机 state
  return generateRandomString(32)
}

// 验证回调时的 state
if (callbackState !== storedState) {
  throw new Error("State mismatch - possible CSRF attack")
}
```

**安全特性**：

- 32 字符高熵随机值
- 一次性使用
- 回调时严格验证

#### 3. 令牌生命周期管理

**访问令牌**：

- 生存期：1 小时（3600 秒）
- 用途：短期 API 访问
- 存储：内存中，不持久化

**刷新令牌**：

- 生存期：长期（取决于提供商）
- 用途：获取新的访问令牌
- 存储：安全持久化（auth.json）
- 刷新机制：自动透明

```typescript
async function refreshAccessToken(refreshToken: string): Promise<Tokens> {
  const response = await fetch(tokenEndpoint, {
    method: "POST",
    headers: { "Content-Type": "application/x-www-form-urlencoded" },
    body: new URLSearchParams({
      grant_type: "refresh_token",
      refresh_token: refreshToken,
    }),
  })

  const tokens = await response.json()

  // 更新存储
  await Auth.set(providerID, {
    type: "oauth",
    access: tokens.access_token,
    refresh: tokens.refresh_token,
    expires: Date.now() + tokens.expires_in * 1000,
  })

  return tokens
}
```

```typescript
// 从 Authorization 头提取 Bearer token
function extractBearerToken(headers: Headers): string | null {
  const auth = headers.get("Authorization")
```

## 数据加密

### 加密操作

OpenCode 使用 Web Crypto API 进行加密操作。

**实现位置**：`packages/util/src/encode.ts`

```typescript
import crypto from "crypto"

// SHA-256 哈希
export async function sha256(data: string): Promise<string> {
  const encoder = new TextEncoder()
  const buffer = encoder.encode(data)
  const hashBuffer = await crypto.subtle.digest("SHA-256", buffer)
  const hashArray = Array.from(new Uint8Array(hashBuffer))
  const hashHex = hashArray.map((b) => b.toString(16).padStart(2, "0")).join("")
  return hashHex
}

// Base64 编码
export function base64Encode(data: string): string {
  return btoa(unescape(encodeURIComponent(data)))
}

// Base64 URL 安全编码
export function base64UrlEncode(data: string): string {
  return base64Encode(data).replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, "")
}
```

### 加密最佳实践

#### 1. 永远不要自行实现加密

```typescript
// ❌ 错误：自定义加密
function customEncrypt(text: string): string {
  return text.split('').reverse().join('')  // 不安全！
```

#### 2. 使用标准算法

| 算法          | 用途             | 密钥长度     |
| ------------- | ---------------- | ------------ |
| SHA-256       | 哈希、完整性检查 | N/A          |

| RSA-2048/4096 | 非对称加密       | 2048/4096 位 |
| PBKDF2        | 密钥派生         | 可变         |

#### 3. 保护加密密钥

```typescript
// ❌ 错误：密钥硬编码
```

## 访问控制

### Actor-Based Authorization

**实现位置**：`packages/console/app/src/context/auth.withActor.ts`

```typescript
// 基于 Actor 的权限检查
export async function withActor<T>(
  userId: string,
  workspaceId: string,
  callback: (actor: Actor) => Promise<T>,
): Promise<T> {
  const actor = {
    userId,
    workspaceId,
    role: await getUserRole(userId, workspaceId), // admin 或 member
  }

  return callback(actor)
}

// 使用示例
export async function createApiKey(actor: Actor) {
  if (actor.role !== "admin") {

  }

}
```
