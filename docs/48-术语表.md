## 架构术语

### Agent（代理）

**定义**: 具有特定能力、权限和行为的 AI 助手。

**上下文**:

- Agent 是 OpenCode 的核心概念，代表不同类型的 AI 助手
- 每个 Agent 有自己的配置、提示词、权限和工具访问
- Agent 可以是三种模式之一：primary、subagent 或 all
- 用户可以在不同 Agent 之间切换（仅限 primary agent）

**相关概念**:

- **Primary Agent**: 用户可切换的默认 agent（如 `build`、`plan`）
- **Subagent**: 内部使用的 agent，不能由用户直接切换（如 `general`、`explore`）
- **All Agent**: 可以是 primary 或 subagent 的灵活 agent

**内置 Agents**:
| Agent | 模式 | 描述 |
|--------|------|------|
| `build` | primary | 默认开发 agent，具有完整访问权限 |
| `plan` | primary | 只读 agent，用于分析和代码探索，默认拒绝编辑 |
| `general` | subagent | 用于多步骤任务的通用目的 agent |
| `explore` | subagent | 快速代码库搜索专家 |
| `compaction` | hidden | 会话摘要生成 |
| `title` | hidden | 会话标题生成 |
| `summary` | hidden | 会话摘要 |

**位置**: `packages/opencode/src/agent/agent.ts`

### Session（会话）

**定义**: 用户-AI 对话的容器，存储消息历史和状态。

**上下文**:

- Session 是 OpenCode 中的主要工作单元
- 每个 Session 包含用户和 AI 之间的消息历史
- Session 支持分支（fork）、压缩（compaction）、恢复（revert）
- Session 可以共享、归档和删除

**Session 生命周期**:

1. **创建**: 通过 API 或 CLI 创建新会话
2. **激活**: 开始处理用户输入和 AI 响应
3. **分支**: 在特定消息点 fork 创建子会话
4. **压缩**: 使用 AI 摘要减少上下文窗口使用
5. **恢复**: 回滚到之前的状态
6. **归档**: 标记为非活跃但保留用于参考
7. **删除**: 永久移除会话及其数据

**位置**: `packages/opencode/src/session/index.ts`

### Workspace（工作空间）

**定义**: 项目的 Git worktree 上下文。

**上下文**:

- Workspace 代表项目的当前工作目录
- 可以是主分支或 worktree（用于并行开发）
- Workspace 决定哪些文件和目录对 Session 可见

**相关概念**:

- **Main Branch**: 主 Git 分支
- **Worktree**: Git 工作树（隔离的开发环境）

**位置**: `packages/opencode/src/worktree/index.ts`

- Project 代表一个代码库或工作目录
- 每个 Project 可以有多个 Session
- Project 可以有自定义配置（名称、图标、颜色）

### Tool（工具）

**定义**: Agent 可以执行的原子操作。

**上下文**:

- Tool 是 OpenCode 中可执行的基本单元
- 每个 Tool 有参数验证（Zod schema）、描述和执行逻辑
- Tool 可以被 Agent 调用并返回结果
- Tool 系统支持自定义工具和 MCP 工具

**工具类别**:
| 类别 | 工具 | 目的 |
|--------|--------|------|
| 文件 | `read`, `write`, `edit`, `glob`, `grep`, `list` | 文件系统操作 |
| Shell | `bash` | 在 shell 中执行命令 |
| LSP | `lsp`, `lsp_*` | 语言服务器协议操作 |
| Web | `webfetch`, `websearch` | Web 请求和搜索 |
| 会话 | `todowrite`, `todoread` | 会话任务管理 |
| 权限 | `question` | 用户交互请求 |
| 管理 | `task`, `batch` | 管理/内部工具 |
| 其他 | `skill`, `multiedit`, `apply_patch`, `codesearch`, `external-directory` | 其他功能 |

**位置**: `packages/opencode/src/tool/tool.ts`

### Task（任务）

**定义**: 委托给子代理的工作单元。

**上下文**:

- Task 由父 Agent 委托给 subagent 执行
- Task 创建具有受限权限的子会话
- Task 用于多步骤任务和并行工作

### Permission（权限）

**定义**: 细粒度的访问控制。

**上下文**:

- Permission 系统控制 Agent 可以执行哪些操作
- 支持三种操作：`allow`（允许）、`deny`（拒绝）、`ask`（询问）
- 权限规则使用模式匹配来应用操作
- 用户可以手动响应权限请求

**权限操作**:
| 操作 | 描述 |
|------|------|
| `allow` | 自动允许操作 |
| `deny` | 自动拒绝操作 |
| `ask` | 询问用户是否允许 |

**位置**: `packages/opencode/src/permission/next.ts`

---

### Provider（提供商）

**定义**: AI 模型提供商（Anthropic、OpenAI、Google 等）。

**上下文**:

- Provider 提供对 AI 模型的访问
- OpenCode 抽象了不同的 Provider 以提供统一接口
- Provider 支持认证（OAuth、API Key）、模型列表和流式响应

**支持的 Providers**:

- **Anthropic**: Claude 模型
- **OpenAI**: GPT 模型
- **Google**: Gemini 模型
- **Azure OpenAI**: Azure 托管的 OpenAI 模型
- **Mistral**: Mistral 模型
- **Groq**: Groq 模型
- **Together AI**: Together 模型
- **本地模型**: 通过自定义提供商支持

**位置**: `packages/opencode/src/provider/provider.ts`

### Model（模型）

**定义**: Provider 内的特定 AI 模型。

**上下文**:

- Model 是 Provider 提供的特定 AI 模型
- 每个 Model 有唯一的 ID、名称、功能和限制
- Model 支持工具调用、流式响应和上下文窗口

**Model 属性**:
| 属性 | 描述 |

| `id` | 模型唯一标识符 |
| `name` | 模型显示名称 |
| `family` | 模型系列（如 Claude 3.5） |
| `context` | 上下文窗口大小（tokens） |
| `cost` | 输入/输出成本 |
| `tool_call` | 是否支持工具调用 |
| `streaming` | 是否支持流式响应 |

**位置**: `packages/opencode/src/provider/models.ts`

## 技术缩写

### MCP（Model Context Protocol）

**全称**: Model Context Protocol

**定义**: 连接外部工具/服务器的标准协议。

**上下文**:

- MCP 是开放协议，用于标准化 AI 模型与外部服务之间的集成
- MCP 服务器可以提供工具、资源和提示词模板
- OpenCode 内置 MCP 客户端，可以动态连接 MCP 服务器

**MCP 功能**:

- **Tools**: 服务器提供的可调用工具
- **Resources**: 服务器提供的数据资源（文件、数据库等）
- **Prompts**: 服务器提供的提示词模板

**位置**: `packages/opencode/src/mcp/index.ts`

---

### SSE（Server-Sent Events）

**全称**: Server-Sent Events

**定义**: 从服务器到客户端的单向事件流。

**上下文**:

- SSE 用于实时向客户端推送事件（如会话状态变化）
- 与 WebSocket 不同，SSE 是单向的（仅服务器→客户端）
- 在 OpenCode 中用于会话更新和通知

**位置**: `packages/opencode/src/server/server.ts`

---

### LSP（Language Server Protocol）

**全称**: Language Server Protocol

**定义**: 提供代码智能（自动完成、定义、诊断）的标准协议。

**上下文**:

- LSP 是语言无关的协议，为编辑器提供语言功能
- OpenCode 使用 LSP 客户端连接到语言服务器
- 支持的操作：符号搜索、定义跳转、引用查找、诊断、重命名

**LSP 功能**:
| 功能 | 描述 |
|------|------|
| `workspace/symbol` | 搜索工作区符号（函数、类、变量） |
| `textDocument/definition` | 跳转到符号定义 |
| `textDocument/references` | 查找符号的所有引用 |
| `textDocument/completion` | 代码自动完成 |
| `textDocument/diagnostic` | 获取代码错误和警告 |

**位置**: `packages/opencode/src/lsp/index.ts`

---

## AI & 语言模型术语

### LLM（Large Language Model）

**全称**: Large Language Model

**定义**: 大型语言模型，OpenCode 的核心 AI 推理引擎。

**上下文**:

- LLM 是处理和生成文本的核心 AI 组件
- OpenCode 支持多个 Provider 的 LLM
- LLM 提供流式响应和工具调用功能

**LLM 功能**:
| 功能 | 描述 |
|------|------|
| `text_generation` | 生成文本响应 |
| `streaming` | 连续生成流式响应 |
| `tool_calling` | 调用工具并传递参数 |
| `function_calling` | 直接调用函数 |
| `reasoning` | 显示推理过程（某些模型） |

**位置**: `packages/opencode/src/session/llm.ts`

---

### Stream（流式）

**定义**: 来自 AI 模型的连续生成响应。

**上下文**:

- 流式响应允许在完全生成前显示部分输出
- 提供更快的用户体验，无需等待完整响应
- 使用 Server-Sent Events (SSE) 传输

**流式类型**:

- **SSE Stream**: 通过 SSE 传输的流式响应
- **WebSocket Stream**: 通过 WebSocket 传输的实时响应

**位置**: `packages/opencode/src/session/prompt.ts`

---

### Temperature（温度）

**定义**: LLM 参数（0.0-1.0），控制随机性。

**上下文**:

- Temperature 控制响应的创造性和随机性
- 较低的值（如 0.1-0.3）产生更确定和准确的输出
- 较高的值（如 0.7-1.0）产生更有创造性和多样化的输出
- 默认值通常为 0.5-0.7

**使用场景**:
| 场景 | 推荐值 |
|--------|----------|
| 代码生成 | 0.1-0.3（精确） |
| 创意写作 | 0.7-1.0（创造性） |
| 分析任务 | 0.1-0.5（准确） |
| 通用对话 | 0.5-0.7（平衡） |

---

### Top-P（核采样）

**定义**: LLM 参数，用于核采样（nucleus sampling）。

**上下文**:

- Top-P 限制模型从最可能的 tokens 中采样
- 例如，top_p=0.1 表示仅从前 10% 最可能的 tokens 中采样
- 较低的值产生更一致和可预测的输出
- 默认值为 1.0（考虑所有 tokens）

**使用场景**:
| 场景 | 推荐值 |
|--------|----------|
| 代码生成 | 0.1-0.3（精确） |
| 创意写作 | 0.7-1.0（创造性） |
| 分析任务 | 0.1-0.5（准确） |

---

### Tool Calling（工具调用）

**定义**: AI 模型调用工具并传递参数。

**上下文**:

- Tool Calling 允许 LLM 执行特定操作（如读取文件、运行命令）
- 工具以结构化格式定义，包含名称、描述和参数
- LLM 可以在一次响应中调用多个工具

**工具调用流程**:

1. LLM 分析用户请求
2. LLM 选择适当的工具和参数
3. 工具执行并返回结果
4. LLM 使用工具结果生成最终响应

**位置**: `packages/opencode/src/session/message.ts`

---

### Function Calling（函数调用）

**定义**: AI 模型直接调用函数。

**上下文**:

- Function Calling 是 Tool Calling 的一种变体
- 主要由 OpenAI 模型使用
- 与 Tool Calling 类似，但使用不同的消息格式

**位置**: `packages/opencode/src/provider/sdk/openai-compatible/`

- OpenCode 使用 HTTP/HTTPS 提供 REST API

**位置**: `packages/opencode/src/server/server.ts`

---

**位置**: `packages/opencode/src/server/server.ts`

## 配置术语

### Environment Variables（环境变量）

**定义**: 在运行时配置行为的变量。

**上下文**:

- OpenCode 支持多个环境变量来自定义义行为
- 环境变量具有不同的优先级
- 可以覆盖配置文件中的设置

**环境变量优先级**（从高到低）:

1. `OPENCODE_CONFIG_CONTENT` - 内联 JSON 配置（最高优先级）
2. `OPENCODE_CONFIG` - 自定义配置文件路径
3. `OPENCODE_CONFIG_DIR` - 配置目录扫描路径
4. 配置文件 - `~/.opencode/config.json`

**常用环境变量**:
| 变量 | 目的 |
|--------|------|
| `OPENCODE_CONFIG` | 自定义配置文件路径 |
| `OPENCODE_CONFIG_CONTENT` | 内联 JSON 配置 |
| `OPENCODE_CONFIG_DIR` | 配置目录 |
| `OPENCODE_AUTO_SHARE` | 启用自动会话共享 |
| `OPENCODE_SERVER_PASSWORD` | Basic Auth 密码 |
| `OPENCODE_SERVER_USERNAME` | Basic Auth 用户名 |
| `OPENCODE_CLIENT` | 客户端类型（cli、web、desktop） |
| `OPENCODE_PERMISSION` | JSON 字符串的权限规则 |
| `OPENCODE_DISABLE_AUTOUPDATE` | 禁用自动更新 |
| `OPENCODE_DISABLE_PRUNE` | 禁用会话清理 |
| `OPENCODE_DISABLE_AUTOCOMPACT` | 禁用自动会话压缩 |
| `OPENCODE_EXPERIMENTAL` | 启用实验性功能 |
| `OPENCODE_DISABLE_LSP_DOWNLOAD` | 禁用自动 LSP 服务器下载 |

**位置**: `packages/opencode/src/flag/flag.ts`

---

### Configuration Keys（配置键）

**定义**: 配置文件中的设置键。

**上下文**:

- 配置文件使用 JSON/JSONC 格式
- 配置键按类别组织
- 支持 Zod schema 验证

**配置类别**:
| 键 | 类别 | 描述 |
|--------|--------|------|
| `permission` | 权限 | 权限规则集（allow/deny/ask） |
| `agent` | Agent | Agent 配置 |
| `mode` | 模式 | 模式配置 |
| `provider` | Provider | AI Provider 配置 |
| `keybinds` | 键绑定 | 键盘快捷键 |
| `command` | 命令 | 自定义命令定义 |
| `mcp` | MCP | MCP 服务器配置 |
| `formatter` | 格式化器 | 代码格式化器 |

## 权限系统术语

### Permission Ruleset（权限规则集）

**定义**: 映射模式到操作的权限规则。

**上下文**:

- 使用模式匹配（glob 模式）来应用规则
- 规则按顺序评估，第一个匹配的规则生效

```json
    {
      "permission": "edit",
      "patterns": ["/etc/*"],
      "action": "deny"
    },
    {
      "permission": "edit",
      "patterns": ["*"],
      "action": "ask"
    }
  ]
}
```

## 总结

OpenCode 使用**客户端-服务器架构**，具有多个前端（TUI、Web、Desktop）。核心概念围绕**Agents**（专业化的 AI 助手）、**Sessions**（对话容器）、**Tools**（原子操作）和**Permissions**（细粒度访问控制）。

**关键架构模式**包括\*\*:

- **事件驱动设计**通过 Bus 系统
- **依赖注入**通过 Instance.provide
- **插件架构**用于可扩展性
- **OpenAPI 规范**用于 SDK 生成
- **Zod schemas**用于类型验证
- **MCP 协议**用于外部工具集成
- **LSP 协议**用于代码智能
- **SSE**用于实时事件流式传输

配置系统使用多个优先级层：远程配置（well-known）→ 全局配置 → 项目配置 → 内联配置（OPENCODE_CONFIG_CONTENT）。

Agent 系统支持三种模式：**primary**（用户可切换）、**subagent**（仅内部）和**all**（灵活）。内置 Agent 包括 `build`（默认）、`plan`（只读）、`general`（多步骤）、`explore`（代码库搜索），加上内部任务的隐藏 Agent。
