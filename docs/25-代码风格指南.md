## 概述

本指南定义了 OpenCode 项目的编码风格和最佳实践。遵循这些约定可以确保代码的一致性、可读性和可维护性。

### 核心原则

1. **简洁**：保持代码简单明了
2. **一致性**：遵循既定模式
3. **类型安全**：充分利用 TypeScript 类型系统
4. **可读性**：代码应自解释

## 命名约定

### 文件命名

| 类型     | 规范             | 示例                                |
| -------- | ---------------- | ----------------------------------- |
| 模块文件 | `*.ts`           | `tool.ts`, `session.ts`             |
| 测试文件 | `*.test.ts`      | `tool.test.ts`, `session.test.ts`   |
| E2E 测试 | `*.spec.ts`      | `prompt.spec.ts`, `session.spec.ts` |
| 类型文件 | `*.types.ts`     | `session.types.ts`                  |
| 工具文件 | `*.util.ts`      | `file.util.ts`                      |
| 常量文件 | `*.constants.ts` | `api.constants.ts`                  |

### 变量和函数命名

**首选单字命名**：

```typescript
// ✅ Good - 单字
const foo = 1
const bar = 2
const baz = 3

// ❌ Bad - 多字（除非必需）
const fooBar = 1
const barBaz = 2
```

**单字 vs 多字规则**：

```typescript
// 使用多字仅当无法找到合适的单字
const userProfile = 1 // ✅ 合理 - user 和 profile 是相关概念
const data = 1 // ✅ 更好的单字选择
```

### 类和接口命名

**PascalCase**：

```typescript
// 类
class Tool {}
class Session {}

// 接口
interface ToolInfo {}
interface SessionInfo {}

// 类型别名
type ToolResult = {}

// 枚举
type LogLevel = "DEBUG" | "INFO" | "WARN" | "ERROR"
```

### 常量命名

**SCREAMING_SNAKE_CASE**：

```typescript
const MAX_LOG_FILES = 10
const DEFAULT_TIMEOUT = 5000
const BASE_URL = "https://api.opencode.ai"
```

### 私有成员命名

**下划线前缀**：

```typescript
class MyClass {
  private _privateField: string
  private _privateMethod(): void {}

  public publicField: string
  public publicMethod(): void {}
}
```

### 异步函数命名

**后缀 `async` 或描述性名称**：

```typescript
// ✅ Good
async function loadConfig(): Promise<Config.Info>
async function saveSession(): Promise<void>

// ❌ Bad
async function config(): Promise<Config.Info>
async function session(): Promise<void>
```

### 事件命名

**大驼峰**：

```typescript
Bus.publish(Session.Event.Created, { info: session })
Bus.publish(Session.Event.Updated, { info: session })
Bus.publish(Session.Event.Started, { id: session.id })
```

### 命名空间

**驼峰命名空间**：

```typescript
namespace Tool {
  async function init(): Promise<Tool.Info> {}
}

namespace Session {
  async function create(): Promise<Session.Info> {}
}

namespace Storage {
  async function read<T>(key: string[]): Promise<T> {}
}
```

## 代码组织

### 模块结构

OpenCode 使用命名空间进行模块组织：

```typescript
// packages/opencode/src/tool/tool.ts
export namespace Tool {
  export type Info<Parameters extends ZodType> = {
    id: string
    init: (ctx?: InitContext) => Promise<{
      description: string
      parameters: Parameters
      execute: (args: z.infer<Parameters>, ctx: Context) => Promise<ToolResult>
    }>
  }

  export async function init<Parameters extends ZodType>(
    info: Tool.Info<Parameters>
  ): Promise<Tool.Info<Parameters>> {
    return info as any
  }
}

// 使用
import { Tool } from "./tool"
const tool = await Tool.init({...})
```

### 文件组织

```
packages/opencode/src/
├── agent/          # 代理系统
│   └── agent.ts
├── tool/           # 工具系统
│   ├── tool.ts      # 工具命名空间和接口
│   ├── bash.ts      # 具体 tool 实现
│   ├── read.ts
│   └── ...
├── session/         # 会话管理
│   ├── index.ts     # Session 命名空间
│   ├── message-v2.ts
│   └── ...
├── server/          # HTTP 服务器
│   ├── server.ts
│   └── routes/
└── util/           # 工具函数
    ├── log.ts
    └── error.ts
```

### 导出方式

```typescript
// ✅ Good - 命名空间导出
export namespace Tool {
  export type Info = { ... }
  export async function init(): Promise<...> { }
}

// ✅ Good - 具名导出
export const Tool = {
  init: async () => {...},
  execute: async () => {...},
}

// ❌ Bad - 混合导出
export type ToolInfo = {...}
export async function initTool() {...}
```

### 依赖顺序

```typescript
// 1. 标准库导入
import path from "path"
import fs from "fs"

// 2. 第三方库导入
import { z } from "zod"
import { Hono } from "hono"

// 3. 内部模块导入（优先相对路径）
import { Log } from "../util/log"
import { Tool } from "./tool"
```

## TypeScript 最佳实践

### 类型定义

**接口 vs 类型别名**：

```typescript
// ✅ 使用类型别名描述简单对象
type ToolResult = {
  title: string
  output: string
  metadata: Record<string, any>
}

// ✅ 使用接口描述可扩展对象
interface ToolExecuteArgs {
  filePath: string
  content: string
}
```

### 泛型使用

```typescript
// ✅ Good - 描述性泛型参数
async function read<T>(key: string[]): Promise<T> {}

async function process<T, R>(input: T, fn: (value: T) => R): Promise<R> {}

// ❌ Bad - 单字母泛型
async function read<K>(key: string[]): Promise<K> {}
```

### 联合类型

```typescript
// ✅ Good - 类型别名
type LogLevel = "DEBUG" | "INFO" | "WARN" | "ERROR"

// ✅ Good - 字面量联合
function setLevel(level: "DEBUG" | "INFO" | "WARN" | "ERROR") {}

// 使用
const level: LogLevel = "DEBUG"
```

### 条件类型

```typescript
// ✅ Good - 条件类型
type ToolInfo<T extends ZodType> = T extends infer U ? U : never

// ✅ Good - 模板字面量
type Env = "development" | "production" | "test"
```

### 避免类型断言

```typescript
// ❌ Bad - 类型断言
const value = someValue as string

// ✅ Good - 类型守卫
function isString(value: unknown): value is string {
  return typeof value === "string"
}

if (isString(someValue)) {
  const value: string = someValue
}
```

### 严格模式

确保 `tsconfig.json` 启用严格模式：

```json
{
  "compilerOptions": {
    "strict": true,
    "noImplicitAny": true,
    "strictNullChecks": true,
    "noUncheckedIndexedAccess": true
  }
}
```

### 类型导出

```typescript
// ✅ Good - 导出类型
export type ToolParameters = {...}
export interface ToolResult {...}

// ✅ Good - 导出带类型的函数
export async function executeTool(args: ToolParameters): Promise<ToolResult> { }
```

## 函数设计

### 函数简洁性

**保持在一个函数中**，除非可组合或可重用：

```typescript
// ✅ Good - 一个函数完成一个任务
async function saveSession(id: string, data: SessionData): Promise<void> {
  const path = getFilePath(id)
  await fs.writeFile(path, JSON.stringify(data))
}

// ❌ Bad - 一个函数做太多事
async function processSession(id: string): Promise<void> {
  // 验证
  if (!id) throw new Error("Invalid ID")
  // 加载
  const data = await load(id)
  // 处理
  const processed = processData(data)
  // 保存
  await save(id, processed)
  // 发送通知
  await notify(id)
}
```

### 参数设计

**避免不必要的解构**：

```typescript
// ❌ Bad - 失去上下文
const { a, b, c } = obj
console.log(a, b, c)

// ✅ Good - 保留上下文
console.log(obj.a, obj.b, obj.c)
```

**使用对象参数**：

```typescript
// ❌ Bad - 参数过多
function process(name: string, age: number, email: string, phone: string): User {}

// ✅ Good - 对象参数
function process(params: { name: string; age: number; email: string; phone: string }): User {}
```

### 返回值

**首选 `const` 而非 `let`**：

```typescript
// ❌ Bad - 使用 let
let result
if (condition) {
  result = 1
} else {
  result = 2
}

// ✅ Good - 使用 const
const result = condition ? 1 : 2
```

**避免 else 语句**：

```typescript
// ❌ Bad - else 语句
function foo() {
  if (condition) return 1
  else return 2
}

// ✅ Good - 早期返回
function foo() {
  if (condition) return 1
  return 2
}
```

### 早期返回

```typescript
// ✅ Good - 提早返回验证
async function executeTool(args: ToolArgs): Promise<Result> {
  if (!args) throw new Error("Args required")
  if (!args.command) throw new Error("Command required")

  const result = await runCommand(args.command)
  return { success: true, data: result }
}
```

### 异步函数处理

```typescript
// ✅ Good - 明确错误处理
async function loadConfig(): Promise<Config.Info> {
  try {
    const content = await fs.readFile(configPath)
    return JSON.parse(content)
  } catch (error) {
    throw new NamedError.JsonError({ message: "Failed to load config" }, { cause: error })
  }
}
```

### 函数长度

**保持函数简短**（< 50 行）：

```typescript
// ✅ Good - 简短函数
function formatPath(path: string): string {
  return path.replace(/\\/g, "/")
}

// ✅ Good - 拆分为小函数
function validateUser(user: User): boolean {
  if (!user.email) return false
  if (!user.name) return false
  return true
}

function saveUser(user: User): Promise<void> {
  const validated = validateUser(user)
  if (!validated) throw new Error("Invalid user")

  await db.users.save(user)
}
```

## 错误处理模式

### NamedError 系统

使用 `NamedError` 基类创建类型化错误：

```typescript
import { NamedError } from "@opencode-ai/util/error"

// 创建错误类型
export const MyError = NamedError.create("MyError", z.object({ id: z.string() }))

// 使用
if (!id) {
  throw new MyError({ id: "Invalid ID" })
}
```

### 错误转换

```typescript
try {
  await operation()
} catch (error) {
  if (error instanceof NamedError) {
    return error.toObject()
  }
  throw new NamedError.Unknown({ message: error.toString() }, { cause: error })
}
```

### 错误日志

```typescript
import { Log } from "@opencode-ai/opencode/util/log"

const log = Log.create({ service: "your-service" })

try {
  await riskyOperation()
} catch (error) {
  log.error("Operation failed", {
    error: error.toString(),
    stack: error.stack,
    context: { param1, param2 },
  })
  throw error
}
```

### 避免 try/catch

**仅在需要时使用 try/catch**：

```typescript
// ❌ Bad - 不必要的 try/catch
try {
  const value = simpleOperation()
  return value
} catch (error) {
  console.error(error)
  return null
}

// ✅ Good - 让错误向上传播
return simpleOperation()
```

### 静默失败

```typescript
// ✅ Good - 提供默认值
const result = await operation().catch(() => defaultValue)

// ✅ Good - 静默并继续
await operation().catch(() => {})

// ❌ Bad - 吞掉错误
try {
  await operation()
} catch (error) {
  // 什么都不做
}
```

### 验证错误

```typescript
// ✅ Good - 早期验证
function divide(a: number, b: number): number {
  if (b === 0) {
    throw new Error("Division by zero")
  }
  return a / b
}

// ✅ Good - Zod 验证
const Schema = z.object({
  id: z.string(),
  name: z.string(),
})

async function create(params: unknown): Promise<User> {
  const validated = Schema.parse(params)
  return db.create(validated)
}
```

## 项目特定规则

### 避免使用 any

**使用具体类型或 unknown**：

```typescript
// ❌ Bad - 使用 any
function process(data: any): void {
  console.log(data.value)
}

// ✅ Good - 使用具体类型
function process(data: { value: string }): void {
  console.log(data.value)
}

// ✅ Good - 使用 unknown（如果类型未知）
function process(data: unknown): void {
  if (typeof data === "object" && data !== null && "value" in data) {
    console.log((data as { value: string }).value)
  }
}
```

### 使用 Bun APIs

**优先使用 Bun 原生 API**：

```typescript
// ✅ Good - Bun API
const content = await Bun.file(path).text()
await Bun.write(path, content)

// ❌ Bad - Node.js API（在 Bun 环境中）
import fs from "fs"
const content = await fs.readFile(path, "utf-8")
```

### 上下文模式

使用 `App.provide()` 提供作用域上下文：

```typescript
import { Instance } from "./project/instance"

await Instance.provide({
  directory: projectRoot,
  fn: async () => {
    // 在此作用域内，所有操作相对于 projectRoot
    const config = await Config.load()
    const session = await Session.create()
  },
})
```

### 事件总线

使用 `Bus` 发布和订阅事件：

```typescript
import { Bus } from "./bus"

// 订阅
const unsub = Bus.subscribe(Session.Event.Created, (event) => {
  console.log("Session created:", event.properties.info)
})

// 发布
Bus.publish(Session.Event.Created, { info: session })

// 取消订阅
unsub()
```

### 存储命名空间

```typescript
import { Storage } from "./storage/storage"

// 读取
const config = await Storage.read<Config.Info>(["config", "project"])

// 写入
await Storage.write(["config", "project"], { ...config })

// 删除
await Storage.delete(["cache", "key"])
```

### 工具定义

```typescript
import { Tool } from "./tool/tool"
import z from "zod"

export const MyTool = Tool.define("my-tool", {
  description: "Description of what this tool does",
  parameters: z.object({
    param1: z.string().describe("Parameter description"),
    param2: z.number().optional().describe("Optional parameter"),
  }),
  async execute(args, ctx) {
    // 1. 权限检查（自动）
    // 2. 执行逻辑
    const result = await doSomething(args.param1)
    // 3. 返回结果
    return {
      title: "Operation completed",
      output: JSON.stringify(result),
      metadata: {},
    }
  },
})
```

### 测试模式

```typescript
import { describe, test, expect } from "bun:test"

describe("Feature", () => {
  test("should do something", async () => {
    await Instance.provide({
      directory: projectRoot,
      fn: async () => {
        // Arrange
        const tool = await Tool.init()

        // Act
        const result = await tool.execute(params, ctx)

        // Assert
        expect(result).toBeDefined()
      },
    })
  })
})
```

## 代码示例对比

### 示例 1：工具实现

```typescript
// ❌ Bad
const ExecuteTool = async (args: any, ctx: any) => {
  let result
  try {
    result = await doSomething(args)
    return { title: "Done", output: JSON.stringify(result) }
  } catch (e) {
    console.log(e)
    return { title: "Error", output: e.message }
  }
}

// ✅ Good
export const MyTool = Tool.define("my-tool", {
  description: "Does something useful",
  parameters: z.object({
    input: z.string().describe("Input parameter"),
  }),
  async execute(args, ctx) {
    const log = Log.create({ service: "my-tool" })
    using timer = log.time("execute")

    try {
      const result = await doSomething(args.input)
      return {
        title: "Operation completed",
        output: JSON.stringify(result),
        metadata: { duration: timer.duration },
      }
    } catch (error) {
      log.error("Execution failed", { error })
      throw new NamedError.Unknown({ message: error.toString() }, { cause: error })
    }
  },
})
```

### 示例 2：会话管理

```typescript
// ❌ Bad
async function createSession(title: string) {
  let session = {}
  if (!title) {
    title = "Untitled"
  }
  session.title = title
  session.id = generateId()
  session.time = Date.now()
  await db.save(session)
  return session
}

// ✅ Good
export namespace Session {
  export async function create(config?: { title?: string }): Promise<Session.Info> {
    const title = config?.title ?? "Untitled"
    const id = ulid()
    const time = Date.now()

    const info: Session.Info = { id, title, time }
    await Storage.write(["session", id], info)

    Bus.publish(Session.Event.Created, { info })
    return info
  }
}
```

### 示例 3：错误处理

```typescript
// ❌ Bad
async function loadConfig() {
  try {
    const data = await fs.readFile(path)
    return JSON.parse(data)
  } catch (e) {
    throw e
  }
}

// ✅ Good
async function loadConfig(): Promise<Config.Info> {
  const log = Log.create({ service: "config" })
  using timer = log.time("load")

  try {
    const content = await Bun.file(path).text()
    const parsed = JSON.parse(content)
    return Config.Info.parse(parsed)
  } catch (error) {
    if (error instanceof SyntaxError) {
      throw new NamedError.JsonError({ message: "Invalid JSON in config file" }, { cause: error })
    }
    throw new NamedError.Unknown({ message: "Failed to load config" }, { cause: error })
  }
}
```

## 总结

遵循这些编码约定可以确保：

- ✅ **一致性**：代码风格统一
- ✅ **可读性**：易于理解和维护
- ✅ **类型安全**：充分利用 TypeScript
- ✅ **可测试性**：函数简洁，职责单一
- ✅ **错误处理**：健壮的错误处理和日志

### 快速检查清单

在提交代码前检查：

- [ ] 函数简洁（< 50 行）
- [ ] 避免使用 `let`，使用 `const`
- [ ] 避免不必要的 `else`
- [ ] 避免不必要的解构
- [ ] 使用具体类型，避免 `any`
- [ ] 使用 `NamedError` 处理错误
- [ ] 使用 `Log` 记录重要操作
- [ ] 使用 `Bun` API 而非 Node.js API
- [ ] 命名遵循约定（单字、驼峰）
